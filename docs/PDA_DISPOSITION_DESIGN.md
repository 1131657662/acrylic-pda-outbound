# 原机实物处置后续作

本轮按 V2.3 §6.8、§12.11 扩展已有受控续作。动作只有 RETAIN、RELEASE、QUARANTINE；后两者必须引用独立的主管实物核验批准凭据。

1. 完整恢复并停止后，具有 `order:dispose` 权限的主管逐包核对卸货位置、结果、凭据，签发不可改写的实物证据。证据绑定仓库、订单、恢复包、原 captureId、包 ID、周期、动作、批准人及恢复代次。批准本身不释放库存。
2. 续作申请覆盖恢复包的全部有效装载行，减少行引用 `approvedEvidenceId`。审批重新校验证据及占用。原始 captures/scans/events 原样保留；另带累计 dispositions 清单，明确哪些原扫描已经从本车有效集合排除。
3. 激活票据签名绑定累计处置清单和保留集合摘要。PDA 核验原始正文、历史处置前缀、每条减少行，再在一个本地事务内保存独立处置记录、重算包数/重量、切换授权。原始行不改成 VOID，本机防重占用继续保留。
4. 接收替换批次完整正文时，同一数据库事务内比较不可变原事实及完整处置清单、选择新批次、释放 RELEASE、建立 QUARANTINE 永久占用、转移保留包占用并核验新增包。任何冲突整笔回滚。短装仍需原有短装审批；成功后才按有效集合出库。
5. QUARANTINE 使用全局 `bale_commitment` 独立状态及证据外键，不能被新订单、恢复包或库存导入覆盖。解除隔离属于另行核验业务，本轮不提供自动解锁。
6. 再次召回完整继承累计处置；尚未提交的减少包继续占用，已原子处置的历史包不再计入本车保留集合。0 包不能确认出库；全部卸下但尚无替换批次时仍保留占用，不能通过旧零包作废入口绕过交接。

兼容：保留 V1～V12 校验和，新建 V13；旧全量保留正文允许省略 dispositions。Android Room 5→6 只新增记录表，保留历史大正文的分片读取。服务器拒绝未携带完整处置的替换正文，旧 APK 无法误接有减少行的新票据。

验证覆盖释放、隔离、凭据串单/串包/串周期、权限与恢复代次、重复审批及重试、原记录改写、漏处置、事务回滚、跨订单争用、再次召回、全部卸下后零包拒绝、本地签名与迁移。
