# 主管核验卸货、隔离后续作（0.6.0）

此流程用于尚未成功出库的正式订单，保持原人员、原PDA、原计划和固定库存快照。已成功批次仍须办理更正，不能使用本入口。

1. 旧批次须已退审或取消传输。Web申请召回，原PDA核对未处理输入、上传完整恢复包并取得停止证明。
2. Web订单详情的“受控召回与恢复证据”下，逐包选择“原车保留”“卸货释放”或“卸货隔离”。减少行填写实际卸货/隔离位置、核验结果及凭据编号。具备 `order:dispose` 权限的主管确认后固定独立批准凭据。
3. 待批准实物处置完成后，申请“原机受控续作”。检查原有效包数、批准减少数、继续保留数，填写原因。具有 `order:resume` 权限的主管再次核验并批准。批准过的减少行不能勾回保留；误批须停止并对账，本入口不改写证据。
4. 原人员在原PDA的召回页点击续作，核对现场实物与清单。App联网验签并原子更新有效装载数；原扫码序号、输入、旧批次、恢复正文和设备身份保留。历史行显示“已核验卸货（保留防重）”或“已核验隔离”。
5. 继续扫码其他计划产品后结单。新批次保留所有历史事实并引用累计实物处置凭据。服务器完整接收后，才在同一事务中释放指定包、永久隔离指定包、转移保留占用并核验新包。短装仍须主管批准；PDA取得且验签成功的云端出库回执后才可放行。

批准凭据、批准续作、PDA激活、退出登录、设备停用或48小时资格到期均不自动放锁。隔离包不能被其他订单抢占，本轮不提供解除隔离。全部卸下后有效0包不能确认出库；未完成替换交接的占用不能通过零包作废绕过。

网络异常时：Web实物批准保存本标签页内的原ID、正文及恢复代次，刷新后重试原请求；续作申请/批准在当前确认框保留原请求，不能编辑后重发。PDA激活响应丢失或本地事务失败时，原恢复数据及占用保留，重试同一票据，授权期限不延长。再次召回会继承历史处置，尚未交接的包继续占用。

本轮验证：24项后端单元、162项MySQL集成、61项Android主机、5项原生模拟器场景、4项Chrome页面流程通过；契约0.10.0/59路径。数据库新增V13；Android Room5→6只新增处置表，原迁移保持；大提交、恢复及续作票据按128KiB分片读取。模拟器验证不能替代正式App的M71现场验收。

验证汇总保存在 `.local/disposition-verification.json`。PDA保留FLAG_SECURE截图保护，页面核验使用原生控件文字和有效包数，证据为 `.local/disposition-ui-evidence.json`；Web释放及隔离页面截图分别为 `.local/web-disposition-release.png`、`.local/web-disposition-quarantine.png`。
