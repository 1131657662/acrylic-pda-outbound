# PDA 断网补救与独立运行分析报告

日期：2026-09-29。分析输入：主树 `D:/acrylic-pda-outbound`，分支 `codex/development`，源码基线 `8dfe7b39a3657598a8ccec2c7ff2ef2bc0fc5f51`。应用、数据库和接口版本见[看板事实块](ORCHESTRATION_STATUS.md)。

范围：响应“已领单、已扫码但不能上传”和“后台不能建单，希望 PDA 导入 sku.txt 自主扫码、导出”的风险分析。本文是源码核对与方案建议；没有新增功能、修改业务行为、构建 APK、运行设备/真实 HTTP 验证或发布部署。已有代码不等于现场安装包具备同样能力。

## 1. 结论先行

**风险成立，但应精确区分：现有系统具备本地保存和恢复原批次上传的基础，欠缺的是操作员可用的、不依赖服务器的资料取出通道，以及无预备资料时的独立采集模式。**

1. **订单已经领取并完整下载：**扫码事实先存 PDA 本地数据库，结单后保留原批次及固定正文；失败后可以恢复同一批次，不能简单说“断网就丢记录”。但网络模块长期损坏、服务器长时间不可用时，等待补传不能解决“把资料拿到电脑”的问题。
2. **办公室不能创建订单：**已有 R06 临时单能在 PDA 建立车号、产品计划并本地扫码，前提是曾联网取得完整、有效的临时作业签名资料，身份、授权期限及可信时间均满足条件。仅下载了某张正式订单，不等于准备了临时作业资料。
3. **只有一份 sku.txt、服务器完全不可用：**正式 PDA 应用尚未提供选文件、预检、导入并开始独立作业的产品入口。技术上可做，也有解析代码可参考，但不能把原始 txt 当作服务器签发的库存状态或作业资格。
4. **推荐优先补“本机应急导出”，再补“原件经电脑受控补传”，最后补“sku.txt 独立采集”。**第一项直接覆盖最迫切的数据取出问题；第三项属于新增业务模式，需要明确其身份、占用与事后对账边界。
5. **导出记录、云端记账、车辆放行是三个不同动作。**本报告建议允许保全和核对数据，不因此开放离线出库确认、自动扣库存、解除占用或生产放行。

### 2.1 数据保存不等于永久备份

`WorkReception` 将采集输入和原设备/人员/顺序等上下文写入数据库；`WorkSaving` 将成功记录、防重、汇总、审计写入同一事务。数据库使用 WAL，并检查 FULL 同步设置。这提供了本机耐久基础，**不构成设备损坏、卸载/清数据、存储失效或遗失后的异地恢复保证**。〔E01、E13〕

因此应区分：输入是否到达应用、是否保存成功、是否生成导出文件、文件是否已经复制到另一介质。扫描枪响过、页面显示过、文件只在同一台 PDA 内，都不能单独证明完成了设备外备份。

### 2.2 断网后还有三个可用性限制

- **离线资格有期限。**正式和临时作业均校验签发起 48 小时的资格；它不是无限期独立运行许可。到期要保留旧事实，不能改时间或重新包装旧资料续扫。〔E05、E07〕
- **设备重启与应用进程重开不同。**`TrustedTime` 检查设备启动代次及墙钟漂移。设备重启后，新增扫码需联网校验时间。正式冻结的时间来源也是 `session::now`，所以“重启后还没结单、又完全断网”可能连正常冻结入口都受阻；不应把应急导出绑在成功冻结之后。〔E02、E05〕
- **身份恢复依赖网络。**本地会话还在时，不是每次扫码都调用服务器登录；但退出登录会清除本机会话，被服务端拒绝后可能记录 blockedReason，主页会隐藏作业入口。应急导出需要单独设计只读的本地身份核验，不能简单复用“先重新联网登录”。〔E05、E10〕

### 2.3 必须区分“没传上去”和“已处理但回执丢了”

服务器可能已经确认了原批次，只是返回途中断网。现有 `SubmissionRepository` 先查询原 ID 的设计是正确基础。应急包、电脑代传、日后原机补传都必须继续引用同一个原批次/摘要；导出一个新文件不应生成一笔新出库业务。〔E03〕

## 3. 按故障场景选择补救路径

| 场景 | 今天能利用的机制 | 推荐补齐 | 不应作出的承诺 |
| --- | --- | --- | --- |
| 短时断网，设备正常 | 本地保留，恢复原批次上传 | 显示未传包数/重量、最后错误、手动重试与导出 | “连上 Wi-Fi 就一定已上传成功” |
| 网络正常但服务器停止、DNS/入口异常 | 本地保留；可重试错误按队列处理 | 明确区分网络、服务器、身份、业务冲突；可离线导出 | 本机导出即服务器已收单 |
| PDA 网络模块长期损坏，但应用、存储和 USB 正常 | 能保留本机事实；常规上传受阻 | 保存到本地可访问目录，再 USB 复制；支持时用 OTG；电脑受控代传 | 未验真机即保证 MTP/OTG 都可用 |
| 服务器可用、Web 页面/建单端不可用 | 预先准备的 R06 临时作业可能可用 | 明确临时作业准备状态及操作入口 | 正式单下载缓存可直接转作任意临时资料 |
| 服务器不可用，有有效临时签名资料 | 在原身份、期限与可信时间满足时建临时单、扫码 | 本机导出；服务恢复后原身份/原来源对账 | 不经既定确认即可放行 |
| 服务器不可用，没有预备资料，只有 sku.txt | 正式应用无完整入口 | 新增独立采集模式及导入预检 | txt 能证明实时库存、跨机独占或出库授权 |
| 设备重启、授权过期、无法重新登录 | 原本地事实仍需保留，继续作业可能被阻断 | 独立于联网续期的只读救援导出入口 | 为导出而延长或跳过扫码资格 |
| PDA 无法开机、存储损坏或整机遗失 | 只能利用此前已经外置的副本 | 日常受控外置备份与可取回检查 | 事后新增导出功能即可救回已损坏的数据 |

网络故障期间的即时原则：保留原机、原应用和原批次，不卸载、不清数据、不借换号建单规避“结果未知”；已到期或时间不可信时停止新增受控作业。现有应用缺少通用操作员导出入口，技术人员提取也需单独评估安装包、设备权限与证据完整性，本文没有实际提取任何业务资料。

## 4. 建议一：本机应急导出，作为第一优先级

### 4.1 操作流程

建议在本机订单、结单页和专门的“数据保全”入口提供：**选择本单 → 查看有效/撤销/未决数量 → 生成应急包 → 选择保存位置 → 复制到电脑 → 校验复制结果**。原身份不能联网恢复时，通过预先建立的受限本地核验进入只读保全；具体核验权限见第 8 节，不在此次分析中自行开放。

支持正式单、临时单，后续支持独立采集单；覆盖尚未结单、已冻结、上传未知、待处理及已成功状态。**正常应急导出不能强迫结单、消除错误或停止原业务。**存在未决输入时，导出的事实必须标注未决，不把它们凑成有效装车数。现有“停止并保全”是另一项不可随意混用的状态动作。

### 4.2 一次导出，提供两种用途的文件

| 文件 | 用途 | 主要内容 |
| --- | --- | --- |
| `扫码明细.tsv` 或分隔明确的 `.txt` | 人工核对、导入 Excel | 按原扫码顺序列出所有已形成的扫描记录，包含 ACTIVE/VOID 等状态；不能只留下最终合计 |
| `产品汇总.tsv` | 现场核数、核重 | 产品、计划数、有效数、差异、整数克与展示公斤；有效/撤销/未决分别列示 |
| `订单说明.txt` | 交接说明 | 正式/临时/独立来源、显示单号、车号、仓库、资料来源、导出时本地状态与“不等于出库确认”提示 |
| `manifest.json` | 文件核验与追溯 | 导出 ID、用途/格式、各文件摘要和字节数、记录数、设备/订单/批次 ID、截止采集/审计序号、时间可信状态 |
| `captures.ndjson`、`scans.ndjson`、`events.ndjson` | 机器保全原始事实 | 原输入、确认与保存状态、撤销、失败、未决、原始顺序和审计，不依赖 Excel 反推 |
| `submission.json` 与原签名回执/必要签名资料 | 后续恢复原批次 | 已冻结时导出逐字保持的原正文和已有回执；未冻结时明确不存在，不人为伪造冻结批次 |

可打成一个 ZIP 方便 USB 交接；上述格式及文件名是建议，尚未实现。机器原件与人读文件在同一份清单中绑定，电脑改过的表格只作为人工注释，不能替代原件进入补传链。

推荐先用 **UTF-8、带明确表头的 TSV/TXT + JSON 原件**，不必让 PDA 承担 Excel 排版。若后续做 CSV，必须定义引号/逗号/换行转义；TSV 也需定义制表符、换行和控制字符处理。电脑转换工具应随方案一并交付，不能把“理论可转换”当作用户已经能转换。

### 4.3 扫码明细至少保存哪些字段

- 原业务来源类型、原单 UUID/临时 clientOrderId/独立本地 ID、展示单号、车号、仓库。
- 原设备 ID、原操作员 ID、captureId、订单采集序号、设备采集序号、批次 ID（没有则明确未冻结）。
- 原输入与标准化条码、产品代码、型号、品名、原重量文本、整数克、显示公斤。
- 接收/保存时间、时间来源与可信状态、启动代次；显示时间标注北京时间或明确时区，原时刻保持。
- 记录状态、失败/撤销原因、采集方式，以及当时的来源快照/资格/出库周期（不存在的字段不能补造）。

条码、产品代码、UUID 和长序号按文本导入 Excel，不能丢前导零或被转换为科学计数法；不以 `=...` 包装条码。名称、备注等可控文本须防公式解释；对危险首字符和制表符/换行统一处理，JSON 中保留原文。重量以整数克为计算依据，汇总只计有效装车记录，并按已确认处置区分撤销/保留。

### 4.4 导出机制的关键要求

1. **本地快照一致。**应与应用单写者队列协调，在确定的截止序号获取一致视图，再生成文件；不能边读取分页、边允许撤销改变旧行而得到混杂快照。可短暂暂停接收并排空已接收的落盘任务，完成后恢复；未决业务输入保留其状态。仅记录一个最大序号并不足以解决旧行状态改变。
2. **失败不得显示成功。**先写私有临时文件、校验摘要和条数，再发布完整文件；外部目标若不支持原子改名，要回读验证或给出明确的复制校验步骤。取消选择、空间不足、USB 拔出、进程中断都不能标记导出完成。
3. **导出独立于业务成功。**不设置 SYNCED、不解除防重/占用、不删除原记录、不刷新授权期限；保持 `localDeletionAllowed=false`。原批次已冻结时，不改正文、摘要或 ID。
4. **身份与时间降级只能用于保全。**离线资格过期、启动代次变化等应标注在清单；不为生成文件伪造可信导出时间。不能因为“只读”就允许任意拿到设备的人读取全仓数据。
5. **外置副本可核验。**摘要能检查复制损坏，但不能独自证明来源；攻击者可以重写数据和摘要。可由已登记设备私钥签封清单，电脑/服务器用已信任的登记公钥验证；不导出私钥、密码、access/refresh token。必要原离线授权签名作为受控证据保存，不与在线登录凭据混淆。未登记设备只能标注来源信任不足。
6. **兼顾可用性与保密。**本地文件选择器、USB、OTG 是否可用须实机验证；Wi-Fi/蓝牙不能作为网络模块损坏时唯一通道。跨人交接采用受控目录/介质，必要时加密，但解密材料也要可离线取得，避免服务器故障时连备份都打不开。
7. **损坏资料不冒充有效。**正常路径完整性核验失败时停止生成“有效补传包”；如增加维修取证功能，应单独标注损坏/未验证原件，不修补或丢弃失败记录后宣称通过。

## 5. 建议二：电脑代传原件，解决网络模块长期损坏

**仅做 TSV 导出，解决的是核对和数据取出；并没有完成系统内订单闭环。**如果 PDA 永久不能联网，要补一条受控的电脑中转路径：

1. PDA 生成带设备来源证明的应急包，USB/介质交给电脑。
2. 电脑先离线检查结构、文件摘要、条数、有效数和重量，并给出可阅读表格。
3. 服务器可用后，有权人员通过专用入口提交原包，保留“实际采集者”和“导入经办人”两种身份。
4. 服务端验证原登记设备/人员/仓库、签名、资格、批次与摘要、恢复代次、原始顺序、占用和冲突；先查询是否已有同一批次结果。
5. 同包重交及原 PDA 后续直接上传应汇合到同一结果；有同 ID 异内容时拒绝，不能重复记账。
6. 签名接收/业务回执可再通过文件返回 PDA 核验。PDA 未核验业务成功回执时不能自行显示云端已确认，也不能凭电脑“文件已收下”释放占用。

这是一条**建议新增**的协议和入口，不是把现有 PDA Bearer 复制给电脑即可调用。现有上传绑定原人原机；换成 Web 管理员直接重放请求不等于完成原身份验证。服务器处于恢复对账模式时，仍须遵守 R09 准入与代次边界。

未冻结快照和裸 sku 独立采集包不能直接假装已有正式 submission；它们应进入证据接收/人工核对流程，再按明确政策产生业务决定。临时单与正式单关联继续遵守已确认的人工确认规则，不自动拼单。〔E03、E08、E14〕

## 6. 建议三：支持 sku.txt 独立导入与采集

### 6.1 可行，但需要单独标明来源

建议在同一个正式 PDA 应用内增加“独立采集（待对账）”入口，保留已有正式单和临时单流程。它可以做到 **选取 sku.txt → 预检 → 固定本地资料批次 → 填车号/原因/产品计划 → 扫码校验并保存 → 导出 → 事后对账**。本文仅建议该模式，不表示允许其自动成为出库完成状态。

同一个应用便于维护统一的本机防重与事实记录。另装一套 Demo/独立 App 看似快，但两套私有数据库不能自然共享防重、占用及顺序，切换时容易二次采集；不建议把旧 Demo 直接投入正式作业。

### 6.2 sku.txt 有什么，又缺什么

服务端正式解析器按 **GB18030、每行 57 字节**处理：型号 20 字节、品名 14 字节、条码字段 13 字节、重量 10 字节；条码实际值须是 11 位大写字母/数字，前三位给出发货代码；重量最多三位小数，精确换算整数克。〔E15〕

这些足以支持本机按条码查型号、品名、重量，并核对本单计划，**但不包含该包是否已被其他设备装车、真实可用库存/出库周期、订单授权、设备权限和服务器恢复代次等可信事实**。不能因文件中存在某条码，就认定它可正式出库。车号、产品计划、操作原因和本地单身份也需要另外输入/生成。

Demo 解析器用 GBK，且导入器校验固定打包样本摘要和行数；不能直接搬来当任意 txt 导入器。应以正式服务端解析语义为准，在 PDA 对同一组文件产生相同结果。〔E12、E15〕

### 6.3 导入必须满足的条件

- 原文件按原字节保存并计算摘要；按字节切列，不能先转成字符串再按字符位置截取中文。沿用正式解析器对编码、空行、换行、BOM、文件大小和行数的处理规则。
- 展示有效包数、产品数、重量、重复行和错误行；完全重复需明确确认去重，同码不同内容、同产品代码冲突、错误编码/行长/重量要阻断该资料激活，禁止静默丢行。
- 预检及暂存与正式激活分开；全部成功再原子启用。失败、取消或断电不能覆盖旧完整资料。
- 每个本地作业绑定固定资料摘要和本地资料批次。新导入只供之后的新单选用，不能改变已经扫过的条码含义和重量，也不能借新文件清除旧防重。
- 自建 UUID、本地顺序和导入审计；没有服务端 baleId/授权/出库周期时用明确的本地标识或未知字段，不能伪造服务器字段。
- 统一检查本机正式/临时/独立作业中的有效防重与未决输入；遇到原正式单尚未确认的同包，应提示原单核对，不能另建“应急单”重扫绕过。

### 6.4 独立采集的权限和时间

“服务器完全没参与过的设备，拿到一个 txt 就能开工”和“已登记设备故障期间降级采集”是两种不同授权范围。推荐第一期仅考虑**已登记、预置了本地应急身份核验机制的设备**；从未登记的新设备完全离线启动属于另一个业务选择，不能靠姓名文本伪装为已认证人员。

独立采集可保留本地时间、启动代次和单调时钟信息，但没有在线可信锚点时应明确“时间未被服务器证实”。已有正式/临时资格的 48 小时约束保持；不能把它延长为无限期。若要允许独立采集跨重启或长期离线，应另定义应急身份的有效范围、续用和事后审核规则。只读导出已有事实则应单独保证可用。

### 6.5 多台 PDA 的根本限制

两台互不联网、持有相同 txt 的 PDA 无法实时知道彼此扫了什么；统一本机防重不能提供跨设备独占。建议应急阶段按实物作业区/车辆/条码范围明确分工，并在恢复后统一对账。若要求离线期间仍硬性保证跨设备唯一占用，需要事先分配互斥库存范围或另有可用的共享协调节点，是额外设计范围。

同理，永久没有服务器时可以长期作为独立采集与报表工具，但它承担的只是明确限定的本机事实管理，无法承诺原系统所有跨机、审批、库存记账与中央审计能力。

## 7. 三种推进方式与推荐顺序

| 方式 | 解决范围 | 主要代价 | 建议 |
| --- | --- | --- | --- |
| A. 现有体系加应急导出及受控中转 | 已领取/已有临时资料下的断网、坏网卡、证据取出 | 快照、文件完整性、本地核验、导入幂等与回执返还 | **先做**；最直接，保留已有事实链 |
| B. 增强预备临时资料 | 后台临时不能建单、短期服务器中断 | 作业前准备、过期/重启提醒；必要时研究带签名资料经文件分发 | 与 A 配合；仍受原资格及可信时间限制 |
| C. 裸 sku 独立采集 | 没有有效预备包时仍能采集并产出核对资料 | 独立来源/身份、解析一致性、防重、跨机风险与事后对账 | 在 A 基础上做；不要混入原 TEMP 授权或伪装正式出库 |

建议拆成可独立验收的交付：

1. **应急导出及电脑核验/转换。**正式/临时单先覆盖，可对未冻结事实导出；支持 USB 取出与现场 Excel 核对。
2. **中转闭环。**先确认电脑接收原件与受控恢复的权限/协议，再实现同批次幂等接收与签名回执返还；不要交付只能重复导出、不能消除结果未知的假闭环。
3. **独立导入采集。**沿用同一导出格式，新增独立来源和本地身份边界；先做到采集/核对，不自动改变正式库存。
4. **备份与演练。**在现场验收后明确外置副本频率和保管人；末班导出只能保护上次导出之前的数据，不能声称零丢失。

无需为“生成 TXT/JSON”先完成全部服务器恢复工程；但中转正式记账和恢复代次冲突处理必须接入既有边界。以上是范围/依赖排序，不虚构尚未评估的工期。

## 9. 后续开发的验收标准

| 验收项 | 至少满足的可观察结果 |
| --- | --- |
| 完全断网导出 | 关闭网络且停止隔离测试服务，原应用仍能生成并取出本单文件；无偷偷依赖 HTTP 的步骤 |
| 未冻结/异常单导出 | 含零有效包、待确认、失败、撤销及部分保存；数目分类正确，不强迫结单，不修改业务状态 |
| 重启/到期/退出/身份变更 | 原数据保持；受控保全入口可按授权工作，导出不授新扫码资格、不伪造可信时间 |
| 并发与一致性 | 扫码/撤销/冻结/上传回执变化与导出交错时，包内来自同一确定快照；不能只测静态表 |
| 文件失败与恢复 | 空间不足、取消、目标只读、USB 拔出、进程终止、半文件都不显示完成；原数据不受损 |
| 真机交付通道 | 目标 PDA 的本地保存、USB/MTP、适用时 OTG、电脑读取逐项实测；主机测试不代替 |
| 人读与机器原件一致 | Excel 转换后条码/代码前导零不丢、长 ID 不变、重量可精确对账；文本不会执行公式 |
| 导入器一致性 | 正式服务端和 PDA 对同一组正常/坏编码/错行长/重量/重复/冲突文件给出相同结果 |
| 裸 sku 记录边界 | 明确独立来源和未证实时间/库存；导入坏文件不改旧快照，切文件不清旧防重 |
| 本机与跨机重复 | 正式、临时、独立来源在本机互斥；两台离线冲突有可复现的识别及人工处理路径 |
| 原批次中转幂等 | 同包重复导入、电脑与原 PDA 并发补传、服务端提交成功但回执丢失均不产生第二次记账 |
| 来源及权限 | 改字节/改清单/换公钥/换人换仓/旧恢复代次不能直接通过；不导出登录秘密和私钥 |
| 回执返还与恢复 | 签名回执经文件回到原机后严格验签；中转已接收不冒充云端已确认；恢复模式不误放行 |
| 不可恢复边界 | 真机断电/存储故障与原身份现场演练单列，不以合成身份、重开数据库或历史测试代替 |
