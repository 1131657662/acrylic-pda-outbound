# 正式订单结单、上传与记账

2026-09-17，承接用户“继续”授权，落实V2.3 §6.3、6.8、9.3～9.6及Q04/Q05。本次接正式订单首轮提交；原有续作、临时单、换机、更正、独立审计同步与灾后重建仍按完整方案后续实现，不开放绕过入口。

1. PDA停止接收，确认队列已清空且无未处理失败，核对实际明细/汇总。0包不能结单；任何产品少于计划必须填写短装原因。一次Room事务保存完整输入、有效/撤销明细、本单审计、原始来源/周期、固定正文、摘要和预期汇总，转FROZEN。到期禁止新增保存，但允许冻结及上传既有记录。正文冻结后不可修改或生成第二批次。
2. 服务端先建立FORMAL来源scope、订单唯一提交槽和最小submission控制头；正文单独耐久存储和关联。原设备/原人员通过当前在线身份提交，不以过期离线令牌充当在线认证。离线期限仅验证保存发生时刻；凭据撤销、来源版本/恢复代次变化仍阻断自动入账。
3. 小正文整单接收；较大正文使用固定摘要、块数/长度的上传清单和可重复分块，全部校验后走同一个最终处理入口。传输限制不作为业务包数限制。取消可先于正文到达，固定ABORTED并签发证明；取消、首次接收、审批和最终入账锁同一控制行，取消不释放订单或包，也不解冻扫码。
4. 按既有服务器/仓库/设备锁前缀，再按scope→订单槽→submission→包ID锁序处理。逐条核对原授权、固定快照、来源、扫码/设备序号、输入终态与审计、原出库周期、产品计划和服务器独立重算重量。先完整校验再建立出库事实；全机/全局条码占用不受自动扣账开关影响。
5. 短装和库存冲突持久为REVIEW_REQUIRED，保留正文、冲突和可安全占用的本单包；不入账、不放行。主管审批须绑定原摘要与当前批次；只能批准已无冲突的短装，审批不能覆盖周期/库存/身份冲突。退回/取消不自动续扫，后续受控续作流程另接。
6. 成功在一个事务写出库事实、有效明细、可选库存扣减流水、结果版本1、订单COMPLETED、提交SUCCEEDED、审计及outbox。成功回执含原摘要、逐产品/整单包数和整数克、来源/轮次/代次，使用现有RSA服务密钥签名并永久保留；原键重试或查询返回原回执。PDA验证签名及完整预期后才显示云端确认。
7. PDA用户主动排队后使用唯一WorkManager任务，仅WiFi自动重试；手动上传与Worker共用互斥。响应丢失进入RESULT_UNKNOWN，查原ID或重传原正文；401只刷新一次，权限/业务阻断保留待处理，不循环换键。不实现自动结单或自动清理在途记录。

本轮完整冻结本单输入及审计用于逐条追溯，但不据此推进全设备连续审计确认或触发90天清理。服务端沿用当前已实现的十进制恢复代次协议；外部灾后恢复控制仍须按F06独立完成。本地旧Room数据采用新增表迁移，不重置来源计数器。
