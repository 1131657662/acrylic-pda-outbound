# R05 恢复对账页面与重新登录验证

日期：2026-09-19。续接[跨进程归档恢复](R05_ARCHIVE_RECOVERY_E2E_GUIDE.md)保留的原数据，在现有Pixel_6隔离应用中完成实际页面和重新登录验证，并修正两处恢复状态提示。R05整体仍未完成。

## 发现与修正

原应用的Room恢复屏障已经生效，但有两处页面没有完整表达当前状态：

| 页面 | 修正前实际显示 | 修正后行为 |
| --- | --- | --- |
| 冻结作业的扫码页 | 冻结提示覆盖“服务器正在恢复对账” | 保留阻断原因，再显示冻结/召回说明；原明细可读，扫码与撤销仍受保护 |
| 已成功提交的历史回执页 | “云端已确认出库 · 回执已验签” | 待对账期间显示“历史回执已验签 · 当前恢复待对账”，明确历史回执不代表本次恢复完成 |
| 尚未结单的结单页 | 按是否已有批次控制冻结按钮 | 另读取持久恢复屏障，待对账时禁用原因输入和新冻结确认；正常状态仍可核对冻结 |

改动仅在`WorkRenderer`和`SubmissionActivity`。历史提交状态、回执、归档签名、恢复屏障及业务校验保持；没有增加解除屏障入口，没有改写旧成功提交。页面读取恢复状态在IO线程执行，首次读取前保持新冻结禁用，底层冻结事务继续重新核对业务保护。
