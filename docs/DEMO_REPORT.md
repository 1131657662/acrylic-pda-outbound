## 4. 模拟器验证

环境为本机已有 Android API 37 x86_64 模拟镜像，以只读临时运行方式启动，2GB RAM，窗口设为 480×800、density 240。没有更改原 AVD 保存状态。与 M71 的 ARM CPU、Android 9、厂家扫码服务和闪存不同。

- APK 安装启动通过，UI 主屏条码/产品/重量/汇总/底部按钮在 480×800 下可见。
- 最终包补充验证了 Activity 的 ADB 按键路径：广播后不按 Enter 保持 0 包；未确认状态经 force-stop/重启仍保持候选和 0 包；正常 Enter 只保存一包；重复包被拒绝；手输 `571B0002093` 在 F1 前不能保存，F1 校验后 Enter 保存。最终两包为 `305+303=608kg`，扫码明细序号为 1、3，保留中间重复尝试 2。ADB 注入与进程停止均不是 M71 物理操作/断电测试。

## 6. 技术边界及后续门槛

1. 正式上传幂等、abort/finalize 并发、退审续扫、审批、库存扣账/反向更正、灾后服务器回执重建、Web/PDF/正式 Excel 尚未开发，仍按 V2.3 完整交付。
2. 双通道自动 Enter 是真机必须先排查的接入风险；若固件无法区分自动和人工键事件，不能绕过逐包人工确认规则。
3. SQLite FULL 和成功后才反馈已经实现，设备存储层实际耐久仍须突失电验证。冻结目录元数据的断电行为同样需实测。
   FULL 通过 Android 9 的 OpenParams 写入连接池配置，包含后续新建连接；启动时和导出时直接检查实际写连接。固定 AndroidX SQLite 2.5.0 的 Java 适配桥在依赖升级时须重点复验。
4. 诊断队列有界，业务审计在事务内持久；发生诊断丢弃时相应时延/无漏收证据不足，不能仅凭累计数判通过。
5. 48 小时授权是本地签名测试夹具；设备重启/授权变更不自动升级原确认上下文。Keystore、离线授权与正式服务器恢复协议需后续真机和云端联合验证。
