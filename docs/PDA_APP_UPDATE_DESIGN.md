# PDA 应用检查更新与安全升级

日期：2026-09-18；首次安装入口补充于2026-09-19。状态：应用内更新已有源码、staging分发及M71首轮验证，实际范围见[更新交付记录](PDA_APP_UPDATE_GUIDE.md)；第9节“下载 PDA 应用”已完成测试Web部署及隔离模拟器浏览器/系统安装验证，code16首次安装已启用，真机与异地待验，见[下载入口记录](PDA_DOWNLOAD_GUIDE.md)。本文是实现基准，不表示全部范围或生产验收完成。

关联：[后续开发路线](DEVELOPMENT_ROADMAP.md)、[开发进度](DEVELOPMENT_PROGRESS.md)、[PDA 页面规范](pda-page-template.md)、[Android 说明](../android/README.md)和[Git 管理说明](GIT_WORKFLOW.md)。目标是让仓库装车操作员在 PDA 内检查并安装已发布的新版本，不再为每次升级回办公室使用电脑。

## 1. 目标和范围

设置页提供“检查更新”。操作员点击后，App 通过当前环境的 HTTPS 更新地址取得版本信息；有可用版本时展示版本号、大小、发布日期和简短说明，操作员确认后下载并调用 Android 系统安装器。安装完成后重新打开 App，保留设备身份、Keystore 私钥、Room 数据、本机订单、待上传资料、原请求和审计。

第一版只做手动检查、可靠下载、完整 APK 校验、系统安装和覆盖升级后的数据核对。暂不做静默安装、后台强制升级、增量补丁、降级安装、远程清除或绕过 Android 系统确认。检查更新失败不能阻断现有作业，也不能显示“已是最新版”。

接续顺序：收到本专项启动指令后，先将正在执行的R05子项收敛到可恢复的断点、记录剩余事项，再接本专项；不要求先完成整个R05，也不删除条码可用状态、审计补传和后台任务等原待办。本会话只登记方案，由用户指定的开发会话实施。

## 2. 渠道、包名和签名边界

更新服务必须按应用渠道隔离。当前 debug 和 staging 是不同应用，不能互相覆盖：

| 渠道 | 应用包名 | 更新要求 |
| --- | --- | --- |
| debug/本机联调 | `com.acrylic.outbound.pda.debug` | 只接受同包名、同签名的开发包；不连接生产更新源 |
| staging/独立测试 | `com.acrylic.outbound.pda.staging` | 只接受同包名、同签名的测试包；由独立测试后台发布 |
| production/正式环境 | 当前release配置为 `com.acrylic.outbound.pda`，发布前再次核验 | 只接受正式签名和正式更新源；在正式签名与地址核定前不启用 |

服务端不得把“最新构建产物”直接暴露给所有 PDA。每个渠道发布一份带签名的版本清单，清单至少包括发布ID、`packageName`、渠道、`versionCode`、`versionName`、最低Android API、可直接升级的来源版本范围、APK下载地址、文件字节数、SHA-256、签名证书摘要、发布时间、更新说明及服务端兼容范围。第一版不增加强制升级策略。客户端拒绝包名、渠道、签名证书摘要、版本号、哈希或兼容范围不匹配的安装包；兼容性未知时显示“需管理员核对”，不能当作无更新。

覆盖升级要求 APK 使用与设备当前应用相同的 Android 签名；签名更换、包名更换和跨渠道升级必须作为新应用安装或另行迁移，不在本功能中偷偷处理。版本号只能单调增加，禁止普通操作员在设置页降级。

staging当前沿用开发签名，实施前须核对已安装包的实际签名并稳定保存对应签名材料；不能在另一台电脑重新生成debug密钥后直接替换更新包。测试签名不作为正式发布签名，任何签名私钥都不得写入仓库、APK或下载接口。比较版本用`versionCode`，不按版本名称字符串排序。

## 3. 操作流程

1. 操作员进入“设置 → 应用更新”，看到当前版本、清晰的测试/正式环境名称和上次检查时间；debug/staging等内部标识放在版本详情。登记/登录页提供可达的更新入口，以便登录故障时仍可取得修复版本。
2. 点击“检查更新”。请求只读、使用 HTTPS、带当前渠道和版本；登录未完成时仍可检查公开的版本清单，但不泄露设备私钥或业务数据。
3. 成功取得可信清单且没有更高兼容版本时显示“当前已是最新版本”，同时显示本次检查时间。尚无本渠道发布、旧后台不支持更新、网络、证书、清单签名或服务端错误分别显示原因并提供合适动作；不能一律显示最新版。更新检查不改变当前业务权限或既有恢复限制。
4. 有更新时显示新旧版本、大小、更新说明、最低支持版本和兼容提示。操作员点“下载更新”后才开始下载；不自动下载大文件。
5. 下载页显示真实进度、已下载大小、总大小和取消/重试动作。网络中断、进程重启或页面离开后保留可恢复下载状态；仅在发布ID、摘要及Range/ETag等资源标识仍匹配时续传，否则安全重新下载。临时网络中断不立即删除有效分片；确认文件错误或摘要不符时删除无效文件并提示重新下载。只清理本功能拥有的临时文件。
6. 下载完成后先校验清单签名、APK SHA-256、包名、版本和签名证书，再显示“准备安装”。操作员点“安装更新”后通过 `FileProvider` 的受保护 `content://` URI 调用 Android 系统安装器。
7. Android 9 的“允许安装未知应用”设置由系统控制。未授权时引导操作员进入本 App 的系统设置，返回后继续安装；不能通过隐藏窗口或无障碍服务绕过系统确认。
8. 调起安装器只表示“等待系统安装”，不能提前报告成功。操作员安装后重新打开App，以实际已安装版本和数据迁移结果核对“更新完成”，不假定系统会自动重开App。安装取消或失败时保留旧版本和可用下载记录，可重试；不清除应用数据、不要求重新配对。

## 4. 作业保护

检查更新可以在作业期间执行，但安装动作只能在安全点进行。以下任一条件成立时，显示原因并禁用安装：

- 当前有未确认的手输、待保存意图或本地存储错误；
- 正在上传，或写请求结果未知且尚无经验证的升级恢复路径；
- 当前订单尚未安全退出，或正在冻结、提交、恢复、召回、处置；
- 设备配对、登录、资料激活或数据库迁移正在进行；
- 存储空间不足以保存完整 APK 和升级临时文件。

仅有已持久化的待上传、待审批或暂停订单，不应一律要求清空任务才能升级。目标版本已验证这些数据的迁移和原请求恢复，且作业已停在安全点时，可以保留资料升级；恢复对账阻断必须完整保留，升级不自动解除。若对应版本缺少此类数据保留证据，明确提示暂不可安装及处理路径，不删除资料来制造可升级条件。

提示必须告诉操作员下一步，例如“请先核对本次上传结果”或“请先退出扫码页面再安装”。安装前再次读取状态，并与扫码接收、业务写入及上传/同步任务建立互斥，避免检查后又开始保存。返回或取消安装后正确恢复正常任务调度，业务占用和原请求保持；不是退出人员账号或释放订单。

## 5. 客户端实现约束

- 更新清单和 APK 只允许 HTTPS；证书错误、重定向到非 HTTPS、跨环境地址和不可信主机直接拒绝。
- 清单使用服务端签名或等效的公钥校验，客户端内置验证公钥；TLS 只保护传输，不能替代清单签名和 APK 签名校验。
- 清单提供的证书摘要还须与当前已安装应用的可信签名比较，不能仅相信下载文件中的证书字段；签名清单覆盖APK身份、摘要、渠道、版本及兼容字段。
- APK 下载到 App 私有目录，使用临时文件和原子改名；不把未校验文件放入公共下载目录，也不在校验前交给安装器。
- 使用系统安装器和 `FileProvider`，不申请不必要的存储权限；记录安装意图、结果和版本，不记录密码、Cookie、私钥或完整业务正文。
- 下载、安装和重启均为可恢复状态机。结果未知时保留原状态，重新打开设置页先查询本地下载/安装状态，不重复创建互相覆盖的下载任务。
- 数据库迁移必须向前兼容当前在途订单和未上传记录；升级失败时不把“版本号已改变”写成成功。安装包构建、APK生成、系统安装、数据迁移通过和真机验收分别记录。

## 6. 发布端配套

清单和APK读取可在登录前提供，不含业务数据或凭据；写入、启用、停发必须由管理员授权并记录审计，普通操作员只读，下载按渠道校验和限流。第一版可用受控发布脚本/配置和现有HTTPS静态服务，不要求新建一套Web发布平台。若采用私有下载，应由本项目后台提供受控链接，不把GitHub私有仓库令牌或发布凭据打包到PDA。

先完整上传并验证不可变的APK，再原子切换带签名清单；不覆盖同一发布ID对应的文件。下载完成、安装前重新核对候选版本仍可分发且兼容，撤回时停止提供该包；未完成重新核对时保留下载并提示联网重试。自有更新服务不能保证撤回已交给系统安装器或已手动复制的APK。部署前核对当前公网后台实际版本，不能仅因本机最新源码可运行就分发依赖新接口的APK。

每个版本的交付记录至少包含：Git提交、应用包名、渠道、versionCode/versionName、签名证书摘要、APK SHA-256、服务端兼容版本、数据库/Room迁移说明、已知问题和回退办法。发现严重问题时停止分发新版本；不能通过降低 versionCode 或替换同名文件伪造回滚。需要回退时发布修复版本，或按已验证的系统恢复流程处理。

## 7. 验收矩阵

### 客户端与协议

- 当前版本、无更新、更新可用、清单签名错误、包名/渠道不符、版本过低、摘要错误、文件截断、非 HTTPS 和服务器错误；
- 下载进度、取消、断网重试、进程重启、低空间、旧文件清理和重复点击；
- Android 系统安装确认、未知来源授权、安装取消、签名不一致、版本已安装和安装器错误；
- 更新后设备绑定、Keystore、登录会话策略、Room 数据、待上传、原请求、审计及恢复阻断逐项核对；
- 安装过程中不打断扫码，不丢失自动保存结果，不解除订单或包占用。

### 版本与环境

- staging 只从同签名 staging 包覆盖升级，debug 不能升级 staging；
- 至少验证当前测试包到下一测试包的保留数据升级，以及 Room 历史版本逐级迁移；
- 在模拟器、USB M71 和异地 PDA 分别记录“代码构建、APK生成、系统安装、数据保留、实际作业”的结果；
- 检查480×800、低高度、200%字体、横竖屏限制及系统安装页面返回后的状态恢复。

## 8. 首次接入与交付边界

现有旧版没有检查更新能力，需先通过原有HTTPS下载链接或USB覆盖安装一次“带更新能力的首版”，保留原包名、签名和数据。之后发布同渠道、更高versionCode且同签名的第二个候选包，通过App内检查、下载、系统安装和重开核验，才算验证更新闭环。不能仅证明首次电脑安装成功就宣称App内更新通过。

首轮优先打通现有staging公网测试渠道；debug用于隔离验证，正式渠道在正式签名及地址核定前不分发。版本号按实际构建确定，不在本方案预先承诺。交付操作说明须列出设备当前版本、升级路径、支持的旧Room版本、首版下载入口和下一版本发布步骤。

本功能完成后，可以让操作员在网络可达时自主安装已发布的兼容版本；它不解决设备没有网络、服务器不可达、签名密钥丢失或 Android 系统禁止安装的问题。第一版不承诺静默安装，也不把测试渠道变成生产发布渠道。真实两台 PDA、异地 HTTPS、长时作业和生产发布仍按[R02、R09、R10](DEVELOPMENT_ROADMAP.md)分别验收。

## 9. 下载 PDA 应用与首次安装入口（源码与本机验证完成）

用户于2026-09-19确认补齐新设备取得安装包的入口，作为R05应用更新配套。新PDA无需USB、微信、GitHub账号或与电脑处于同一局域网；能够访问当前环境的HTTPS服务即可下载。本节源码及本机验证已完成，实际部署和设备验收状态见[交付与启用说明](PDA_DOWNLOAD_GUIDE.md)。

### 9.1 入口与固定地址

- Web登录页提供次要入口“下载 PDA 应用”，无需先登录；PDA设备管理页工具栏提供同名入口，不替代“登记设备”的主要动作，也不新增侧栏一级菜单。
- 两处进入同一独立下载页，固定站内短路径已实现为 `/pda-download`；本机已验证，公网可用性仍须部署后核对。设备管理入口以独立标签页保留原列表上下文。
- PC页面展示固定下载页的二维码、完整短地址及复制地址按钮。二维码使用正式二维码库生成，内容只包含当前环境的HTTPS下载页地址，不绑定某个版本的APK，也不携带账号、令牌、设备身份或配对码。
- 新PDA可在浏览器手动输入短地址；设备有可打开网址的扫码工具时也可扫码进入。不假设厂家物理扫描键能直接打开网址，不把扫码作为唯一安装方式。
- 地址保持稳定，APK仍按发布ID保存为不可变文件。发布下一版只更新可信发布信息，已打印的下载页二维码继续有效。

### 9.2 页面内容与发布一致性

- 页面标题“下载 PDA 应用”，突出产品名和当前测试/正式环境；展示当前可安装版本、文件大小、发布时间、最低Android版本及简短更新说明，主动作是“下载安装包”。版本和说明较长时换行，PDA窄屏不横向溢出。
- 版本、包名、渠道、大小、下载地址、摘要及兼容信息复用App内更新的同一可信发布清单，不另写一份人工维护的“最新版本”。版本按versionCode判断，展示按versionName；不把最新构建或未发布产物推荐给用户。
- 实施时复用发布端的签名/渠道/APK核验结果或提供只读的已验证元数据；不能仅解码签名清单就宣称已经验签。保持HTTPS及当前环境的可信下载路径，不接受外部任意下载地址。
- 默认只展示当前后台环境的已启用渠道。staging明确写“测试版”，不提供debug安装入口；production在正式签名、地址和兼容性核定前不开放，不提供随意跨环境切换。
- 未登录只可读取下载信息和公开安装包，设备管理仍按原权限访问；下载不会自动登记设备或获得业务权限。不暴露GitHub私有仓库凭据、发布密钥或业务数据，不新增完整发布管理后台。
- 加载、网络失败、尚无发布、暂停分发、版本不兼容分别显示真实状态及适用的重试动作；失败不显示“已是最新版”，无可用发布不保留可点击的旧包推荐。
- 页面重新打开及开始下载前重新核对当前发布。发现发布已变更时刷新版本/说明与下载目标，不能显示A版却下载B版；缓存策略需保证停发和新发布及时可见。已下载或已交给系统安装器的文件仍遵守第6节的撤回限制。

### 9.3 安装与后续使用

下载页提供简短的安装步骤：“下载APK → 在Android系统安装器确认 → 打开App进行短码登记 → 登录”。浏览器需要安装来源授权时只引导进入系统设置，不绕过确认，也不在下载完成时显示“安装成功”。

全新设备可直接安装当前渠道允许首次安装且满足Android/后台兼容条件的版本，不要求先装旧版再逐级升级。清单中的旧版本覆盖升级范围不能误套为全新设备的最低已装版本；首次安装可用性仍须独立验证。

已安装用户优先在App内“检查应用更新”；旧版没有此入口时按已验证的覆盖接入路径处理。网页无法可靠判断设备已装包名、签名、版本和作业状态，不宣称任意旧版都可直接覆盖，不引导卸载、清空数据或重新登记。需要中间接入版时明确标注用途及适用范围。

页面按[Web页面规范](web-page-template.md)使用简洁单列布局，PC显示二维码，PDA优先展示下载动作；版本信息、操作和安装说明用平铺分区，不做宣传首页。设备管理页打开下载页后返回保留原筛选、页码和位置；浏览器直接访问或刷新下载页不能被登录守卫拦截。
