# 项目背景与目标总结（完整版）

## 一、老系统情景总结

### 1. 业务对象

- 货物：腈纶有光短纤包。
- 一包一唯一条码，例如 `719C0000056`。
- 单包重量不固定，约 300kg，支持小数，如 302.5kg、303kg、303.5kg。
- 单车最大可装 116 包，单次出库最少 1 包。

### 2. 老设备与数据文件

使用**单机离线扫码枪**：

- 无网络。
- 无 PC 网页后台。
- 扫码枪内部预置两个文本文件：
  - `sku.txt`：库存主数据。
  - `out.txt`：出库采集结果。

### 3. 实际操作流程

1. **库存维护**
   - 上游客户维护完整全量 `sku.txt`。
   - 电脑 USB 连接扫码枪，直接覆盖原有 `sku.txt`。
   - 在扫码枪设备上执行导入，加载库存数据。
2. **出库扫码前**
   - 预先在扫码枪上录入“代码”，即条码前 3 位。
   - 扫码时只校验条码前 3 位是否与预设代码一致。
   - 不一致则无法录入该条码。
3. **装车扫码**
   - 同一车包含多种前缀条码时，必须分多批次扫码。
   - 没有订单概念。
   - 没有车号、柜号、操作员、作业时间记录。
   - 无法限制本车计划包数，扫多扫少全靠人工记录。
4. **扫码完成**
   - 一车作业结束后，所有扫码记录存在 `out.txt`。
   - USB 连接电脑，人工拷贝 `out.txt`。
   - 人工导入 Excel，分列、美化、汇总。
   - 手工计算包数、总重量，制作出库台账。

### 4. 老方案主要痛点

- 完全依赖人工拷贝 txt 文件，容易丢失、版本错乱。
- 出库数据要人工 Excel 整理，包数和总重量容易算错。
- 没有订单管理，无法预设计划包数，不能提前拦截超装。
- 缺少车号、柜号、操作员、作业时间，出现问题难追溯。
- 扫码无实时汇总，现场无法查看已扫包数、累计重量。
- 无网页后台，办公室不能实时查看装车情况。
- 缺少音效交互，连续高速扫码体验差、效率低。

## 二、要开发的完整系统总结

### 1. 总体架构

新系统由三部分组成：

1. **Web 后台管理系统**
2. **Android PDA 离线扫码端**
3. **云端 API 与数据库**

核心流程：

> Web 后台创建订单和导入库存 → PDA 联网同步订单与库存 → 仓库现场离线扫码 → 回到有网区域按订单上传 → Web 后台查看、汇总、导出。

### 2. Web 后台系统

#### 权限

- 管理员：库存维护、订单新增、查看、导出报表。
- 仓库操作员：仅查看订单，不可新增/修改订单。

#### 库存主数据管理

- 上传原始 `sku.txt` 批量导入。
- 自动解析：规格型号、品名、条码、单包重量。
- 自动维护映射：发货代码（条码前 3 位）→ 型号、品名。
- 记录导入日志：导入时间、操作人、成功数、失败数、错误文件。
- 支持库存查询、条码检索。
- 支持上传后自动扣减库存（可配置开启）。

#### 订单管理

一个订单对应一车货，一个订单下可包含多个产品代码。

订单主信息：

- 订单编号：系统自动生成。
- 车号：必填。
- 柜号：可空。
- 订单总计划包数：所有产品计划包数之和，上限 116 包。
- 订单状态：新建 / 已下发PDA / 已上传完成。
- 创建人、创建时间。

订单产品明细：

- 发货代码：条码前 3 位。
- 型号规格：根据发货代码自动带出。
- 品名：根据发货代码自动带出。
- 计划包数：每个产品单独设置。

业务规则：

- 发货代码不存在，不能创建订单。
- 同一订单下不允许重复添加相同发货代码。
- 订单总计划包数不得超过 116 包。
- 订单创建成功后自动生成 PDF 装车单。
- 支持订单作废、修改。
- 支持多 PDA 并发作业时订单锁定，防止多人同时扫同一订单。
- 支持完整操作审计日志。
- 支持异常备注：扫码时可标记破损、标签模糊等异常信息。

#### 订单列表、详情、汇总

- 订单列表：订单号、车号、柜号、产品代码、计划包数、实际包数、状态、创建人、创建时间。
- 订单详情：基础信息、分产品汇总、分产品出库明细、实际总包数、总重量。
- 订单汇总视图：按订单汇总总计划、总已扫、总重量、分产品明细。
- 支持导出 PDF 装车单、Excel 明细台账。
- 支持订单作废、修改后重新下发 PDA。

### 3. Android PDA 扫码系统

#### 目标设备

摩比信通 M71：

- Android 9。
- 2GB RAM + 16GB Flash。
- 480×800 竖屏，约 320×533dp。
- 顶部扫码头，Mobydata E3250/E3200。
- 实体扫描键、实体回车键、左右 K1/K2 自定义键。
- 支持广播扫码。

#### 核心功能

1. **基础同步**
   - 有 WiFi 时拉取云端订单和库存到本地 SQLite。
   - 断网后依然可查看订单、扫码、校验、暂存明细。
2. **离线扫码**
   - 选中订单进入扫码页。
   - 页面显示：订单号、车号、柜号、已扫/计划、累计重量。
   - 条码输入框：扫码自动填入，也支持人工手动输入。
   - 扫描键扫码 → 广播返回条码 → 自动校验 → 回车保存。
   - 手动输入条码 → 按 F1 校验 → 回车保存。
   - F2 可作为辅助键，如清空输入框、打开汇总页。
3. **六层本地校验**
   - 条码格式：去空格、转大写、长度/字符集合法。
   - 产品匹配：当前订单下是否存在该发货代码的产品明细。
   - 库存校验：条码存在于 PDA 本地库存。
   - 重复校验：本订单内该条码未扫过。
   - 产品包数上限：对应产品未超计划包数。
   - 订单总上限：本订单已扫包数 < 订单总计划包数。
4. **实时汇总**
   - 扫码后实时刷新已扫包数、累计重量、明细列表。
   - 订单汇总页按产品显示计划包数、已扫包数、重量。
   - 达到产品上限或订单总上限后强锁止。
5. **上传**
   - 有 WiFi 时按订单上传。
   - 上传内容：订单号、车号、柜号、操作员、设备号、作业起止时间、所有产品明细及扫码记录。
   - 上传成功后台状态更新为“已上传完成”。
   - 上传失败本地数据完整保留，可重复重试。
   - 上传接口幂等，同订单同条码不会重复写入。
   - 支持上传后自动扣减库存（可配置开启）。
6. **辅助功能**
   - 条码离线查询。
   - 本机订单管理：待扫码、待上传、已上传。
   - 本地缓存清理：只允许清理已上传订单。
   - 音效开关：扫码音、成功音、失败音。
   - 支持 PDA 本地打印装车小票。
   - 支持异常备注：扫码时可标记破损、标签模糊等异常信息。
   - 支持完整操作审计日志。

#### 技术方案

- 原生 Kotlin + Android View。
- MVVM + ViewModel + Flow。
- Room (SQLite) 开启 WAL。
- Retrofit + OkHttp + Coroutines。
- SoundPool 播放短音效。
- 广播接收扫码结果，不依赖厂家 SDK。
- 广播 Action：`com.android.decodewedge.decode_action`
- 条码 Key：`com.android.decode.intentwedge.barcode_string`
- 屏幕锁定竖屏，适配 480×800。
- 应用峰值内存控制在 250MB 以内。

### 4. 完整系统功能范围

系统需完整支持以下能力：

- 库存导入、查询、映射维护、导入日志。
- 订单创建、多产品明细、订单列表、详情、汇总、PDF/Excel 导出。
- 订单作废、修改、重新下发 PDA。
- 多 PDA 并发作业订单锁定。
- PDA 离线扫码、六层校验、实时汇总、按订单上传、上传幂等。
- 条码损坏时人工手动输入，F1 校验，回车保存。
- 音效交互：扫码音、成功音、失败音，支持开关。
- 上传后自动扣减库存（可配置开启）。
- PDA 本地打印装车小票。
- 异常备注：扫码时标记破损、标签模糊等异常。
- 完整操作审计日志。
- 后台权限管理、操作日志查询。
- PDA 本地缓存管理、时间同步、上传重试。

## 三、整体一句话总结

> 老系统是一台无网络的离线扫码枪，靠人工维护 `sku.txt`、拷贝 `out.txt`、Excel 整理台账；新系统要做的是一套 **Web 后台 + Android PDA 离线扫码端**，实现订单驱动、一车多产品、离线高速扫码、本地六层校验、实时汇总、按订单上传、后台统一管理和 PDF/Excel 导出，并完整支持订单作废修改、多 PDA 并发锁定、自动扣减库存、本地打印、异常备注和审计日志，彻底替代人工拷贝和 Excel 汇总。
