# PDA 页面与现场交互规范

日期：2026-09-17。状态：设计提案，关联[设计总规范](design-system.md)与[状态语义](status-semantics.md)。面向M71的Android原生界面，不把Web缩小后搬到PDA。

## 1. 设备与业务底线

[已实测设备](DEVICE_SPEC.md)为Android 9、480x800、density240，逻辑空间约320x533dp；可用空间还需扣除实际系统栏与软键盘。不能把480当作dp宽度，也不能假定所有M71固件和键位完全一致。

保留已经确认的B模式：完整扫码广播 -> 校验 -> 自动保存；手输 -> 校验 -> 人工确认保存。错误暂停后续保存，原输入及确认意图保留；实体扫描键交给厂家解码，不模拟Enter。未决输入不能通过换单、清空资料或切换模式跳过。

UI优化保留本机身份、原订单、原序号、原请求、签名校验、断电恢复和占用关系。当前源码的新功能是否已安装与实测，实施时分别核验。历史Demo验收不因本方案重新打开。

## 2. 页面架构

| 页面 | 首要内容 | 去向 |
| --- | --- | --- |
| 设备登记 | 环境、登记短码、等待/确认状态 | 绑定成功后人员登录 |
| 人员登录 | 设备/仓库身份、账号密码、错误 | 登录后本机任务与待领取订单 |
| 订单 | 本机任务、待领取两类；异常任务可定位 | 准备资料、继续扫码、上传/核对结果 |
| 订单准备 | 车号、计划、资料准备与校验状态 | 原资料激活成功后进入扫码 |
| 扫码装车 | 当前包、阻断错误、有效装车数量 | 手输、订单明细、结单核对 |
| 订单明细 | 产品汇总、包明细、未处理输入 | 返回同一作业上下文 |
| 结单与上传 | 实物核对、冻结、上传、后台结果 | 原批次恢复或返回任务列表 |
| 停止与恢复装车 | 原机停止、证据、主管处理、恢复资格 | 验证成功后回原订单作业 |
| 设备信息与设置 | 身份、环境、声音、连接诊断、版本 | 回来源页；退出登录为独立动作 |

这些是界面职责，不要求每一项新增一个Activity；可使用现有导航/页面结构实现。登记、登录、订单列表不会继续混在一个长ScrollView里。

订单页作为登录后入口，不新增带统计图的首页。设备信息入口在标题栏可见，退出登录放设置中，避免与高频刷新相邻。扫码作业页不放全局底部导航，防止误切任务。

## 3. 标题栏、状态与背景

标题栏约48dp，白底、细分隔；左侧返回图标触控区48dp，中间页面名/车号，右侧最多一个必要工具入口。必要的第二行显示仓库或订单末段，完整标识在详情中可查。实际操作对象不能只出现在小字页脚。

应用连接状态在标题附近紧凑显示：后台可达、后台不可达或待核对；网络详情区分Wi-Fi、后台和授权。测试环境在登记、登录和设备信息明确标出，已绑定后不能靠一个设置开关静默换环境。系统电池/Wi-Fi图标已可见时不重复堆满一排图标。

主体以白色和中性浅灰分区，正文高对比度。状态条采用轻背景、明确文字和图标，避免整个页面随成功/失败变色。红色阻断在恢复前保持可见；正常离线但允许作业时使用中性提示，不制造持续报警。

操作按钮最低48dp，主要确认56dp，按钮间距至少8dp。不会用两个长文案按钮挤在同一窄行；工具图标可并排，完整业务命令必要时纵向排列。

## 4. 扫码页空间分配

布局从上到下为：

| 区域 | 内容与尺寸基准 |
| --- | --- |
| 对象栏 | 返回、车号，约48dp；必要身份辅助行约24dp |
| 当前包/错误区 | 约88-112dp起，完整条码、产品、结果；错误时允许扩展 |
| 本单摘要 | 有效装车/计划、净重、待处理数量，约44-56dp |
| 可滚动内容 | 当前产品进度及少量最近记录，使用剩余空间 |
| 状态操作区 | 正常约48dp次要入口；待确认/错误时约56dp主操作及必要间距 |

以上不是全部强制最小高度相加。系统栏、字体放大或错误区扩展后，首先减少最近记录和产品预览，再压缩摘要副信息，保留车号、当前错误/条码、处理动作。无法容纳时将次要信息移至明细页，不用裁切或缩小关键字号应付。

正常连续扫码时，主要动作由实体扫描键完成，底部保留手输和明细入口；不占据大块空间放一个不可点击的“自动保存”按钮。结单在订单明细的明确入口执行，进入核对页暂停扫码，不会一键直接冻结上传。

当前包区域的展示规则：

- 初始显示“等待扫码”；收到完整输入后根据真实阶段显示正在处理或待人工确认，不把解码成功当作保存。
- 本机事务提交成功后，显示条码、产品与“已保存到本机”，数量更新；保留最近一次结果直到下一输入，不能短到无法辨认。
- 错误显示“本包未保存”、原因与当前可执行动作。后续到达的输入只更新待处理数量，不能覆盖当前错误或借一次确认处理下一包。
- 存储故障/队列入口溢出显示停止状态，并区分已持久化输入与可能未记录的输入，不能统一显示“都已保存”。
- UI绘制可以合并，但每次业务事件、保存序号和反馈依据不能丢失。当前正在处理的包与最近成功的包有明确标识。

## 5. 多产品、明细与数量口径

扫码页显示当前产品及相邻少量产品进度，默认最多3行预览；产品多时提供完整汇总入口。完整汇总按稳定的计划顺序排列，不因当前扫描不断重排导致定位跳动。当前产品用细标记/轻底色提示。

每行包含发货代码、有效装车/计划包数；重量按空间放副行。进度条为辅助，不替代数字。达到计划写“数量已达计划”，不写“已完成出库”；继续扫描该产品应拒绝保存并保持原数量。错误色表达被拒绝的输入，不把超装表现成允许保存后的红色进度。

区分历史已保存、撤销/卸货/隔离、当前有效装车、本轮提交、后台确认出库数量；具体口径见状态文档。明细保留原扫码序号与状态标记，不能为了视觉整齐重新编号或删除被撤销的记录。

完整明细以可复用列表分页/按需读取，支持按实际字段查找条码和产品；未处理输入有独立入口与数量。最近记录只读预览，撤销末包等影响实物的动作进入核对流程并填写原因。

## 6. 订单列表与资料准备

订单页以分段选择“本机任务 / 待领取”。本机任务优先，提供待处理/待上传等真实状态筛选；不能依据仅已领取就显示“正在装车”。卡片/行只包含车号、订单号、状态、关键数量和一个当前动作，详情再展示技术信息。

本机任务由本地数据库按需查询，待领取按服务端分页请求，建议每批20条。采用可复用列表，向后加载时有结束和失败反馈，返回恢复列表位置。不能在首页循环请求所有服务端分页后一次创建全部视图；数据量大时限制内存中的页面窗口。

刷新通过可辨认的图标入口执行，不要求用户发现下拉手势。刷新不丢本机离线任务，也不重排正在点击的行。领取结果待核对的任务保留独立恢复入口，不再出现第二个“领取”请求。

资料准备显示真实阶段“下载资料 / 校验资料 / 准备完成”；已知字节才显示百分比，未知总量用阶段进度。失败区分下载可重试、签名/身份不一致须处理、本地空间不足；未原子激活成功不能让用户开始扫码。

## 7. 手输、软键盘与实体键

手输入口显式打开输入区，字段标签“条码”，允许字母数字并保留前导零。手输输入框与扫码广播职责分离；不因焦点在输入框就把真实扫码变成人工输入，不依赖厂家键盘注入或自动回车。

键盘弹出时隐藏最近记录、减少产品预览，输入框、当前错误和校验动作保持在键盘上方；订单身份压缩但可辨认。以系统insets/实际可用区域处理，不写死键盘高度。键盘收起恢复原位置，不自动提交；必要时提供收起键盘图标。

键位保持当前已验证规则：K1/F1校验手输；Enter按当前状态确认手输、确认错误或触发受控恢复；K2/F2只处理允许清空/放弃的未确认手输。已持久化的原扫码与确认意图不能通过编辑输入框覆盖。错误处理后重新输入形成新的可追溯输入。

主界面显示清楚的动作名称，不常驻一排“F1/Enter/F2”教学条。键位位置和当前绑定进入设置/诊断，依设备实测配置展示；不为未知固件宣称已校准。长按重复不能造成多次保存。软键盘Enter不借用实体确认权限。

顶部返回、实体返回和系统返回遵守同一业务离开规则；键盘打开时先收起键盘，不退出作业。离开可恢复的页面保留状态，有未处理输入时明确提示其保留及不能换单的限制；进入明细/弹窗后暂停自动作业，返回依据状态恢复。

## 8. 声音与视觉联动

保留已确认PASS/FAIL音频，不新增每包“校验通过”提示音。厂家识别提示只代表解码，不代表计包；本应用PASS只在最终本机事务成功后触发，FAIL与明确失败相对应。错误优先，恢复时不重播旧成功造成再次计包的错觉。

静音时通过条码、结果文字、数量变化和错误区独立判断结果。声音开关状态可查询，音频加载/播放故障在诊断与必要状态提示中呈现，不把“已调用播放”当作操作者已听见。

## 9. 结单、上传与恢复

结单页首先展示车号与逐产品计划/有效装车差额，未处理输入单独阻断，短装原因就地填写。没有完成核对不能靠大按钮跳过。用户确认后冻结原正文，后续页面呈现阶段状态，不一直并排显示所有阶段的大按钮。

| 当前情况 | 主动作/反馈 |
| --- | --- |
| 尚未冻结 | 核对并结单；说明冻结后停止扫码 |
| 已冻结未上传 | 上传本单；断网时可加入上传队列 |
| 已加入队列 | 显示等待上传条件，保留原批次，不反复创建任务 |
| 上传处理中 | 显示真实阶段，可查看对象详情；不伪造百分比 |
| 结果未知 | 核对原提交结果；有限自动恢复及显式查询 |
| 待主管处理 | 显示具体原因与等待对象，不建议反复上传解决审批 |
| 已验证成功回执 | 后台已确认出库；明确结果与返回任务列表入口 |
| 退回/取消/停止 | 原记录与占用保留，进入已有受控处理流程 |

后台自动上传遵守现有Wi-Fi策略；手动上传不因UI规范擅自改变网络政策。网络重连提示有已排队任务即可，不自动冻结订单、提交未授权动作或清理本机资料。

停止与恢复页将申请原因、原机停止确认、主管处理、原机核验恢复按真实阶段呈现。原机没有联网就不能显示已收到新停止指令；主管批准不等于设备已经恢复。实物卸货/隔离证据和库存占用结果分别说明。

## 10. 登记、登录和设置

短码登记按[已确认方案](PDA_PAIRING_REGISTRATION_DESIGN.md)：显示服务环境、分组8位短码、有效时间、等待状态；收到管理员信息后由PDA核对仓库/设备名称，保存成功才进入登录。断网、过期与结果未知有不同恢复动作，不能要求用微信、编辑器搬运公钥或UUID。

人员登录保持账号与密码标签、密码可见性工具、明确错误；登录请求中防连点。默认不把密码长期保存成“记住我”；会话到期与本机已保存作业分开处理。退出前说明资料保留，退出不是放弃订单或释放占用。

设置只放实际可用功能：设备名称/编号、当前仓库/环境、App版本、声音、连接与设备键位诊断。敏感标识、原始错误码在高级详情按权限查看；不提供“清空所有数据解决故障”的常规按钮。换机、解绑、迁仓须走已有独立业务流程，不能作为普通设置开关。

设置页后续接入[应用检查更新与安全升级](PDA_APP_UPDATE_DESIGN.md)，登记/登录页也提供可达入口。第一版由操作员手动检查并调用系统安装器，检查、下载和安装状态可恢复，渠道/签名/清单/APK校验须通过。安装在经核对的安全点执行，与扫码、冻结和上传等动作互斥；已持久化的待上传/待审批资料按经过验证的迁移路径保留，恢复对账阻断不因升级解除。不清除设备密钥、订单或Room记录。

## 11. 验证与实施定位

优先涉及[准备页](../android/app/src/main/res/layout/activity_main.xml)、[订单列表生成](../android/app/src/main/java/com/acrylic/outbound/pda/ui/OrderCards.kt)、[扫码布局](../android/app/src/main/res/layout/activity_work.xml)、[扫码渲染](../android/app/src/main/java/com/acrylic/outbound/pda/ui/WorkRenderer.kt)和[结单页](../android/app/src/main/res/layout/activity_submission.xml)，样式集中到Android资源，不为视觉调整重写作业引擎。

验收覆盖正常扫码、重复/错误、手输未确认/已确认、键盘打开、离开返回、断网、授权到期、资料损坏/存储失败、上传结果未知及长列表。使用实际系统栏和字体设置核对480x800，不以高分辨率模拟器截图代替M71。

强光下检查条码、数量和状态可读性；静音下由操作员辨认当前包是否保存；连续扫描时检查错误是否被覆盖、视图是否跳动。保留原数据与密钥，正式App的现场验证与历史Demo记录分开。需要截图时使用获准测试构建/环境或合适取证方式，不关闭生产安全标志。
