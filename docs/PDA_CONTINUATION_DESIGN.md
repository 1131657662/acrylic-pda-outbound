# 受控续作：原人原机全量保留

依据 V2.3 §6.8、§12.11，承接 0.4.0 的完整恢复包及原机停止证明。

本阶段支持正式订单、原人原机、原计划/产品/重量快照不变、全部保留。卸货减包、换机、计划修订和恢复代次变化必须先走各自核验流程，本入口明确拒绝。已成功订单只能更正。

## 服务端

1. 原 S1 必须 REJECTED/ABORTED，召回 STOPPED，完整恢复包无未决冲突。申请携带旧批次、轮次、修订、设备、恢复包及逐包 RETAIN 清单；申请不发资格。
2. 主管使用 order:resume 审批，并填写实物核验凭据。锁定来源→订单→申请→批次→包，重验版本/周期/当前库存及保留集合。事务内创建新资格，轮次加一，清除旧 current，记录 superseded 关系，占用直接转 CONTINUATION_RESERVED。48 小时从签发时固定计算，重试不延期。
3. 原人原机联网取得签名续作票据。票据绑定新旧授权、原恢复摘要、原计划、保留集合、高水位+1及新轮次；激活回执绑定同一票据。未完成本地核验不能恢复扫码。
4. S2 保留完整旧 captures/scans/events，新增行必须来自新授权且序号高于核验高水位。旧事实逐条摘要相等。分块控制头只固定本轮唯一在途批次，此时 current 仍为空、包仍为 CONTINUATION_RESERVED；完整正文校验通过后，同一事务选唯一 current 并转移保留包占用。漏行、改行、周期冲突整事务回滚。旧审批和旧批次不能复活。V12 唯一约束保证每来源每轮至多一个批次；提前取消仍保留原控制头及墓碑。

## 本机

本地 assignmentId 作为稳定作业容器，旧 PreparedOrder、提交正文、恢复包只读保留。新增 originAssignmentId 明确区分记录来源和容器；历史行迁移填入原授权，新事件/输入填入续作授权。续作独立持久表保存签名票据；WorkStore 取当前资格但复用已验签且摘要相同的原计划/库存。

旧提交 current 标记取消，新轮次使用新 submissionId、正文和摘要。继续前核对完整恢复正文、本机统计、全部保留行及扫码号高水位，所有激活变更同一 Room 事务提交。保留包禁止普通 VOID；新增未提交误扫仍按原规则处理。读取大正文继续使用 128 KiB BLOB 分片。

## 验证

真实 MySQL 验证权限/仓库隔离、同键重试/异文、旧终态和迟到审批、逐包集合完整性、周期冲突回滚、抢提交及无放锁窗口。Android 验证升级、签名、原子激活、来源/序号/旧正文保留及重新冻结。最后验证 Web→PDA→S2 回执闭环并运行相关回归。生产、真机和 Git 发布不包含在本轮操作中。
