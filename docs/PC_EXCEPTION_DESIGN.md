# PC 异常处置闭环

2026-09-18。用户已授权开始 PC 换人接续、卸货释放与隔离处理。本方案延续 PC 在线采集及 PDA 受控处置的业务约束，PC 不生成 PDA 身份或停止签名。

## 流程与状态

1. 具有 `order:recall` 权限的主管停止未完成的 PC 作业。锁定订单后固定原人员、轮次、全部录入记录及摘要，作业进入 `STOPPED`，递增窗口栅栏。待审核的提交转为 `ABORTED`，原正文和包占用保持。已出库或已结束的作业不能进入此流程。
2. 具有 `order:resume` 权限的主管提交完整逐包方案：本车保留 `RETAIN`、卸下并释放 `RELEASE`、卸下并隔离 `QUARANTINE`。每条必须属于停止时的有效集合，不得重复或漏包；减少行必须记录实物位置、核验结果和凭据。指定具备本仓库 `pc:operate` 权限的接续账号，计划、库存依据、可信重量和原序号不改变。
3. 主管核对固定方案并批准或退回。批准需要 `order:resume`，存在减少行还需要 `order:dispose`；受控结束还需要 `order:recall`。批准时重验指定人员权限、全部原包周期和占用及保留包库存，不释放任何包。批准后仍可在交接生效前撤回批准并重新申请，原方案与决定不可覆盖。
4. 指定接续人员登录并明确确认交接。后台重新校验停止摘要、审批、双方现有权限、恢复代次、所有原包周期和占用，复核保留包的实时库存；同一事务保存独立处置证据、释放或隔离相应占用、切换人员和轮次。新窗口须显式取得写入资格，原窗口和原人员的迟到请求不能继续写入。

全部卸下时可选择“结束本单”，要求没有保留包并逐包核验；生效后 PC 作业及订单为 `CANCELLED`，不创建出库事实或库存扣账。保留零包但继续补装也可明确选择继续；普通结单仍拒绝零包。隔离占用为全局 `QUARANTINED`，库存导入、其他 PC/PDA 订单不得覆盖，本轮不提供解除隔离。

## 证据与兼容

新增 Flyway V17，不修改 V1～V16。停止、方案、审批、交接与逐包处置分别持久化。原 `pc_entry` 条码、重量、人员、时间、序号、原始状态及 `pc_submission` 正文不改写；录入行只新增指向独立处置证据的关联，有效汇总排除已处置行。列表显示有效状态及单独处置记录，冻结新批次包含累计处置证据。已经交接保留的旧包也禁止普通撤销，须再次受控核验。

所有写请求复用 PC 原请求持久化、回执查询与同键同正文重试。拒绝串单、串仓、旧版本、旧摘要、漏包及伪造目标人员；未知结果不启动下一笔写入。旧冻结批次仍可核验，不因增加 API 字段改变其正文。Android 0.7.0/Room6 不变；新 Web 与 V17 后端配套使用。

## 验证范围

真实 MySQL 验证停止与迟到写入/审批竞争、原包全集、换人权限、批准不放锁、原子应用/冲突回滚、保留包不可普通撤销、释放跨单复用、隔离跨渠道阻断、全部卸下结束、同包再次录入、连续处置历史、幂等及恢复代次。浏览器验证申请→审批→换账号交接→继续录入、卸货和隔离、退回/撤回、响应丢失与刷新恢复、只读权限、分页记录及低高度/窄屏/200%布局。最终实际结果另记交付文档，不将源码完成等同现场验收。
