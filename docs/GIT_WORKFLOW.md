## 提交与上传检查

1. 核对分支、HEAD、远端、实际写者、全部差异和未跟踪路径，保护他人未提交改动。
2. 运行与本次范围相关的验证；历史结果注明版本/输入，不能替代当前验证。
3. 使用明确路径暂存，仅包含本次范围，复核暂存差异与清单。
4. 排除密码、私钥、数据库/备份、真实业务数据、本机配置、缓存/产物及 `out.xlsx`；私有仓库也不存这些内容，忽略规则不会清除历史泄漏。
5. 按下列格式提交，并按已有授权推送到正确分支。阶段备份明示“开发中”或“阶段备份”，不因可备份而省略必要验证。

标题：`类型(模块): 具体变化`，清晰中文；类型为 feat/fix/docs/test/build/chore/refactor，单一范围可省略模块。正文包含：

```text
改动：解决的问题和范围。
验证：实际运行及结果；未运行、失败和历史引用明确说明。
未完成/已知问题：后续工作和适用限制；没有则写“无”。
版本/兼容：APK、接口、数据库及升级影响；无影响则注明。
```

仅文档可简写“已检查文档及引用，未运行业务测试；仅文档，无运行行为变化”。分别报告测试、构建、接口联调、模拟器、真机和部署，不将其互相替代。

## 版本与交付产物

- 测试版本用预发布标签（示例 `v0.3.0-alpha.1`）和 Pre-release；正式版本须完成相应验收并合 main 后使用正式标签（示例 `v1.0.0`）。示例不代表已有发布或授权。
- 标签固定在明确提交，发布后不移动，修订用新版本。Release 说明包含 SHA、APK 与 SHA-256、实现范围、实际验证、已知问题及升级注意事项；源码版本、APK 内版本和文件名一致。
- APK 等大型产物优先放 Releases，Git 保存源码、配置、锁文件、必要 schema 与文档。当前本机产物未发布前不视为已异地备份。
- 按范围收口已验证子项；现场、运维/审批和跨步依赖单列，不把局部通过写成完整上线。
