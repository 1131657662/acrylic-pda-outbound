# 状态、文案与错误恢复规范

日期：2026-09-17。状态：设计提案，作为[设计总规范](design-system.md)的状态与术语来源。本文件给出本轮核对的主要状态映射及扩展规则，不宣称已穷举未来全部错误码。新增流程实施时按实际契约补充，不能凭界面名称新增后台状态。

## 1. 状态必须回答的问题

每条重要状态定义六项：对象、事实来源、用户文案、强调级别、可执行动作、禁止动作/恢复边界。Web读后台结果，PDA本机状态与已验证后台结果分别展示；同一英文值在订单、上传、召回等领域不能共用一个无上下文翻译函数。

新增[PC手工出库](PC_MANUAL_OUTBOUND_DESIGN.md)的计包状态来自后台：选择候选=未计入，后台逐包保存=已计入本单，最终出库完成=后台已确认出库。PC“已计入”不借用PDA“已保存到本机”，也不意味着最终已出库。作业渠道与订单创建来源分开显示，PC当前接口枚举为ACTIVE（PC录入中）、REVIEW_REQUIRED（待主管审核）、REJECTED（已退回，保留占用）、SUCCEEDED（后台已确认出库）。REVIEW_REQUIRED若含库存/占用冲突，须同时展示阻断原因，不能只按短装批准。未知回执先恢复原请求；刷新或关页不释放占用。

优先级从高到低：必须停止/存储故障/身份异常 -> 当前包错误或待确认 -> 当前任务进度 -> 全局连接与低频提示。阻断状态持续显示且不能被普通成功消息覆盖；多条问题显示最关键原因及数量，完整清单可查看。错误解除须基于真实状态变化，不能只关闭提示。

颜色含义：红色为失败/阻断，琥珀为等待处理/结果待核对，蓝色为进行中或普通信息，绿色为具体阶段的已确认事实，灰色为中性或历史状态。所有颜色附明确文字，不以图标或颜色独立授权操作。

## 2. 页面命名与动作词

| 当前或易混用表达 | 建议展示 | 约束 |
| --- | --- | --- |
| 库存查询与版本 | 库存查询；标签“库存版本” | 不将两个任务塞入每个标题 |
| 发货代码映射 | 导航“发货代码”；标题“发货代码与产品” | 字段仍叫发货代码，保留三位字符串 |
| 出库政策 | 出库规则 | 数据结构/版本不改名或重建 |
| 已分配 | 已领取 | 只证明领取，不宣称正在扫码 |
| 装车实绩 | 装车记录 | 标明后台已收到或本机已保存 |
| 待复核 | 待主管审核 / 存在冲突，待处理 | 依据具体原因，不能一律显示可批准 |
| 召回 | 停止装车申请 / 停止装车核对 | 保留管理员详情中的技术名称，明确原机是否已确认 |
| 受控续作 | 申请恢复装车 / 核验并恢复装车 | 主管批准与原机激活分别显示 |
| 固定恢复包 | 确认核对结果；上传停止记录 | 确认区说明记录将固定且不能修改，技术详情保留原名称 |
| 确定 / 提交 / 处理 | 保存草稿 / 批准短装出库 / 查询原提交结果等 | 按实际副作用命名，不给同一按钮罗列多个阶段 |
| 返回（资料保留）等长标签 | 统一返回图标与可访问名称 | 有未处理资料时在离开提示中说明影响 |

标题说对象或任务，状态说事实，按钮说动作。默认不用UUID、摘要、epoch、scope、原始枚举让用户辨认业务对象。技术字段保留在有权限的“技术详情”，可用于排查；不删去故障所需证据。

## 3. 网络、后台与授权

| 事实 | 用户表达 | 操作边界 |
| --- | --- | --- |
| 没有可用网络 | 网络未连接 | 允许具备完整资料及有效授权的本机作业；不能声称后台已收到 |
| 网络存在，后台请求失败 | 后台暂时无法连接 | 不等同账号失效；保留本机内容，按原请求恢复 |
| 最近成功访问后台 | 最近连接正常，附时间 | 不据此宣称持续实时在线或其他设备在线 |
| 尚无可用连接证据 | 连接状态待核对 | 可发起查询，不显示虚假绿点 |
| 当前在线身份失效 | 请重新登录 | 原订单/提交保留；是否允许本地新增按现有资格规则判定 |
| 离线授权到期 | 本单扫码授权已到期 | 禁止新增保存；原数据保留，符合规则时仍可结单上传 |
| 时间可信度失效 | 需联网核对时间后继续扫码 | 不以设备显示时间自行延长资格 |
| 服务器要求恢复/对账 | 后台正在恢复，需核对原记录 | 按服务模式限制写操作，不自动换恢复代次绕过 |

Wi-Fi连接仅说明网络介质，不能作为后台可达证明。浏览器/PDA用实际请求或获授权的轻量连接检查更新状态，展示最近核对时间，不为一个绿点持续高频轮询。订单数据另显示最近成功读取时间，与连接时间分开。

“待上传N单”只统计当前用户/设备范围内符合定义的冻结待提交任务；“已排队N单”“待核对结果N单”分别计算。未结单、不属当前人员、已被后续轮次替代的历史批次不能混入可上传计数。

## 4. 订单与提交状态

### 4.1 后台订单

| 现有状态 | 建议文案 | 允许的主要入口与限制 |
| --- | --- | --- |
| DRAFT | 草稿 | 编辑、校验后发布、符合条件时作废 |
| READY | 待领取 | 查看；获授权时修订重新发布/作废；PDA领取需后台裁决 |
| ASSIGNED | 已领取 | 查看领取设备/人员；无实时证据不显示正在装车或实时包数 |
| REVIEW_REQUIRED | 待主管处理 | 查看具体审批/冲突原因；仅符合条件的短装可批准 |
| RECALL_PENDING | 停止作业处理中 | 通用订单标签；PDA需核对原机停止证明，PC需查看停止、处置与交接阶段，不能由此值推断具体阶段 |
| CONTINUING | 恢复装车处理中 | 根据续作请求显示待批准、待原机激活等子状态 |
| COMPLETED | 后台已确认出库 | 查正式结果/回执；不等同一定已自动扣库存 |
| CANCELLED | 已作废 | 只读历史；释放与否按实际业务证明，不能由标签推断 |
| LINKED | 已关联正式订单 | 显示有权限的关联对象；不把关联自动译成出库成功 |

若某种状态当前页面尚未实现完整流程，只展示可信事实与详情入口，不提供猜测动作。未知状态显示“状态待核对”并提供查询入口，不落成默认绿色，也不自动进入任一可写流程。

### 4.2 PC异常处置与交接（0.14.0）

PC详情继续显示独立作业状态；订单列表使用通用状态，避免把PC作业解释成待原PDA确认。实物处置与正常出库分别显示，参见[PC异常处置设计](PC_EXCEPTION_DESIGN.md)。

| 对象/状态 | 显示文案 | 操作边界 |
| --- | --- | --- |
| PC作业 STOPPED | 已停止，待实物处置 | 原窗口不能写入；保留全部原包占用，先逐包核验方案 |
| 方案 PENDING | 待主管审核 | 核对实物、去向及接续账号；不得按待审方案释放包 |
| 方案 APPROVED | 已批准，待本人交接 | 指定人员核对后确认；批准尚未改变占用 |
| 方案 REJECTED | 已退回，占用保留 | 原方案及决定保留，重新提交完整方案 |
| 方案 APPLIED | 交接已生效 | 保留包属于本单，释放包可按规则重新使用，隔离包继续禁止出库 |
| PC作业 CANCELLED | 已核验结束，未出库 | 全部有效包已按方案卸下；未生成出库或扣账，隔离占用仍有效 |
| 录入 RELEASED | 已卸货释放 | 原录入事实保留，不再计入本单有效数量和重量 |
| 录入 QUARANTINED | 已实物隔离 | 原录入事实保留，不计入本单有效汇总；全局隔离继续生效 |
| PC提交 ABORTED | 已停止原提交，记录保留 | 停止前的冻结正文不改写，不能继续批准该批次 |

未提交方案必须逐包明确选择，无默认全保留；提交按钮只有在全集、原因、人员和实物确认齐全时可用。未提交编辑与结果未知分别提示，放弃编辑会清空未发送资料；未知结果须恢复原请求。停止、批准、交接的成功提示不表示已确认出库。

### 4.3 提交、传输与放行

| 来源/状态 | 主文案 | 下一步与禁止事项 |
| --- | --- | --- |
| 本机未结单 | 本机已保存，尚未结单 | 继续有效扫码或核对结单，不表示后台已收到 |
| PDA FROZEN | 已结单，等待上传 | 原正文固定，不能继续改本轮扫码事实；可加入上传队列 |
| 后台 REGISTERED | 提交已登记，资料待接收 | 按原批次继续传输；不能写上传成功 |
| 后台 RECEIVING | 正在接收本单资料 | 显示可证实的传输进度；不能放行 |
| PDA RESULT_UNKNOWN | 提交结果待核对 | 查询原批次，必要时重传原正文；不重新结单/生成新ID |
| PDA ACTION_REQUIRED | 上传需要处理 | 展示具体原因，按权限/数据/身份分类恢复；不一律写网络失败 |
| REVIEW_REQUIRED | 后台已接收，待主管处理 | 显示短装或冲突原因；不能放行，不能靠反复上传代替审批 |
| REJECTED | 已退回，记录与占用保留 | 进入已支持的受控处理，不自动解冻或续扫 |
| ABORTED | 传输已取消，记录与占用保留 | 原批次终结；不是删除订单或释放所有包 |
| 后台 SUCCEEDED | 后台已确认出库 | 展示当前有效结果、数量、重量、是否扣库存 |
| PDA SYNCED | 后台已确认出库，回执已核验 | 仅当前对象/轮次匹配、验签及本地保存成功后展示最终结果 |

回执验签失败、对象不符、旧轮次回执、本地保存失败均不得展示允许放行。放行判断按当前有效业务结果，不凭按钮点击、HTTP成功、主管批准动作或单个绿色标签。

### 4.3 停止、恢复与实物处置

| 事实 | 用户文案与边界 |
| --- | --- |
| 召回 REQUESTED | 已申请停止，等待原PDA确认；离线原机不能即时收到 |
| 召回 STOPPED / 本机已验停止证明 | 原PDA已确认停止，订单与占用保留 |
| 召回 CANCELLED | 已完成本次核验作废；以具体结果说明对象，不套普通取消提示 |
| 续作 REQUESTED | 已申请恢复装车，等待主管核对 |
| 续作 APPROVED | 主管已批准，等待原PDA核验；尚不能称已经恢复扫码 |
| 续作 ACTIVATED | 原PDA已核验恢复；新增保存仍受当前资格、计划及时间限制 |
| 续作 COMPLETED | 本轮恢复装车已完成；最终出库结果另核对 |
| 实物 RELEASE 凭据 | 已核验卸货；不能直接显示库存已释放 |
| 实物 QUARANTINE 凭据 | 已核验隔离；全局占用/隔离生效按实际后台事务区分 |

现有[实物处置规则](PDA_DISPOSITION_DESIGN.md)将批准、原机激活与替换提交分为不同阶段。减少本车有效装载数不等于释放全部库存，也不允许把历史原扫描改写成未发生。

## 5. 本包状态与音效

| 原输入事实 | 屏幕表达 | 动作与声音 |
| --- | --- | --- |
| 尚未接收 | 等待扫码 | 无保存提示 |
| 已耐久接收/排队 | 条码及“等待处理”，有必要时显示队列数量 | 不加装车数、不响PASS |
| 自动扫描校验通过 | 正在保存或直接过渡到真实成功 | 不要求Enter，不新增校验成功音 |
| MANUAL + WAITING_CONFIRM | 手输校验通过，等待确认保存 | 确认只绑定当前输入；未确认不计包 |
| COMMITTED/真实保存事务成功 | 已保存到本机，显示当前条码与产品 | 数量按真实有效汇总更新，PASS |
| INVALID / BUSINESS_REJECTED | 本包未保存，显示具体原因 | FAIL；暂停后续保存，确认当前错误不确认下一包 |
| 存储状态无法确认 | 已停止，请核对原记录 | 核对同一输入结果，不能把异常一概解释成未保存 |

自动保存与人工确认的事实来源必须保留。已接收原始文本不可原地编辑；重新输入可更正错误，但形成新的输入记录。撤销与实物处置另走有原因的业务动作，不能通过删除列表行实现。

## 6. 数字与数据口径

- 计划包数：当前有效计划各产品之和，不能添加历史116包限制。
- 历史已保存记录：追溯事实，可能包含后续撤销或实物处置，不直接等于当前车上数量。
- 有效装车包数/净重：按当前有效轮次及已核验处置规则计算，汇总与明细对应；不把多轮保留记录重复累加。
- 后台已收到包数：后台已经收到且可核对的资料范围；离线PDA尚未上传的数值不能在Web臆测。
- 后台确认出库包数/净重：以最终当前有效出库结果为准；自动扣库存关闭仍可有已确认出库事实。
- 在库/扣账/冻结/占用分别是不同维度。未扣账不等于可用，准备时可用不等于现在已为本单预留。
- 未取得值显示“尚未收到”“暂无记录”等精确原因；0只表示已经确认的零值。发货代码与条码保留前导零；重量以整数克精确换算，千分位只影响显示。

## 7. 错误文案与恢复矩阵

常用结构为“发生了什么 + 本次结果/影响 + 下一步”，不要求每个小错误写三句话。字段错误短句，现场阻断明确“本包未保存”或“结果待核对”；技术码、请求号放详情并可复制，不输出栈、密钥或凭据。

| 已存在的情形/代表码 | 建议用户文案 | 恢复方式 |
| --- | --- | --- |
| 条码格式不合法 | 本包未保存，条码应为11位数字或英文字母 | 确认错误，重新扫描或重新手输；原输入保留 |
| 条码不在本单固定库存 | 本包未保存，当前订单资料中没有此条码 | 核对标签与订单，必要时由主管处理；不能普通刷新替换本单快照 |
| 错产品 | 本包未保存，该产品不在本车计划内 | 核对实物和车号，确认当前错误 |
| 本机重复/占用 | 本包未保存，该条码已有本机记录 | 查看有权限的原记录，不直接解除占用 |
| 超计划 | 本包未保存，该产品已达计划数量 | 核对计划/实物，数量不增加 |
| 本机存储异常 | 保存结果待核对，已停止作业 | 核对原输入；未持久化部分明确提示，不直接重扫全部 |
| 网络写请求超时 | 操作结果待核对，原内容已保留 | 查询/重试原请求，不创建新身份；只有确已保存原内容才能这样表述 |
| SUBMISSION_STILL_CONFLICTED | 当前仍有库存或身份冲突，不能批准出库 | 展示具体冲突，进入已有核对流程 |
| INTERNAL_ERROR | 后台暂时未能确认结果 | 写操作保留原请求核对；读操作重试当前查询 |
| LOGIN_RATE_LIMIT | 操作过于频繁，请稍后重试 | 遵守后台重试时间，不连续自动提交 |
| SERVER_RECOVERY_REQUIRED | 后台恢复后需要核对原记录 | 保留原请求/代次和证据，按恢复流程处理 |
| 数据/签名不一致 | 资料核验未通过，请保留设备数据并联系主管 | 不继续放行、重新绑定或清库 |
| 未知错误码 | 操作未确认，请查看详情并核对原记录 | 默认保守展示，保留证据及实际原请求恢复入口 |

SUBMISSION_NOT_FOUND在原提交恢复查询中可能只是“后台尚未登记，继续发送原正文”的正常分支，不能全局映射成丢单。相同HTTP状态也需按请求是否发送、业务码和当前对象处理，不能把所有4xx当作可放心新建请求。

自动恢复必须有退避、次数/时限和人工接手状态；页面离开或切换对象后不继续更新错误的页面。会话刷新不自动代表重试已批准，权限/身份/仓库/内容变化要重新核对。操作成功提示以回执及持久状态为依据，旧请求的成功回执不能覆盖较新的对象状态。

“联系主管”默认是明确的处理说明，不伪装存在即时通信功能。“复制问题信息”仅在真实实现并去除敏感字段后提供；“导出证据”属于有权限、可审计的独立能力，不先做空按钮。

## 8. 呈现位置与验证

字段错误在字段旁；当前包错误在固定结果区域；订单级阻断在详情摘要或当前操作区；网络/身份异常在全局状态区域并只阻断相关操作。重复错误合并数量，不能连续堆几十条Alert把操作挤出视口。

关键审批摘要不能省略冲突、逐产品差额和动作后果。长原因可以展开，但“不能放行”“原记录与占用保留”等影响判断的信息不能藏进悬浮提示。常规页面不重复粘贴完整技术流程或操作教学。

实施时为状态建立代表性样本：未知值、旧回执、空结果、部分上传、已批准未激活、签名不一致、离线但可作业、离线且授权过期。验证文案、颜色、可操作性与实际业务结果一致；不只验证截图里的标签颜色。
