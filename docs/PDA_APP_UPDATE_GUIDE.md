## 操作员使用

1. 当前无可用更新入口或仍为 11 及更早测试版时，先退出扫码并处理未决保存/上传，通过 HTTPS 下载或 USB 文件传送取得首版 APK。在系统安装器中确认“为现有应用安装更新”；不得卸载或清空资料。
2. 从首页“检查应用更新”或设置页进入，核对环境、当前版本、上次检查时间和版本说明。检查失败显示原因，不会当作“已是最新版”。
3. 点击“下载更新”。可以暂停并保留进度；返回或进程结束后重新进入并继续。只有校验完成的 APK 才会出现安装入口。
4. 点击“安装更新”。正在扫码、保存、登录、配对、资料激活或联网任务未完成时会阻止；未处理输入、未知上传结果、召回/恢复及待确认续作显示原处理路径。已冻结且持久化的资料可以保留。
5. 若 Android 提示来源未允许，在系统设置中允许本 App 安装，返回后再次点击安装。安装前会再次联网核对发布是否仍可分发；撤回、清单变化或网络错误时保留资料并停止安装。
6. 系统安装由操作员确认。取消后仍使用旧版，可重试；安装后重新打开更新页，先核对实际版本、数据库可打开/quick_check 和原绑定密钥，再显示更新完成。原审批、占用和恢复限制继续有效。

## 已实现的保护

- 清单使用 ECDSA 验签，渠道、包名、来源版本范围、Android API、服务端兼容范围、APK 大小/SHA-256、实际版本/最低 API/证书均需一致。当前证书还与已安装 App 比较，不接受跨渠道、跨签名或降级安装。
- 所有更新流量强制 HTTPS，同一绑定服务的同渠道路径；不跟随重定向。清单大小和 APK 大小有上限，摘要按块计算，不整包读入内存。
- APK 保存在私有 `files/updates/`。强 ETag 和正确 Content-Range 才续传；服务器返回完整文件时重新写入，截断/取消保留有效部分，坏摘要清理无效临时包，验签后原子改名。下载完成和安装前均重新验证当前发布。
- 业务任务使用进程内安装互斥，包括扫码队列与前台扫码占用、保存、冻结、召回、续作、配对、登录和上传 Worker。先取得互斥，再次读取安全状态；安装取消/启动失败释放互斥。订单/包占用和原请求不因此释放或改写。
- FileProvider 只暴露更新目录；安装器 URI 仅临时授权。未提供静默安装、强装、卸载、清库、重绑或绕过系统确认的操作。

## 后续发布和停发

使用 `tools/publish_pda_update.py`，传入经验证的 APK、渠道、新发布ID、更高版本、来源范围、兼容服务端、证书摘要和说明。构建配置须包含 `pdaServerUrl`、`pdaEnvironment`、`pdaUpdatePublicKey`；对 staging 原生测试另加 `-PpdaTestBuildType=staging`。签名私钥不进入命令输出、Git或APK；staging必须继续使用已核验的Android签名材料。

先验证 `apksigner`、实际包名和版本，生成签名清单，再完整上传唯一APK、远端核对摘要，最后原子切换清单并保存旧清单和部署记录。脚本拒绝覆盖已存在的发布ID及向下发布版本；不覆盖本次03/04/05产物。测试源通过当前渠道分发；GitHub预发布使用 `v0.10.3-alpha.1` 固定源码及最终APK，提交/发布状态以Git及Release实际记录为准。

需要停发时撤下当前清单/对应APK并保存证据；修复采用新ID和更高versionCode，不把降版本或替换同名文件当成回滚。已经交给系统安装器的包无法靠清单撤回取消。
