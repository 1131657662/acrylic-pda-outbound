## 普通登记

1. 未绑定PDA进入短码登记，核对页面上的环境和服务地址，点“开始登记”。App自动提交本机公钥和私钥持有证明，显示如`4827 1953`的8位登记码，有效10分钟。
2. 管理员登录同一后台，选择获授权仓库，打开“PDA 设备管理”。在“短码配对登记”输入短码，核对型号、申请时间和仓库，填写设备编号与名称，勾选核对并发送给原PDA确认。
3. 原PDA前台每4秒查询本申请，取得待绑定的仓库、设备名称和编号。操作员核对后点“信息无误，确认绑定”。管理员确认前不能绑定，原PDA确认前不会创建已启用设备。
4. 后台登记完成且本机完整保存身份后，进入人员登录。账号密码和原私钥证明仍必需；配对不代替登录或增加权限。

普通操作无需复制公钥、输入UUID或借助摄像头。两端可位于不同网络，前提是均能访问同一后台。当前交付包配置`http://127.0.0.1:18083/api/v1/`，环境名为“本机联调环境（USB转发）”；这是本机测试地址，不能直接用于异地。正式HTTPS地址须在实际部署后通过构建参数配置，证书校验保持开启。

## 中断与恢复

| 情况 | 应执行的动作 |
| --- | --- |
| PDA断网、申请或确认响应丢失 | 恢复联网后点“刷新／恢复原请求”；重开App保留同一申请和确认内容 |
| 后台已登记，本机保存失败 | 保留原申请并恢复；完整落盘前不会显示本机绑定完成 |
| Web确认响应丢失或回执不匹配 | 保持同一标签页和同一账号、仓库，刷新后点“恢复原配对确认” |
| Web浏览器存储失败 | 请求不会发送，先恢复标签页存储再重试 |
| 信息不正确或设备编号冲突 | 先核对原状态；未完成时由原PDA取消，再用原密钥申请和核对新内容，不改写已批准信息 |
| 未完成申请过期 | 原PDA先联网确认EXPIRED，再重新申请；仍复用原Keystore密钥 |
| 已完成申请的短码到期 | 原PDA仍可用申请凭据和私钥证明恢复同一设备；管理员从本标签页原申请或设备列表核对 |
| 已有绑定、密钥丢失或服务器恢复代次变化 | 保留原设备与本机资料，联系管理员核对；不能以重新配对、清除数据或换UUID绕过 |

短码只供管理员查找，不能单凭短码领取结果。PDA申请凭据为32字节随机数，结合每次120秒挑战签名；服务端只存凭据摘要。申请、管理员批准及最终登记/取消有审计，不记录可用凭据或私钥。最终登记重新核验管理员账号、权限版本及仓库范围；并发只允许一个不可变结果。

PDA原申请和待发送动作保存在`noBackupFilesDir`内的AES-GCM加密原子文件，绑定身份单独原子保存并回读核对；密钥在Keystore，不备份到其他设备。Web恢复信息保存在`sessionStorage`，按账号/仓库隔离，不包含设备私钥或PDA申请凭据；关闭标签页不保证保留，不能据此判断后台未执行。

当前服务端保留申请、挑战和已完成回执，未接自动清理任务；已完成回执不以短码期限删除。限速为单进程10分钟窗口：挑战600次/IP、创建30次/IP、状态/确认/取消合计600次/IP，管理员短码查找30次/账号。正式反向代理、多实例限速及清理保留策略须在部署时核验；本轮不声称已做生产容量验证。
