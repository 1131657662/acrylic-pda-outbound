## 分阶段验证

| 阶段 | 实际结果 |
| --- | --- |
| 1. 原进程结束后重新启动 | 原会话可读、原身份接口成功、Keystore挑战签名通过、原成功提交/审计凭据再次验签；保存20张本地事实表和原绑定/公钥摘要 |
| 2. 服务器RECOVERY_PENDING | 客户端观察新代次2并持久化RECONCILING屏障；拒绝采用非NORMAL响应，原会话仍为代次1，没有新归档证明/确认点；业务保护检查拒绝放行 |
| 3. NORMAL但归档文件缺失 | 将原审计文件临时改名保管，保持原字节；真实恢复接口两次返回503 `ARCHIVE_EVIDENCE_UNAVAILABLE`，PDA保留同一待恢复请求，未保存新证明或推进确认点 |
| 4. 文件归还但恢复响应丢失 | 恢复文件原名/摘要后调用真实接口，服务端从签名证明和私有文件重建15条审计并签发代次2凭据；测试客户端在写Room前丢弃成功响应，PDA仍保存待恢复请求 |
| 5. 再次启动续接请求 | 新进程重新读取相同请求，取得与丢失响应完全相同的签名凭据；审计确认点推进至15，重复恢复结果稳定，RECONCILING屏障保持，成功提交不生成代次2归档证明 |
| 6. 完成后的再次启动 | 新代次证明和确认点持久保存、重新验签通过；普通NORMAL身份响应不会清除RECONCILING，原业务事实及旧代次两种证明保持 |

最终6个原生阶段均通过、0跳过。成功阶段进程PID依次为2863、3539、3627、3697、3758、3860；丢响应阶段与续接、再次启动明确是不同进程。这证明force-stop后恢复，不冒充硬件断电/文件系统崩溃测试。

第2阶段首轮有1次测试失败：测试误以为非NORMAL身份响应可更新会话并继续调用归档；实际 `PdaNetwork` 先观察新代次并保存屏障，然后抛出 `IllegalStateException`。修正为断言原会话保留、无新凭据且业务受阻后，同一保留数据复测通过。只修测试，没有放松业务保护；`pending-initial-failure.log`保留。计数为6阶段最终通过、另有1次初始失败，不写成首轮全部通过。
