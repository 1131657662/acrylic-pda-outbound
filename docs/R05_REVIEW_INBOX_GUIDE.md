# R05 当前超时待审入口

日期：2026-09-19。当前超时待审API、Web入口及中文历史提醒已完成源码和本机验证。契约0.21.0，数据库仍V28；本轮未部署公网、未改动APK或PDA。R05整体仍有持续同步与现场等待办。

## 实际行为

- Web“装车作业”下新增“超时待审”，仅向具备`submission:review`的用户显示。每页20条，显示完整订单号、车号、后台接收时间与提醒时间；桌面表格、窄屏列表复用既有规范。
- `GET /api/v1/review-reminders`校验当前权限和仓库，只返回已生成提醒、仍为订单当前提交且状态为`REVIEW_REQUIRED`的记录。审批、退回、取消或替代后，刷新会移出待办；原提醒和时间线不删除。未到期、尚未由Worker生成的提醒不在列表中，页面说明每分钟检查。
- 按`reminded_at DESC,id DESC`真实游标分页，游标保存仓库、时间和唯一ID；边界行已处理也能继续下一页。只查询`limit+1`条，无虚构总数。无权限403、无仓库权限404、无效/跨仓库游标400；页大小1至200。
- 点击订单或“核对并审批”进入现有装车记录页，沿用原审批摘要、确认、CSRF、恢复代次及原请求重试保护。返回重新查询原仓库/游标，未被移除的来源行恢复焦点和滚动；直接打开后可从首页查询。
- 首次失败可重试；刷新失败明确标识上次结果。仓库变化清除旧结果和游标，晚到响应不串入新仓库。已失效权限响应清空旧结果。
- 订单时间线将`SUBMISSION_REVIEW_REMINDER`显示为“待审超时提醒”，操作人显示“系统”，说明对应批次和满30分钟的时间；提示当前处理结果以装车记录为准，已处理历史不会被描述成仍待审。

后台原`ReviewReminderStore.list()`仍用于历史查询/测试，新待办使用独立只读查询，未把历史列表直接暴露为当前待办。未修改提醒Worker调度、审批或库存账务行为。
