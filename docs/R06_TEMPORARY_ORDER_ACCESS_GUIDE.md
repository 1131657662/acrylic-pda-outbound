2026-09-20。基线 `8f566e9`，分支 `codex/development`。本批已完成权限、设备准入、不可变回执及 Web 操作源码，后端和迁移验证通过；浏览器实际联调待审批条件恢复。R06 完整业务仍在开发，未开放临时建单或出库。

## 已实现范围

V29 新增四项权限：`temporary_order:manage/create/confirm/link`。默认仓库管理员仅增加 manage；三个执行权限分别由 `TEMPORARY_ORDER_CREATOR/CONFIRMER/LINKER` 角色授予，普通 PDA 操作员没有自动获得临时权限。

人员管理同时要求 `user:manage` 和完整仓库范围。持有临时管理权限时，可分配、查询和撤销三个执行角色；仅持执行权限不能转授。其他权限仍须在管理员自身可管理范围内，不能跨仓库、改本人角色或借临时管理授予审批等无关权限。`UserAccess.Scope.manageablePermissions` 仅用于人员管理，不写入实际身份权限，也不作为业务执行鉴权。

设备新增 `temporaryOrderEnabled`，旧设备、短码登记及高级公钥登记均默认 false。接口：

```text
POST /api/v1/devices/{id}/temporary-order?warehouseId=…
{ "expectedVersion": "1", "enabled": true, "reason": "已核对设备" }
```

要求有效 Web 会话、CSRF、`device:manage`、`temporary_order:manage`、当前仓库、恢复代次、幂等键、预期设备版本及非空理由。停用设备不能开启准入，但可关闭已有准入。每次新命令递增设备版本、撤销现有 PDA 会话，并原子写入回执/幂等记录/审计；失败回滚全部改动。同键同正文返回原回执，不再次撤销后来登录的会话；同键改正文拒绝。

设备与回执都返回准入值。登记及启停回执也保留操作时的值，旧回执不会随设备当前设置变化。原订单、离线授权全文与截止时间、提交、采集/审计事实和包占用保持。重新登录不更新原离线授权版本；涉及正在作业的设备须按既有受控续期/恢复规则处理，不能把开关当成解锁或放行。

Web 设备列表显示准入，具备双权限才显示开关。操作前核对设备、影响和理由；发送前保存原正文、请求键和代次，丢响应/错误回执保留恢复入口。0.21 遗留的 STATUS 请求缺少准入字段时按原版本 false 读取，发送的原命令正文不变。普通用户仍使用短码登记流程。
