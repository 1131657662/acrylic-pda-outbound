## 1. 项目概述

### 1.1 业务背景

仓库现场装车出库，作业区域无WiFi。原方案使用单机离线扫码枪，依赖 `sku.txt` 和 `out.txt`，需要人工拷贝、Excel整理，存在数据丢失、版本错乱、无订单、无追溯、无实时汇总等问题。

新系统采用支持WiFi的PDA设备，核心流程：

> **Web后台创建订单和导入库存 → PDA联网同步订单与库存 → 仓库离线扫码 → 回到有网区域按订单上传 → Web后台查看、汇总、导出。**

### 1.2 一期范围

一期包含：

1. Web后台：用户权限、库存导入、订单创建（支持多产品明细）、订单列表、订单详情、订单汇总视图、PDF/Excel导出。
2. PDA端：库存同步、订单同步、离线扫码、本地校验、实时汇总、按订单上传、本地缓存管理。
3. 服务端：认证、库存、订单、PDA同步、上传、导出接口。
4. 数据规则：条码格式、订单内产品匹配、库存校验、重复校验、产品包数上限、订单总包数上限。
5. 音效交互：扫码音、校验通过音、校验失败音、保存成功音，支持开关。
6. 支持条码损坏时人工手动输入，点击【校验】按钮校验，校验通过后按实体回车保存。

一期不包含：

1. 上传后自动扣减库存。
2. 订单作废、修改。
3. 多PDA并发订单锁定。
4. PDA本地打印。
5. 完整审计日志。
6. 异常备注。

## 2. 总体架构

### 2.1 逻辑架构

```text
┌──────────────────────────────────────────────┐
│                 Web后台管理系统                │
│  用户权限 / 库存导入 / 订单管理 / 订单汇总 / 导出 │
└───────────────────────┬──────────────────────┘
                        │ HTTPS
┌───────────────────────▼──────────────────────┐
│                 云端API服务                   │
│ 认证 / 库存 / 订单 / PDA同步 / 上传 / 导出 / 幂等 │
└───────────────────────┬──────────────────────┘
                        │
┌───────────────────────▼──────────────────────┐
│        数据库 / 文件存储 / PDF模板 / 日志         │
└───────────────────────▲──────────────────────┘
                        │ 有WiFi时同步
┌───────────────────────┴──────────────────────┐
│                  PDA离线端                    │
│ 本地库存 / 本地订单 / 本地扫码明细 / 上传队列      │
│ 条码输入框 / 广播接收 / 实体按键 / 音效 / SQLite   │
└──────────────────────────────────────────────┘
```

### 2.2 核心设计决策

| 决策           | 说明                                                         |
| -------------- | ------------------------------------------------------------ |
| 离线优先       | 扫码、校验、存储全部在PDA本地完成                            |
| 网络仅同步     | 网络只用于拉库存、拉订单、上传明细、确认下载                 |
| 订单驱动       | PDA不能建订单，只能下载后台订单                              |
| 一订单=一车    | 一个订单对应一车货，车号、柜号在订单上                       |
| 一车多产品     | 一个订单下可包含多个产品代码，每个产品有独立计划包数         |
| 扫码广播接收   | 通过M71广播接口接收条码，不依赖厂家SDK                       |
| 校验与保存分离 | 广播后自动校验，按实体回车才保存                             |
| 按订单上传     | 以订单为单位上传该车所有产品的扫码明细                       |
| 上传幂等       | 同一订单、同一条码不能重复入库                               |
| 一期不扣库存   | 库存仍由上游维护                                             |
| 高速扫码       | 支持扫码后自动校验，回车保存，1秒2~3条                       |
| 低端PDA适配    | M71为2GB RAM + 16GB Flash + 480×800竖屏，需严格内存优化，锁定竖屏 |

## 4. 业务模型设计

### 4.1 核心概念

| 概念       | 说明                                                         |
| ---------- | ------------------------------------------------------------ |
| 库存主数据 | 由上游维护，包含条码、规格型号、品名、单包重量               |
| 发货代码   | 条码前3位，用于匹配订单下的产品明细                          |
| 产品明细   | 订单下的一个产品代码，包含发货代码、型号、品名、计划包数     |
| 订单       | 一个订单对应一车货，包含车号、柜号、多个产品明细、订单总计划包数 |
| 扫码明细   | 每扫一包生成一条记录，关联订单和产品明细                     |

### 4.2 业务关系

```text
订单（FH20260915001，车号：浙B12345，柜号：CSLU1234567）
 ├── 产品明细1：发货代码 719，型号 V17 B 9 RE102 300，品名 有光短纤，计划 60 包
 │    └── 扫码明细（多条）
 ├── 产品明细2：发货代码 720，型号 V17 B 9 RE102 300，品名 有光短纤，计划 56 包
 │    └── 扫码明细（多条）
 └── 订单总上限：116 包
```

说明：

1. 后台创建订单时，录入车号、柜号，然后添加多个产品明细行。
2. 每个产品明细行包含发货代码、型号、品名、计划包数。
3. 订单总计划包数 = 所有产品明细计划包数之和，不得超过116包。
4. PDA下载订单后，订单即为一个车次，扫码页顶部显示订单号、车号、柜号、订单已扫/计划、累计重量。
5. 扫到条码后，根据条码前3位匹配当前订单下的产品明细行，再执行库存、重复、包数上限校验。
6. 订单汇总页显示本订单总计划、总已扫、总重量，以及分产品明细汇总。

## 5. 核心状态机

### 5.1 后台订单状态

```text
新建 → 已下发PDA → 已上传完成
```

| 状态       | 触发条件              | 说明                               |
| ---------- | --------------------- | ---------------------------------- |
| 新建       | 后台创建订单成功      | PDA尚未下载                        |
| 已下发PDA  | PDA调用下载确认接口   | 后台知道PDA已下载                  |
| 已上传完成 | PDA按订单上传明细成功 | 后台写入明细，汇总实际包数和总重量 |

> “PDA已扫码待上传”仅作为PDA本地状态，后台无法实时感知。

### 5.2 PDA本地订单状态

```text
待扫码 → 待上传 → 已上传
```

| 状态   | 说明                               |
| ------ | ---------------------------------- |
| 待扫码 | 已下载，未完成或未上传             |
| 待上传 | 已扫码完成，等待有网上传           |
| 已上传 | 上传成功，本地锁定，不允许继续扫码 |

## 6. Web后台功能设计

### 6.1 库存主数据管理

#### 功能

1. 上传 `sku.txt` 批量导入。
2. 自动解析：规格型号、品名、条码、单包重量。
3. 库存列表支持按条码、发货代码、品名检索。
4. 自动维护映射：发货代码 = 条码前3位 → 型号、品名。
5. 记录导入日志：导入时间、操作人、成功数、失败数、错误文件。

#### sku.txt 解析规则建议

示例：

```text
V17 B 9 RE102 300   有光短纤      719C0000056  303
```

由于规格型号含空格，不能简单按空格拆分。建议规则：

1. 优先按 Tab 或多空格分组。
2. 用条码正则定位：`[0-9A-Z]{11}`。
3. 条码前为品名，条码后为重量。
4. 条码前剩余部分为规格型号。
5. 解析失败写入错误文件，不阻断整批导入。

> 条码格式、长度、字符集需业务最终确认。

### 6.2 订单创建

#### 订单主信息

| 字段           | 规则                                |
| -------------- | ----------------------------------- |
| 订单编号       | 系统生成，如 `FH20260915001`        |
| 车号           | 必填                                |
| 柜号           | 可空                                |
| 订单总计划包数 | 系统根据产品明细自动汇总，上限116包 |
| 订单状态       | 系统维护                            |
| 创建人         | 当前登录人                          |
| 创建时间       | 系统时间                            |

#### 订单产品明细

一个订单可添加多行产品明细：

| 字段     | 规则                         |
| -------- | ---------------------------- |
| 发货代码 | 必填，条码前3位              |
| 型号规格 | 根据发货代码自动带出，不可改 |
| 品名     | 根据发货代码自动带出，不可改 |
| 计划包数 | 必填，1~116                  |

业务规则：

1. 发货代码不存在 → 弹窗“该发货代码无匹配货品，无法创建订单”。
2. 同一发货代码对应多个型号/品名时，必须提前定义规则：唯一映射、选择或禁止创建。
3. 同一订单下所有产品明细计划包数之和不得超过116包。超过时提示“本订单总计划包数不能超过116包”。
4. 同一订单下不允许重复添加相同发货代码。
5. 订单创建成功后自动生成PDF装车单。
6. 一期建议订单创建后不可修改；如必须修改，需重新下发PDA并处理冲突。

### 6.3 订单列表

列表字段：

订单号、车号、柜号、产品代码列表、品名、订单总计划包数、实际扫入包数、订单状态、创建人、创建时间。

筛选：

订单号、车号、柜号、时间范围、订单状态。

操作：

查看详情、导出PDF、导出Excel。

### 6.4 订单汇总视图

按订单聚合展示：

| 字段         | 说明                               |
| ------------ | ---------------------------------- |
| 订单号       | 订单编号                           |
| 车号         | 运输车辆号码                       |
| 柜号         | 集装箱柜号                         |
| 总计划包数   | 本订单所有产品明细计划包数之和     |
| 总已扫包数   | 本订单所有产品明细实际扫入包数之和 |
| 总重量       | 本订单所有已扫条码重量之和         |
| 产品明细数   | 本订单包含的产品明细行数           |
| 发货代码列表 | 本订单包含的发货代码               |
| 订单状态     | 新建 / 已下发PDA / 已上传完成      |

操作：查看订单详情、导出订单汇总PDF/Excel。

### 6.5 订单详情

展示：

1. 订单基础信息：订单号、车号、柜号、订单总计划包数、订单状态。
2. 分产品汇总：发货代码、型号、品名、计划包数、已扫包数、重量。
3. 分产品出库明细：条码、单包重量、扫码时间、操作员。
4. 订单汇总：实际总包数、整车总重量。
5. 导出PDF装车单、Excel明细台账。

## 7. PDA端功能设计

### 7.1 基础同步模块

有WiFi时操作：

1. 库存同步：拉取云端库存到本地SQLite。
2. 订单同步：刷新订单列表，缓存到本地。
3. 下载订单后调用后台“下载确认”，后台订单状态变为“已下发PDA”。
4. 记录本地库存版本、同步时间、订单版本。

离线时：

1. 可查看已下载订单。
2. 可扫码校验。
3. 可暂存扫码明细。
4. 不能新建订单、不能拉新库存。

### 7.2 订单列表页

展示已下载的订单：

| 字段       | 说明                           |
| ---------- | ------------------------------ |
| 订单号     | 订单编号                       |
| 车号       | 运输车辆号码                   |
| 柜号       | 集装箱柜号                     |
| 总计划包数 | 本订单所有产品明细计划包数之和 |
| 总已扫包数 | 本订单所有产品明细已扫包数之和 |
| 订单状态   | 待扫码 / 待上传 / 已上传       |
| 操作       | 进入扫码、查看汇总、上传       |

### 7.3 扫码页（核心）

#### 页面布局（480×800竖屏）

```text
┌─────────────────────────┐
│ 订单号 FH20260915001     │
│ 车号 浙B12345            │
│ 柜号 CSLU1234567         │
│ 已扫/计划 35/116         │
│ 累计重量 10605.5kg       │
├─────────────────────────┤
│ 条码输入框               │
│ [ 719C0000056        ]   │
│ [ 校验 ]   [ 清空 ]      │
├─────────────────────────┤
│ ✅ 校验通过，请按回车保存 │
│ 或 ❌ 产品不匹配/库存不存在│
├─────────────────────────┤
│ 最近明细（只显示5~8条）   │
│ 1. 719C0000056 303kg     │
│ 2. 719C0000057 302.5kg   │
│ ...                     │
├─────────────────────────┤
│ [订单汇总] [切换] [上传]  │
└─────────────────────────┘
```

#### 顶部字段说明

| 字段      | 是否显示       | 说明                                     |
| --------- | -------------- | ---------------------------------------- |
| 订单号    | 显示           | 当前正在扫码的订单                       |
| 车号      | 显示           | 当前车次                                 |
| 柜号      | 显示           | 允许为空                                 |
| 已扫/计划 | 显示           | 当前订单已扫包数 / 当前订单总计划包数    |
| 累计重量  | 显示           | 当前订单累计重量                         |
| 发货代码  | 不显示在主区域 | 一单可能多个，放在订单汇总页或产品切换页 |

#### 操作流程

**正常扫码（高速场景）**

1. 按下PDA实体扫描键。
2. 扫码头识别条码，通过广播返回。
3. App广播接收器收到条码，填入【条码输入框】。
4. App自动执行校验（高速模式默认开启）。
5. 校验通过：播放校验通过音，提示“请按回车保存”。
6. 按下实体回车键：保存记录，刷新包数和总重量。
7. 自动清空输入框，回到等待下一次扫码。

**手动输入（条码损坏场景）**

1. 操作员点击【条码输入框】。
2. 用24键数字键盘或软键盘手动输入条码。
3. 点击【校验】按钮，或按 K1（映射 F1）触发校验。
4. 系统执行校验。
5. 校验通过：提示“校验通过，请按回车保存”。
6. 按下实体回车键：保存记录。
7. 校验失败：显示失败原因，输入框保留，允许修改后重新校验。

#### 按键职责

| 按键        | 映射   | 功能                               |
| ----------- | ------ | ---------------------------------- |
| 左/右扫描键 | 扫描键 | 触发扫码头，广播返回条码           |
| 实体回车键  | ENTER  | 校验通过后保存记录                 |
| K1          | F1     | 手动输入后触发校验                 |
| K2          | F2     | 辅助功能，如清空输入框、打开汇总页 |

#### 校验与保存分离

| 动作              | 作用                     |
| ----------------- | ------------------------ |
| 扫描键            | 只负责识别条码，广播返回 |
| 广播接收          | 条码填入输入框，自动校验 |
| 手动输入          | 用于条码损坏时补录       |
| 【校验】按钮 / F1 | 执行校验，不保存         |
| 实体回车键        | 校验通过后，保存记录     |

#### 六层校验顺序

```text
① 条码格式：去空格、转大写、长度/字符集合法
② 产品匹配：当前订单下是否存在该发货代码的产品明细
③ 库存校验：条码存在于PDA本地库存
④ 重复校验：本订单内该条码未扫过
⑤ 产品包数上限：对应产品明细未超计划包数
⑥ 订单总上限：本订单已扫包数 < 订单总计划包数
```

校验通过后，提示区显示绿色“校验通过，请按回车保存”。

#### 高速扫码兼容策略

| 模式             | 行为                                                      |
| ---------------- | --------------------------------------------------------- |
| 高速模式（默认） | 广播收到条码后自动校验；校验通过后按回车保存              |
| 手动模式         | 扫码/输入后，必须点击【校验】或按F1；校验通过后按回车保存 |

#### 附加控制

1. 支持删除本订单已扫错误条码。
2. 支持临时保存，退出页面再进入可继续。
3. 音效开关可关闭。
4. 达到产品计划包数上限后，该产品锁止。
5. 达到订单总计划包数上限后，整个订单锁止。
6. 明细列表分页或虚拟滚动，避免卡顿。

### 7.4 订单汇总页

#### 页面布局

```text
┌─────────────────────────┐
│ 订单号 FH20260915001     │
│ 车号 浙B12345            │
│ 柜号 CSLU1234567         │
│ 操作员 张三              │
│ 作业时间 08:00~09:30     │
├─────────────────────────┤
│ 订单总计划：116 包        │
│ 订单已扫：  98 包         │
│ 订单总重量：29680.5kg     │
├─────────────────────────┤
│ 分产品汇总：              │
│ 发货代码 719             │
│ 品名 有光短纤            │
│ 计划 60 / 已扫 60        │
│ 重量 18180kg             │
├─────────────────────────┤
│ 发货代码 720             │
│ 品名 有光短纤            │
│ 计划 56 / 已扫 38        │
│ 重量 11480kg             │
├─────────────────────────┤
│ [返回扫码] [上传本订单]   │
└─────────────────────────┘
```

#### 汇总维度

1. 订单维度：订单号 + 车号 + 柜号。
2. 总计划包数：本订单所有产品明细计划包数之和。
3. 总已扫包数：本订单所有产品明细已扫包数之和。
4. 总重量：本订单所有已扫条码重量之和。
5. 分产品汇总：每个产品明细对应的发货代码、品名、计划包数、已扫包数、重量。

### 7.5 产品切换

如果一单多个产品，操作员可通过【切换产品】选择当前要扫的产品。  
也可配置为系统根据条码前3位自动匹配到本订单下对应产品明细，无需手动切换。

### 7.6 订单上传模块

有WiFi时：

1. 选择“待上传”订单。
2. 点击【上传本订单数据】。
3. 上传内容：订单号、车号、柜号、操作员、设备号、作业起止时间、本订单所有产品明细及其扫码记录。
4. 上传成功：订单状态改为“已上传”，后台订单状态改为“已上传完成”。
5. 上传失败：本地数据完整保留，可重复重试。

#### 上传幂等设计

1. 每次上传生成唯一 `batch_id`。
2. 后台唯一索引：`order_no + barcode`。
3. 若同一 `batch_id` 重复提交，后台直接返回成功，不重复写。
4. 若订单已上传完成，但 `batch_id` 不同，返回冲突，提示“订单已上传，请勿重复上传”。

### 7.7 PDA辅助功能

1. 条码离线查询：扫码后查看品名、重量。
2. 本机订单管理：待扫码、待上传、已上传。
3. 本地缓存清理：只允许清理“已上传”旧订单。
4. 未上传订单禁止一键清空。
5. PDA联网时自动校时，保证 `scan_time` 可靠。

## 10. 统一校验规则

1. 所有业务校验在PDA本地执行，不依赖网络。
2. 订单只能由Web后台创建。
3. 只允许匹配本订单下对应发货代码的产品明细。
4. 同一订单内禁止重复条码。
5. 建议对未上传订单做跨订单条码占用校验，防止同一包扫入两个订单。
6. 条码统一去空格、转大写。
7. 产品计划包数上限强拦截。
8. 订单总计划包数上限116包强拦截。
9. 上传后一期不扣减库存。
10. 上传接口必须幂等。

### 17.3 关键技术实现要点

#### 17.3.1 扫码广播集成

```kotlin
private val scanReceiver = object : BroadcastReceiver() {
    override fun onReceive(context: Context, intent: Intent) {
        val barcode = intent.getStringExtra(
            "com.android.decode.intentwedge.barcode_string"
        ) ?: intent.getStringExtra(
            "com.android.decode.intentwedge.barcode_data"
        ) ?: return

        binding.etBarcode.setText(barcode)
        validateBarcode(barcode)   // 自动校验
    }
}

override fun onResume() {
    super.onResume()
    val filter = IntentFilter("com.android.decodewedge.decode_action")
    registerReceiver(scanReceiver, filter)
}

override fun onPause() {
    super.onPause()
    unregisterReceiver(scanReceiver)
}
```

#### 17.3.2 实体按键处理

| 按键   | 映射   | 功能                     |
| ------ | ------ | ------------------------ |
| 扫描键 | 扫描键 | 触发扫码头，广播返回条码 |
| 回车键 | ENTER  | 校验通过后保存记录       |
| K1     | F1     | 手动输入后触发校验       |
| K2     | F2     | 辅助功能                 |

```kotlin
override fun onKeyDown(keyCode: Int, event: KeyEvent?): Boolean {
    return when (keyCode) {
        KeyEvent.KEYCODE_ENTER -> {
            if (isValidated) saveScanRecord()
            true
        }
        KeyEvent.KEYCODE_F1 -> {
            validateBarcode(binding.etBarcode.text.toString())
            true
        }
        KeyEvent.KEYCODE_F2 -> {
            binding.etBarcode.setText("")
            true
        }
        else -> super.onKeyDown(keyCode, event)
    }
}
```

### 18.1 扫描设置建议

| 设置项       | 建议值      | 说明                                      |
| ------------ | ----------- | ----------------------------------------- |

| 高级设置密码 | 654321      | 进入扫描设置                              |

### 18.2 广播与输入框防重复处理

由于扫码时广播和输入框可能同时收到条码，需避免重复校验：

```kotlin
var isFromBroadcast = false

// 广播
scanReceiver = object : BroadcastReceiver() {
    override fun onReceive(context: Context, intent: Intent) {
        val barcode = intent.getStringExtra(
            "com.android.decode.intentwedge.barcode_string"
        ) ?: return
        isFromBroadcast = true
        binding.etBarcode.setText(barcode)
        isFromBroadcast = false
        validateBarcode(barcode)
    }
}

// 输入框监听
binding.etBarcode.doAfterTextChanged { text ->
    if (!isFromBroadcast) {
        // 手动输入，不自动校验，等点击校验按钮或按F1
    }
}
```

### 18.3 内存优化措施

| 措施                           | 说明                                  |
| ------------------------------ | ------------------------------------- |
| 列表用 RecyclerView + DiffUtil | 避免全量刷新                          |

## 19. 结论

本开发技术文档 V1.3 整合了摩比信通 M71 的实际硬件参数、广播接口参数和扫描设置信息，明确了以下核心内容：

1. **业务模型**：一个订单 = 一车货，一个订单可包含多个产品代码，订单总计划包数上限116包。
2. **扫码交互**：扫描键触发扫码头 → 广播返回条码 → 自动校验 → 回车保存；手动输入后按F1校验。
3. **技术方案**：采用原生 Kotlin + Android View + Room(WAL) + Retrofit + Coroutines + SoundPool + 广播接收，不依赖厂家 SDK。
4. **广播参数**：已获取 Action `com.android.decodewedge.decode_action` 和条码 Key `com.android.decode.intentwedge.barcode_string`。
5. **按键映射**：K1→F1（校验），K2→F2（辅助），回车键保存。
6. **扫描设置**：发送模式“输入框+广播”，结束符关闭，扫码延时关闭。
7. **设备适配**：M71为2GB RAM + 16GB Flash + 480×800竖屏，需严格内存优化，锁定竖屏。
8. **真机验证**：开发前必须完成17.4清单中的扫码、按键、性能、UI验证。
