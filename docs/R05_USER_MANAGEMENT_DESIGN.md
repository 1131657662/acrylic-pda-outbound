# R05 用户与仓库授权管理

2026-09-18，依据已确认R05路线和V2.3第7.1节实施。本子项不代表受控续期、同步、后台任务及清理已完成。

- 沿用现有角色、权限和用户仓库关联；新增`user:manage`授予现有仓库管理员。角色权限表本次只读展示，不开放任意权限编码编辑。
- 提供当前仓库内人员的真实总数/页码查询、新增、基本信息与角色/仓库授权修订、启停、密码重置和操作记录。账号创建后不可改名、不可删除。密码沿用BCrypt，新增/重置至少8字符且最多72个UTF-8字节，不强制大小写或特殊符号（2026-09-20按用户确认调整）；现有密码不自动改变。
- 目标人员全部仓库必须在管理员有效仓库范围内；目标已有角色和拟授角色的权限不能超过管理员。跨范围目标不出现在列表，直接访问不透露详情。新增及修订至少保留一个角色和当前仓库；需移除某仓库时从仍保留的授权仓库操作。
- 不允许修改自己的基本信息/角色/仓库/启停，可单独重置自己的密码；当前执行管理员始终保留管理资格。账号管理写操作用独立单行锁串行，再重新核验身份与权限，防止两个管理员互相停用或越过刚生效的撤权。服务恢复代次、CSRF、乐观版本和幂等键继续校验。
- 变更原子增加`auth_version`、注销PDA在线会话并写审计/不可变回执；Web旧会话下一请求被拒绝。角色、仓库和状态变更不更新已有订单、设备、扫码事实、离线资格或占用。离线设备无法立即收到撤权，已有事实保留，联网后按原规则重新核验。
- 含密码命令只把BCrypt验证值保存在受保护的服务端回执；幂等摘要不包含明文密码或快速密码摘要。同键不同密码不能改变已完成操作。响应/审计不返回密码及其验证值。
- Web发送前在当前标签页按管理员与仓库存原请求元数据，绝不存密码。网络结果未知时保留原请求；刷新后查询原回执，未查到时使用原请求身份补发，含密码操作须重新输入。明确拒绝可核对后解除原请求，不把网络错误当作拒绝。恢复记录损坏或存储不可写时阻止新提交。
- 核对权限边界、串仓/越权授予、自改管理资格、并发修改、旧版本、同键恢复、密码不泄露、旧Web/PDA会话失效及原订单资格/占用保留。只写本机隔离测试库，不变更公网账号和设备。
