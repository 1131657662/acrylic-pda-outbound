# M71 全部按键验证向导

日期：2026-09-16｜当前Demo：0.1.19-demo（versionCode 20；向导从0.1.8引入）｜适用：M71，Android 9，480×800 竖屏。

当前设备`22D2910042`已完成7键14次真实验证并应用，2026-09-16只读取证通过，详见[验收记录](M71_KEY_WIZARD_REPORT.md)。这台设备无需重做向导；下文保留供其他设备及需要重新校准时使用。

## 1. 回到 PDA 旁后怎么做

1. 打开 **M71 扫码验证 → 更多 → 诊断 / 设置 → 全部按键验证向导（可独立完成）**。若已经停在向导，直接点击 **开始 / 继续验证**。
2. 扫描头对着空白处，按屏幕提示的实体键。每次按下后松开，稍停再按；每个键需要两次独立按压。
3. 顺序为 **正面扫描键 → 左侧扫描键 → 右侧扫描键 → 回车 → K1 → K2 → 实体返回键**。左右以自己正对屏幕时为准。完成一次有效按下/松开后自动显示下一次提示，不用在聊天里逐键回复。
4. 按错时点击 **重测本键**；已进入下一键时用 **上一个键** 回退。中途可以点 **稍后继续**，再次打开会恢复已保存进度。没有答题倒计时。
5. 完成 14 次后，核对自己实际按的位置，点击 **位置正确，确认并应用**。显示“配置已应用”后，点底部按钮返回扫码页，新配置立即生效。

应用能检查事件是否一致、是否重复分配，不能识别键帽写的是 K1 还是 K2；最后的位置确认仍需操作者核对。若某键始终没有反应，保留页面和日志，记录键的位置；不要改按其他键冒充通过。

## 2. 交互与配置规则

| 项目 | 行为 |
| --- | --- |
| 验证次数 | 7 个键各两次，共 14 个完整 DOWN/UP 周期；长按 repeat 不推进 |
| 独立按压 | 松开后至少间隔 300ms；过快连击提示稍停，不计入第二次 |
| 一致性 | 同一位置的两次 keyCode、scanCode、source 必须一致；同一物理标识不能占两个位置 |
| 应用映射 | Enter 保存人工候选；K1 校验手输；K2 辅助；返回键返回。三个扫描键仅识别并记录，触发扫描头仍交给厂家服务 |
| 原配置 | 完整验证且明确应用之前保持原有效配置；旧 SharedPreferences 的 K1/K2 是兼容回退，不等于本轮完整验证通过 |
| 重启 | 保留已经耐久保存的完整按压；未完成 DOWN/UP 的半次按压作废。回到前台后点击继续 |
| 数据隔离 | 向导不调用出库引擎；收到条码只写诊断事件，不校验库存、不保存包、不播放出库成功音 |
| 事件取证 | 保存 keyCode、scanCode、source、deviceId、action、repeatCount、eventTime、downTime；普通 ADB 虚拟按键不能完成验证 |
| 设备差异 | 每台设备单独验证，绑定当前 Android 构建指纹；deviceId 只留证据，不参与长期匹配，避免重启后 ID 改变造成失效 |
| 保存失败 | 停止推进并显示保存错误，保留旧配置；退出再打开核对耐久进度，不宣称已通过 |

用户已选 B 模式：完整扫码广播校验成功自动保存；手工输入仍先 K1/F1 校验，再按 Enter 或屏幕大保存按钮。向导不修改这一业务规则，也不修改厂家全局键位或开启扫码头自动回车。

## 3. 进度、配置与报告

- 私有进度：`files/key-calibration/draft.json`；私有有效配置：`files/key-calibration/active.json`。采用 `AtomicFile` 写入及备份恢复。
- 诊断报告：应用外部文件目录 `evidence/key-tests/`。采集报告为 `COLLECTED`，操作者确认后的导出副本为 `APPLIED`；每个文件名含独立 UUID，保留历史。
- `active.json` 是生效依据，必须包含完整 14 次、`status=APPLIED`、`operatorConfirmedLabels=true` 和匹配的设备指纹。报告副本输出失败会记 `KEY_REPORT_COPY_FAILED`，不撤销已经成功保存的有效配置。
- 全量按键事件位于现有 `events-*.ndjson`，向导内条码事件名为 `KEY_WIZARD_BARCODE_IGNORED`。日志中同时记录当时提示位置及是否开始采集。
- `tools/capture_database.py` 从本版起一并备份存在的私有 `files` 目录，涵盖按键配置。外部诊断报告仍按原取证流程另行拉取。保留应用数据升级，不卸载或清空。

## 4. 验收边界

自动测试验证状态机、暂停恢复、配置耐久性和按键路由。ADB 触屏仅检查页面，ADB 虚拟按键仅用于验证拒绝逻辑，不会把占位键码写为真机已确认配置。

完成本向导表示“事件与操作者确认的位置匹配”，还需在扫码页验证三个扫描键触发真实广播、B 模式自动保存、手输校验和错误处理。高速实际扫描、真实掉电、声学测量及其他 Demo 门槛见 [DEMO_PLAN](DEMO_PLAN.md) 和 [B 模式记录](M71_B_MODE_REPORT.md)。本向导完成不等于完整 Demo 验收通过。
