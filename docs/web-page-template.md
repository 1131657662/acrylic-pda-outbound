# Web 页面与交互规范

日期：2026-09-17。状态：公共工作台、订单列表和详情已按用户授权实施并完成本机验证，见[交付记录](WEB_UI_FOUNDATION_DELIVERY.md)；PC手工出库实施与验证见[专项交付记录](PC_MANUAL_OUTBOUND_GUIDE.md)，其他页面的完整迁移仍待实施。尺寸为CSS像素基准，业务含义以[状态与恢复语义](status-semantics.md)为准。

## 1. 信息架构与侧边栏

导航建议固定为以下顺序，只显示当前用户有权限的入口，无子项的分组不显示：

| 分组 | 导航名称 | 现有对应 |
| --- | --- | --- |
| 装车作业 | 装车订单 | `/orders`，列表内筛选待领取、已领取、待处理、已完成等真实状态 |
| 库存管理 | 库存查询 | `/inventory/bales`；库存版本记录作为本页标签 |
| 库存管理 | 库存导入 | `/inventory/imports`；导入核对进入独立详情 |
| 库存管理 | 发货代码 | `/inventory/mappings`；页面标题“发货代码与产品” |
| 系统管理 | 人员与权限 | `/users`；角色、仓库授权、启停、密码重置和操作记录，要求`user:manage` |
| 系统管理 | 出库规则 | `/policies`；对应现有“出库政策”，只改展示命名 |
| 系统管理 | PDA 设备 | `/devices` |

侧栏顶部显示产品名“纤序”和包件扫描框标识，不放宣传语。导航项图标加文字，高40px、间距4px；选中项有浅色底、强调文字与左侧标记，同时设置语义上的当前页面。详情与编辑页仍高亮所属菜单。

默认宽224px，折叠宽64px；折叠图标位于固定位置，折叠项提供聚焦/悬停名称。菜单自身必要时滚动，顶部品牌和底部账户之外的低频入口不挤压业务项。账户操作统一放顶栏，侧栏不重复放退出按钮。

不新增空的统计首页、独立审批中心或“即将上线”菜单。登录后优先恢复有权限的站内目标页，否则进入装车订单；无订单权限时进入第一个允许的页面。无仓库或无任何业务权限时给出明确状态，不循环跳转登录页。

## 2. 顶栏与页面标题

桌面顶栏高56px，白底加下边线。左侧为折叠导航及真实面包屑，右侧依次为仓库选择、测试环境标识、后台连接状态、账户菜单。只展示实际存在的环境信息；服务器时钟和技术版本进入连接/账户详情，不持续占用顶栏。

仓库名称一直可辨认；超长名称允许选择器扩展或提供完整查看。连接状态表示当前浏览器与后台，不代表其他PDA在线。正常连接用小图标及可访问名称，异常时扩展为“后台连接中断”等短文字；悬浮/点击详情显示最近成功请求时间。

页面头放在内容区：左侧标题、必要对象标识与状态，右侧一个主要动作及少量次要动作。列表标题只用业务名称；详情标题示例“装车订单 FH202609170001”，车号紧邻显示；编辑标题明确“新建装车订单”或“修订订单”。不重复放英语标题、长说明和多个大号指标。

详情返回使用统一箭头图标按钮并提供可访问名称，放在标题左侧。面包屑表示层级，返回表示回到进入前的业务上下文，两者不混同。

## 3. 页高、背景与滚动

| 区域 | 桌面规则 |
| --- | --- |
| 应用外层 | 以动态视口高度为基准，有兼容回退；不写死768/900px |
| 侧栏 | 占满视口高，必要时独立滚动 |
| 顶栏 | 固定56px，不随内容消失 |
| 工作区 | 宽度占剩余空间，四边24px；主体最小宽度允许收缩 |
| 列表页 | 纵向分为页头、筛选栏、结果表格、分页；表格占剩余高度 |
| 列表滚动 | 表体一个纵向滚动区，表头和分页保持可见；不用外层长页再套表格长页 |
| 详情/表单 | 工作区一个纵向滚动区，主要摘要/操作按需吸顶；正文不再层层滚动 |

桌面视口高不足640px或放大后可用高度不足时，列表切换为页面滚动，保留最小可操作表格区域；不能让多个固定栏把表体挤到只剩一行。弹窗打开时锁定背景滚动，弹窗正文独立滚动并保留操作区。

表格与详情以白色平铺工作区承载，灰色背景只用于区分外围。页面内部用细线、标题和留白分区，不给每个区块加圆角边框。表格可以横向滚动，但横向滚动不能传播到整个页面；不会同时固定太多列把中间内容挤没。

列表和数据详情允许使用可用宽度，超宽屏工作区最大约1800px；编辑表单最大960px并保持阅读起点与页头一致。短页面不填装饰内容、不强拉行高来占满屏幕。

## 4. 响应式与窄屏

| 视口宽度 | 布局 |
| --- | --- |
| >=1280px | 默认完整侧栏，可手动折叠 |
| 1024-1279px | 默认折叠侧栏，工作区边距20px |
| 768-1023px | 抽屉式导航，工作区边距16px，顶栏不挤压内容 |
| <768px | 导航按钮始终可见；顶栏必要时两行，工作区边距12px，筛选和表单单列 |

窄屏菜单展开后有遮罩、关闭按钮及焦点管理，选中入口后关闭。当前CSS中直接隐藏菜单的行为需要替换。字号不随视口连续缩放。

订单/设备等实体列表在窄屏使用紧凑行：标识、状态、两项关键字段和详情入口；更多字段在详情中完整可见。密集库存数据可保留局部横向表格并固定必要标识；不强迫所有业务变成大卡片。审批/编辑在窄屏仍显示完整核对内容，危险操作不因空间不足省略确认。

## 5. 标准列表页

结构顺序：页面标题与主要动作 -> 筛选区 -> 当前结果说明/选择状态 -> 表格 -> 分页。搜索与重置入口固定，次要条件可展开，已生效条件可见；“输入中的条件”与“已查询条件”分开。

- 默认主筛选不超过一行：订单页为订单号/车号、状态、查询、重置；库存为条码、发货代码、库存状态。日期等后续条件放更多筛选，不先添加后端不支持的搜索能力。
- 搜索范围明确。后端只支持完整匹配时，字段写“完整订单号或车号”；需要模糊查找时同步接口和性能设计，不伪装支持。
- 输入不逐字触发整表请求；Enter/查询生效。改变生效条件、排序、仓库或每页条数后回第一页。加载时保留区域尺寸，忽略旧查询迟到响应。
- 日期筛选注明时区，起止范围一致。客户端统一以 Asia/Shanghai 展示业务时间，未知时间显示“暂无记录”，不显示当前时间充当数据时间。
- 查询失败保留明确标记的上次结果，注明“刷新失败，以下为上次结果”；旧结果上的写操作须重新核验。首次失败显示失败状态与重试，不显示零条。

### 5.1 分页与查询契约

订单、库存、设备、导入记录和发货代码采用完整分页作为目标：默认20条，可选20/50/100；显示真实总条数、上一页、页码、下一页和跳页。总数以当前筛选且当前权限可见的结果计算，不取全库数量。页码和页大小做上下限校验，排序有唯一稳定次序。

当前多数接口只有 nextCursor/hasMore，没有 total 和任意跳页能力。必须先落实服务端配套，不能前端拉完数据再分页。实现时对普通管理列表评估页码分页与索引；对大型审计/导入明细保留游标分页，提供前后翻页、当前范围和已访问位置，不显示虚假的总页数。

数据变化后允许提示“结果已更新”并重新查询；若当前页已超出最后页，回退至有效页并提示。批量处理需要固定对象集合，不能依赖动态页码代表对象身份。精确总数若成本过高，需要明确调整该列表展示方式，不能悄悄用估计数冒充。

20条不等于强制一屏显示20行。桌面表体可滚动，分页始终可达；不靠压小字号和行高硬塞一屏。

### 5.2 表格细则

默认表头40px、单行数据行44px；带必要副信息的行56-64px，超长内容换行时允许增高。宽度变化不改变行内按钮大小。

| 内容 | 展示规则 |
| --- | --- |
| 订单号/条码 | 保留完整身份；订单号可点击，条码保留前导零；提供单值复制并反馈 |
| 数量/重量 | 右对齐、等宽数字、千分位；净重标kg，精度按原值，不显示无依据的0 |
| 状态 | 中文标签、图标/颜色；长状态允许两行，不截掉关键限制 |
| 操作 | 常用动作最多1-2项，其余进入有名称的菜单；危险动作分组 |
| 长备注/品名 | 可截断预览，聚焦/点击能看全；审批关键原因不只靠悬浮 |
| 排序 | 仅展示服务端真正支持的排序项；不可只排序当前页 |
| 列宽 | 给标识与数值稳定宽度，描述列弹性；用户自定义列和拖宽后置 |

多选仅在存在已实现的批量动作时出现。当前页全选与全部筛选结果全选必须显式区分；切换筛选/仓库后清空选择。批量审批和作废不随表格改造自动开放。

## 6. 导航、返回与上下文

仓库、已生效筛选、排序、页大小、页码/可恢复游标保存在合适的路由状态中；滚动和焦点按账号/仓库/列表上下文保存，不将密码、凭据、完整审批正文放URL。详情标签可编码进路由，浏览器前进/后退、刷新和复制站内链接均有确定结果。

从列表进入详情后返回恢复条件、位置与来源行焦点。直接打开详情时回其所属列表；来源已失效时提示并使用有效列表，不盲目调用浏览器后退导致离开系统。不引入整套多标签工作台。

仓库切换保留仍适用的通用搜索条件，移除旧仓库专属对象、游标、选择和缓存。详情属于旧仓库时，先核对授权再决定返回列表或显式切回；无权限时不透露另一仓库的对象内容。编辑未保存先提示，已发送且结果未知的请求按原仓库恢复，不能随切换改写。

## 7. 详情、表单与确认模板

订单详情顶部为订单/车号、真实状态、关键数量及主要动作；下方标签为“产品计划”“装车记录”“异常处理”“操作记录”。仅在确有阻断事项时，摘要区域显示持续提示与入口；不会把整个错误清单铺满首屏。用户主动切换标签后不被自动刷新切走。

计划数量、后台已收到的有效数量、后台确认出库数量分别标注。未收到PDA提交时显示“尚未收到装车记录”，不显示0包，也不显示虚构的实时进度。详细统计来自同一口径，不能把历史轮次重复累加。

订单详情增加条件化的“PC 手工出库/继续PC录入”入口，进入本单专属作业页。与PDA领取互斥，跨本单发货代码的模糊候选逐包确认；布局和业务要求见[PC手工出库设计](PC_MANUAL_OUTBOUND_DESIGN.md)。该入口为新需求，不能在后端支持完成前作为可用动作上线。

新建/修订订单采用独立表单页，分基础信息、产品计划、备注/原因三组。宽屏基础信息两列，产品计划全宽；窄屏单列。页底操作区与正文留出空间，主按钮写实际动作“保存草稿”或“保存并重新发布”。更改计划与发布不能混成一个含糊的“确定”。

输入框有持续标签，提示文字只给格式示例；必填项一致标识。输入错误保留原值、就地提示，提交时定位首个错误并给摘要。库存/产品不存在时提供有权限的处理入口和返回路径。多产品编辑支持移除未保存行的轻量撤销，不能用此撤销业务上已提交的事实。

发送前可取消编辑；发送后保留原内容和请求身份。结果未知时提供原请求核对入口，不允许修改后重复发送。浏览器关闭恢复能力须按实际存储明确实现；不把“离开提示”当作已持久保存，也不将完整敏感草稿无期限写入本地存储。

简短原因录入/危险确认使用约480-560px弹窗，最大宽度受视口边距约束；轻量身份/版本查看用约480-640px抽屉。弹窗包含对象、影响、必要原因和明确动作，主次按钮位置固定。关键确认不使用默认已勾选项，不采用无语义的“确定”“是”。

| 页面 | 目标结构与关键行为 |
| --- | --- |
| 登录 | 简洁产品名、环境、账号密码、可见性按钮、登录；移除大幅口号区；失败不泄露账号是否存在，登录后回有权限目标；次要入口“下载 PDA 应用”已完成本机验证 |
| 装车订单 | 统一列表、完整分页、真实状态筛选；计划与已收到记录不混淆，详情返回恢复上下文 |
| 订单详情 | 摘要与四类标签；版本、发布历史放操作记录，召回/续作/实物处置集中于异常处理 |
| PC手工出库（新增） | 左侧查询/候选与本单记录标签，右侧逐产品进度，底部所选包核对；确认后由后台计包，结单另核对 |
| 审批 | 首屏显示车号、逐产品差额、短装原因、冲突与当前批次；允许批准的条件明确，明细可核对；批准仍由后台复核 |

| 库存查询 | 默认库存列表，历史版本另一个标签；明确上游在库、系统扣账、冻结，避免合成一个误导性的“可用库存” |
| 库存导入 | 页面列上传入口与导入记录；选记录进入独立核对页，按预检问题、差异、代码对应、发布结果组织；不把详情接在列表底部 |
| 发货代码 | 代码/型号/品名/状态列表，修订有原因；历史在抽屉或详情，返回不滚过整页 |
| 出库规则 | 当前规则与生效范围先展示，版本历史另标签；固定规则只读，自动扣库存有明确保存/生效确认 |
| PDA设备 | 设备编号/名称/启停/最近联网；短码登记接入后作为主入口，公钥UUID进入身份详情；停用影响按真实离线边界说明；工具栏“下载 PDA 应用”独立标签页保留原列表 |
| 下载 PDA 应用（本机验证完成） | 无需登录的 `/pda-download`；产品和环境、已发布版本、大小、Android要求、下载按钮、二维码/短地址和简短安装步骤；复用App可信发布清单，失败/无发布/停发不可误导下载；部署和设备待验见[交付记录](PDA_DOWNLOAD_GUIDE.md) |
| 停止与恢复装车 | 申请、原机停止证据、主管核对、原机恢复各阶段区分；每阶段只突出当前可执行动作，历史证据可查 |

导入预检通过不等于发布成功，候选库存数量不代表已预留库存；单个标签“通过”不能跨越这些业务阶段。相关发布校验仍沿用既有规则。

操作时间线默认最新在上，显示时间、人员、动作、关键变化、必要原因；更改前后值可展开。类型筛选须有后台支持，长记录分页。扫码业务明细仍按已确认扫码序号呈现与导出。

### 8.1 PDA首次安装页

“下载 PDA 应用”属于R05更新配套，详见[应用更新方案第9节](PDA_APP_UPDATE_DESIGN.md)。登录页和设备管理页指向同一固定下载页，不新增一级菜单；直达/刷新不要求登录，设备管理本身的权限不变。PC可展示二维码和可复制短地址，PDA优先展示版本与下载按钮；二维码指向固定页面，不指向易过期的某一版APK。

沿用现有颜色、字号、按钮及状态规范，简洁单列、平铺分区；长版本号换行，窄屏和大字体下按钮与安装步骤可达。网络失败、尚无发布、暂停分发及不兼容分别反馈并给出适用动作，下载完成不宣称系统安装成功。返回设备管理保留列表上下文，新设备首次安装和已有设备覆盖升级分别说明与验证；不要求用户卸载、清空资料或搬运长版本链接。

## 9. 反馈与异常页面

空状态区分“还没有记录”“筛选无结果”“没有权限”“后台不可达”。分别提供有权限的新建入口、清除筛选、返回有权页面、重试。移除通用空白插画与大段功能介绍。

刷新不清空输入，不自动滚回页头，不弹重复成功通知。多个字段错误集中到表单内；阻断问题在对象附近持续显示。成功轻提示约3-5秒，但关键保存/审批结果留在页面；不要要求用户依靠一闪而过的消息确认出库。

会话过期停止新的受保护写请求，保留可恢复上下文并要求重新登录，恢复后重新核对身份/权限/版本。403、404、后台错误有独立清楚的说明与安全返回，不将业务错误全部跳到登录页。

## 10. 实施定位

优先涉及 [工作台](../web/src/WorkspaceLayout.vue)、[全局样式](../web/src/style.css)、[路由](../web/src/router.ts)、[订单列表](../web/src/orders/OrdersPage.vue)和[订单详情](../web/src/orders/OrderDetailPage.vue)，再迁移各模块。分页依赖对应服务端查询和契约变更；页面设计不能直接视为接口已经具备能力。

每迁移一个完整流程，核对正常/空/加载/失败/未授权/数据变化状态与返回路径。最终验收矩阵见[设计总规范](design-system.md#8-验收清单)。
