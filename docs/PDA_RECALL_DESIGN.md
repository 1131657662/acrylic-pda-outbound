# 受控召回、恢复包与停止证明

2026-09-17，承接用户“继续开发”授权，按V2.3 §6.4、6.5、6.7、6.8实现续作所需的停止/恢复前置链路。使用现有Java/JDBC、Vue和Android/Room工程。只在本机隔离库及指定模拟器验证，不操作M71、Demo或生产，不commit/push。

本轮交付：Web申请召回 → 原PDA联网发现后持久停扫 → 操作员核对未保存输入并冻结恢复包 → 上传完整原输入/扫码/本单审计及本设备连续审计覆盖 → 服务端验证、保留包占用 → PDA收到并验签停止证明 → 零有效包由主管填写实物核验凭据后作废。有已装包的订单保持待召回及占用，下一步才能办理续作/卸货/换机，不因“已停止”变成待领取。

1. 后台申请绑定当前订单版本、原授权与恢复代次，专用order:recall权限，原键重试。同仓库锁及scope→order→request串行化；与提交竞争只有一个方向成立。提交先成功则召回拒绝；召回先到则旧提交最多转待复核，审批也不能出库。
2. PDA联网刷新或打开作业时查询原授权召回；收到后先暂停接收并在Room记RECALL_PENDING。断网不能即时撤销已签离线资格，界面明确以实际收到为准。停止状态跨重启保留；新保存/撤销/普通结单均按本地状态拦截。
3. 操作员必须查看未决/失败列表并确认实物：所有尚未保存输入转有原因的BUSINESS_REJECTED，原确认意图、序号、原人原机均保留；失败逐条写确认事件。待落盘队列须归零。已保存/撤销事实不变；冻结恢复包与RECALL_STOPPED事件同一Room事务落盘。零包也可形成恢复包，不冒充出库提交。
4. 恢复包拥有独立packageId/规范SHA，上传仅接收证据。完整本机审计从0连续补齐至停止事件，逐条校验原授权/设备/操作员和已知审计摘要；本单输入序号连续、完整终态、保存窗口、原固定快照及旧提交中不可变行均核对。固定正文32MiB以内，采用原字节分段读取避免CursorWindow限制；同ID异文拒绝。恢复接收不推进设备通用审计清理检查点。
5. 停止确认必须引用已耐久接收的包、摘要、高水位及审计覆盖。安全包进入RECOVERY_RESERVED；冲突留在恢复详情，不覆盖其他单占用或出库周期。确认事务撤销原作业资格、签发不可变停止证明，并写审计/outbox；订单仍RECALL_PENDING。响应丢失只重试原包/原停止确认。证明固定aud=acrylic-pda-recall，绑定完整响应，验签后本地RECALLED。
6. 主管CANCEL_EMPTY要求order:recall、order:cancel、已确认停止、有效包数0、无任何原订单包占用、固定包摘要及实物核验原因。单事务终结未成功批次并保存签名作废结果，订单CANCELLED。已成功单只能更正；有包/缺恢复证据/旧版本/跨仓库均拒绝，不提供直接解锁或转派。

本轮不颁发续作票据、不开放保留包减包/换机/重派，不将既有设备全量审计转成持续同步游标。设计保留原停止恢复数据，后续REOPEN_WORK必须在此基础上继承来源、高水位和逐包处置证据。未准备完、损坏或缺审计的授权保留待召回，须故障恢复流程，不能以“本机未显示订单”当成零包证明。
