# 项目文档地图与零记忆接手顺序

本文是静态导航，不保存版本号、测试数量、当前分支或当前完成度。易变化事实只读 [开发看板](ORCHESTRATION_STATUS.md) 的 `CURRENT_STATE_START/END` 与生成事实块。

## 文档职责

| 文件或目录 | 主要读者 | 应放内容 | 不应放内容 |
| --- | --- | --- | --- |
| `AGENTS.md` | 每次接手的开发助手 | 长期协作、写权、证据保全、发布边界和清理规则 | 当前 SHA、当前测试数、某轮进度、一次性接续提示 |
| `docs/GIT_WORKFLOW.md` | 开发者/审阅者 | 分支、提交、推送、产物和发布的长期规则 | 当前分支、当前版本、某次运行结论 |
| `docs/ORCHESTRATION_STATUS.md` | 接手者、审阅者 | 唯一当前状态、写权、实际环境、失败/未验和下一动作；事实块由脚本生成 | 大段历史复述、完整测试日志、未核实的旧状态 |
| `docs/DEVELOPMENT_ROADMAP.md` | 产品/技术负责人 | 用户确认的范围、路线、依赖和完成口径 | 当前跑数、当前 SHA、一次性任务日志 |
| `docs/REMAINING_DEVELOPMENT_PLAN.md` | 执行者/验收设计者 | 剩余事项的退出标准、证据要求、边界和可复制接续提示 | 运行中的当前结论、重复历史报告、版本四元组 |
| `docs/DEVELOPMENT_PROGRESS.md` | 审阅者/验收索引使用者 | 每项验收报告的短索引、输入/限制/证据入口 | 逐轮日志、完整报告正文、当前状态副本 |
| `docs/BUSINESS_POLICY_R06.md`、`BUSINESS_POLICY_R07.md`、`OPEN_QUESTIONS.md` | 产品/权限/审阅者 | 已确认的业务政策和范围决定 | “已实现/已验收”的替代结论，当前测试跑数 |
| `docs/history/<专项报告>.md` | 需要复核证据的读者 | 一次验收、失败、接管或清理的输入、命令、原始路径、哈希、结论和限制 | 覆盖看板当前状态的指令；改写旧事实来表示新状态 |
| `docs/history/README.md` | 定向查历史的读者 | 历史报告的可检索索引，按日期/主题链接 | 当前状态入口、活跃写权、下一动作 |
| `docs/history/CONTINUE_*.md`、handoff 页 | 中断后复核者 | 当时的接续背景、边界、证据入口和未验项 | 自动恢复旧角色、旧 PID、旧服务或已取消范围 |
| `README.md` | 首次浏览者 | 产品静态简介、目录和安全边界入口 | 当前版本、当前测试数、当前“下一步” |
| `.local/` | 当前写者/独立消费者 | 原始输入、运行日志、数据库/文件快照、逐文件清单和摘要 | 提交到 Git 的密钥、密码、真实业务数据；删除唯一证据 |

## 零记忆接手顺序

1. 读 `AGENTS.md`、本地图、`docs/GIT_WORKFLOW.md` 和看板的当前区；只把看板生成事实块当作版本事实来源。
2. 重新核对 `branch`、`HEAD`、实际远端和 `git ls-remote`，记录暂存、tracked/untracked 清单与逐文件 SHA。继承脏状态默认受保护，不能用 reset、checkout 或批量清理“整理”。
3. 核对实际写者、重型进程、监听、数据库身份、ADB/模拟器、Keystore 和 C/D/E 余量；旧交接页中的 PID、端口和设备只作线索。
4. 确认唯一写者后运行 `tools/version_facts.ps1 -Write` 和 `-Check`；若事实源或当前区不一致，先保存旧区再修正。
5. 从看板“下一动作”选一个独立子项，再读路线、剩余计划、对应政策和看板链接的最新专项报告；不要从历史索引顶部猜当前任务。
6. 新工作先在 `.local/<任务根>/` 建立输入 manifest、命令、环境、退出码和输出哈希。失败原件、原资料、原身份、最终 APK 和唯一证据不清理。
7. 只有在本批证据完成后，才更新看板当前区、进度索引和历史索引；治理动作单独记录，不计 D/O/U 或第 8 节闸门。

## 工作树收敛规则

- tracked 修改和未跟踪源码/测试先按“继承 WIP”保全；只有在能从输入 SHA、命令和报告证明同一批次时，才允许拆分提交。
- `docs/history/` 报告和 `.local/` 证据先按“历史/唯一证据”保全；可清理的大文件只能在保留文字摘要、输入 SHA、命令、结果和哈希后，依用户已授权的持续清理规则处理。
- 当前控制文档只做小范围修订；替换看板当前区前归档旧区。不要把旧报告搬回当前区，也不要把当前区复制到每个历史页。
- 未能从磁盘证明归属的文件标记为“归属未判定”，等待明确的批次边界或用户决策；不因文件名、日期或目录猜测删除或提交。
