# R06 验收方案

日期：2026-09-18。**本文件全部为待实施、待执行场景；本轮只完成设计和文档核对，没有运行 R06 业务测试、生成 APK、连接设备或演示真实闭环。** 起点既有测试结果只能证明对应历史范围，不计作下表通过。

## 1. 环境、数据与取证

- 使用隔离MySQL、合成库存和测试身份；不得清理原开发库、真实PDA任务/密钥或会话1产物。真实规模样本若获授权使用，只在本机受控路径，不提交到Git。
- 角色组合至少包括：仅创建/扫码、仅正常确认、仅短装审批、确认+审批、仅关联、处置/续作主管、无权限人员、其他仓库人员；异常审批另有独立人员。设备A/B和PC分别使用可辨认的测试身份。
- 合成产品例如003、571；混扫计划003×2、571×1，三包净重分别300.5kg、15.5kg、302.125kg，按003→571→003接收，应为3包、618125g。15.5不因重量大小被阻断；前导零、字母及原始重量文本均保留。
- 准备当前完整快照、旧但完整快照、部分包、错误签名/哈希、已出库/隔离/占用/已批准新周期条码、空只读正式缓存、有活动正式/PC作业目标。
- 测试组合包含：断网前/请求发送后/服务端提交后丢响应；进程杀死与设备重启分别注入；Room事务失败和服务器事务失败分别验证。网络代理/故障注入只用于隔离环境。

每例记录：用例ID、代码提交、APK/versionCode/Room版本、服务端/契约/Flyway版本、环境、设备/账号角色代号、前置数据、步骤与注入点、预期、实际、失败原因、修复提交及复测。不得仅截绿色页面作为成功证据。

证据分类：`L`=本机DB/原字节摘要/序号/guard/审计；`S`=服务端scope/current/占用/账据/审计；`N`=请求键/来源/摘要/响应与签名；`U`=界面、声音、返回及实际操作；`M`=迁移前后非空资料比对。导出证据去除token/密钥/真实客户业务信息。
