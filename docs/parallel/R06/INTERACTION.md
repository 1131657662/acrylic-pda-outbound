# R06 交互设计与页面核对

日期：2026-09-18。**以下是设计线框和行为规范，不是已运行界面、原型演示或真实闭环。** 业务条件以 [专项设计](DESIGN.md) 为准；基础样式直接沿用 [PDA 页面规范](../../pda-page-template.md) 与 [状态语义](../../status-semantics.md)。

## 1. 导航与布局约束

主路径：订单「本机任务」→ 临时建单 → 车辆及原因 → 多产品计划 → 开工核对 → 扫码装车 → 订单明细 → 结单核对 → 冻结/上传 → 待确认或待主管处理 → 查询原结果 → 回执核验成功。每个临时页面保留“临时”文字、车号、临时号末段；正式化后可查看完整双号，扫码时不因映射变化丢失原上下文。

M71 按 480×800 px、density240、约320×533dp设计；扣除真实系统栏。标题约48dp，正文16sp、辅助14sp、标题20sp，触控≥48dp、主按钮56dp、间距≥8dp，白/浅灰背景及现有语义资源。先让最近记录、次级汇总让出空间，不缩小当前条码、错误或主动作。480×600、200%字体及键盘态均须验证，不将这些尺寸当作已有 R06 实测结果。

每页一个主要任务，不新建图表首页，不在扫码页增加全局底部导航。复杂建单/关联使用独立页；简单确认才用对话框。无深层弹窗套弹窗、无常驻技术流程说明。业务动作文本纵向排布，避免窄屏并列长按钮。

## 2. 页面定义

### P01 订单入口与本机任务

- 保留“本机任务 / 待领取”两段，不增加第三套任务库。本机段工具区放有文字的“临时建单”，设置保留在标题工具入口；权限/资格不足时显示可解释的禁用原因或准备入口。
- 无创建权限隐藏创建命令，但本人既有临时任务保留查询/恢复入口，不能因当前权限撤回让事实从列表消失。访问仍受身份和仓库范围保护。
- 有创建权无完整资格时进入 P02；有效资格且资料完整可直接 P03。存在另一单未决输入时先定位原任务处理，不能借新建临时单切走。
- 任务行：车号、临时标识/号、当前真实阶段、有效/计划、一个当前动作。草稿→继续建单；扫码→继续装车；冻结→上传；未知→核对结果；待审→查看处理；成功→查看回执。
- 正式化/关联后同一本机任务不重复出现两行；详情显示对应正式号。不把来源 LINKED 当作完成。按状态真实分页/按需加载，默认20条；保留筛选、位置和返回焦点。

### P02 临时作业资料准备

内容依次为仓库/当前人员与设备、准备状态、库存版本与最近核对时间、离线期限、下一动作。首次主要动作“联网准备资料”；已有有效资料时“开始临时建单”。技术摘要/签名进入详情，不要求操作员搬运公钥。

| 情况 | 显示与操作 |
| --- | --- |
| 首次无资格或无缓存 | “请联网准备临时装车资料”；开始按钮禁用 |
| 下载/校验 | “下载资料 / 校验资料 / 保存资料”；仅有真实字节总量时用百分比 |
| 中断 | 保留旧完整资料；“重试本次准备”；不能半包开始 |
| 激活完成、ack未确认 | “本机资料已准备，下载确认待重试”；保留原ack；有效资格下可按设计开工 |
| 到期/设备重启/时钟异常 | “联网续期”或“联网核对时间”，不混成网络故障 |
| 签名不符/仓库或恢复代次变化 | 持续阻断，保留资料；提供核对说明，不提供清库按钮 |

离开下载页不谎称完成，返回继续同包。刷新时旧单引用的快照不变。正常离线且可作业使用中性提示；红色仅用于真实阻断。

### P03 车辆与临时建单原因

表单持续可见标签：车号（必填，40字）、柜号（可空，40字）、临时建单原因（必填，500字）、货堆/区域备注（可空，500字）。车号不作为唯一键；同车既有本机任务提示核对并可打开，用户确认不同车次后仍可另建。字段错误就地显示并定位首错，原输入保留。

点击“下一步：产品计划”前把草稿头/ID耐久保存，双击沿用同一ID；未写成功不显示“已保存”。返回保留草稿并显示其保存状态；显式“放弃草稿”只适用于无采集/占用/提交的草稿，留建单/放弃审计。离开未落盘编辑时提示保存或放弃未保存修改，不能声称每次键入都已保存。

键盘不自动提交建单；车号可用文字键盘，原因多行。系统返回先收键盘，再遵守页面返回规则。

### P04 多产品计划

从本资格固定产品映射选择，支持代码/型号/品名检索；离线本机查询，不能向旧单混入刚发布的产品。列表按代码稳定排序、按需读取；已选择产品提示“已加入”，不能重复建行。

每行显示发货代码、型号/品名、计划包数（必填正整数）及移除入口。添加不同产品保留原行和输入焦点；计划汇总只读，移除未开始行可轻量撤销。当前缓存可用数是参考并标明截点，不表示已预留；小于计划提示核对，不自动截小计划。库存中不存在/映射不可用的产品不能开扫。

主动作“核对并开始装车”进入 P05，不直接打开摄像头/模拟扫描。0、小数、负数、重复代码、空产品及溢出阻断；最多1000行等技术范围明确报错，不写“每车最多116包”。键盘弹出时当前计划输入及校验反馈保持可见。

### P05 开工核对

显示车号/柜号、建单原因、逐产品计划及合计、仓库、资料版本与有效期限。固定提示：“临时装车记录须上传并确认出库后才可离场。”主动作“保存并开始装车”；提交事务成功后进入 P06。返回 P03/P04 可以改草稿，重复点击和进程重开返回同一作业。

开工时重新核对资格、存储和跨单未决输入，不能以打开表单时的状态放行。按钮完成后计划冻结；有输入后的改计划入口只显示受控处理说明，不就地修改已采集事实。

### P06 扫码装车

复用 B 模式语义与现有实体键配置：广播自动校验/保存、手输 F1/K1 校验、Enter或等价大按钮确认；扫描键交厂家解码，软键盘 Enter 不借用实体确认权限。临时单不增加逐包确认、不允许自动切产品或静默修改计划。

页面从上到下：对象栏→当前包/错误→有效/计划与净重→当前产品及最多3行预览/最近记录→手输与明细。无不可点击的大“自动保存”按钮。进入明细、结单或对话框暂停自动作业，恢复时继续已经耐久接收的原队列；暂停期间不接受的新扫描须有明确反馈，不能把未记录的输入声称已保留或已保存。

| 输入/状态 | 反馈与允许动作 |
| --- | --- |
| 成功耐久保存 | 完整条码、产品、“已保存到本机”，有效数与重量刷新，PASS |
| 手输已校验 | “等待确认保存”；只确认当前capture；未确认不计包 |
| 重复/错产品/超量/缺库存 | 当前错误持续可见，“本包未保存”；FAIL；后续输入计入待处理，不覆盖错误 |
| 存储结果不确定 | 停止并核对原输入；区分耐久接收与可能未记录部分，不能全部宣称已保存 |
| 某产品满额 | “数量已达计划”；该产品新增拒绝，其他产品可继续 |
| 到期/已知撤权/恢复阻断 | 停止新增，不清输入或guard；详情可查，按条件联网续期/恢复 |

正常离线状态注明资料核对时间，无持续红色报警。手输时隐藏最近记录、减少产品预览；当前错误、输入及动作保持键盘上方。字号放大优先减少预览，不裁切错误。返回有未决输入时说明保留和不能切单限制；同一个错误确认不能兼作下一包确认。

### P07 订单明细与结单核对

明细页显示稳定计划顺序的产品汇总，展开按原 `orderScanSeq` 查看，提供真实字段的条码/代码搜索和按需分页。历史保存、撤销/卸货/隔离、当前有效装车分别标注；不因视觉排序改号。

“核对结单”是明确入口。进入后暂停扫码，显示车号与各产品“计划 / 有效 / 差额”、总数及净重、未决输入数、原记录异常。短装的每个产品填写原因；可“同一原因应用到所选短装产品”，但冻结保存逐行对应，不能只留一条无范围备注。

未决输入/错误未处理、总数0、汇总不一致、存储不足或恢复阻断时不能冻结。总数0显示“不能形成出库；返回装车或办理受控结束”，已有扫码后全卸下不能走空草稿放弃。

主动作“确认结单并冻结”，确认框显示车号、有效/计划、短装项及“冻结后停止扫码”。联网正常也不自动把冻结和上传合成一次不透明动作。冻结成功转 P08；冻结过程中进程中断后先读原冻结记录，不能生成第二submissionId。

### P08 上传、审批与结果恢复

首屏始终保留车号、临时号/正式号、关键汇总、明确是否允许离场及当前唯一主动作。技术批次/摘要放详情；用户不必理解幂等键。

| 真实阶段 | 主文案 | 主动作/次动作 |
| --- | --- | --- |
| 已冻结未排队 | “已结单，尚未上传 · 不可离场” | 上传本单；断网可“加入上传队列” |
| 已排队 | “等待上传条件 · 不可离场” | 查看本单；可显式立即上传，沿用当前手动网络策略 |
| 正在传输 | “正在上传本单资料 · 不可离场” | 查看进度；无伪造百分比，不重复建任务 |
| 结果未知 | “提交结果待核对 · 不可离场” | 核对原提交结果；查询未找到才重传原正文 |
| 已接收待正常确认 | “资料已接收，待授权人员确认 · 不可离场” | 有权原机人员可“核对并确认出库”；其他人“查询处理结果” |
| 短装/冲突/重复待审 | “待主管处理：具体原因 · 不可离场” | 查看差额/冲突；查询结果；不得反复上传代替审批 |
| 已退回/取消 | “批次已终结，记录和占用保留 · 不可离场” | 查看处置/恢复阶段；经票据才能回扫码 |
| 映射已关联 | “已关联正式订单，尚待确认 · 不可离场” | 核对正式号/新目标；查询当前批次，不新建正式提交 |
| 云端成功但本机未核验/未落盘 | “后台结果待核验 · 暂不可离场” | 重试核验/保存原回执，不重做业务 |
| 验签、汇总、映射及保存全部成功 | “后台已确认出库，可按现场流程离场” | 查看回执；返回本机任务 |

自动上传仅对用户已排队的冻结批次生效，WorkManager 同批次唯一任务；默认 Wi-Fi，现有手动上传可用网络行为不改变。多次失败转人工接手；401/403、业务冲突不无限循环。批准待办 30 分钟提醒仅是提醒，不改变状态。

正常单即时确认的操作说明在首次上传确认处明确：“具备确认权限且全部校验通过时，后台将确认出库；否则等待处理。”这是已确认 Q02 的可预期行为。用户关闭确认说明返回核对时尚未发请求；一旦发送则只能恢复原命令。

PDA 的单独确认页显示当前冻结摘要对应的逐产品实绩、车号及所有待决事项；只有 NORMAL 确认权不能看到可执行的短装批准按钮。需要多个批准时显示各自真实完成/未完成状态，不用一个“审批通过”总标签误导。

成功回执同时显示确认时间、正式号、包数/净重、是否自动扣账。关闭扣账仍可确认出库并保留全局防重，不写“未扣账所以可再扫”。历史回执附核验时间；R07 后续调整另显示当前净结果。

## 4. Web 临时审核与受控关联

不另起平行后台平台。在装车订单列表增加“临时来源/待确认”条件与可见来源字段，服务端真实分页；详情沿用“产品计划 / 装车记录 / 异常处理 / 操作记录”，新增临时原因、双号映射与待决条件。

### W01 审批核对

首屏为车号、原设备/操作者、最近收到时间、逐产品差额和原因、当前批次及待决项。扫描明细按原序分页，不整表拉取。本人异常不能自批时持续显示原因；只有正常确认权时明确还缺哪项审批。

按钮按实际权限与条件展示“确认临时出库”“批准短装”“退回处理”。确认框显示对象、数量、待决条件及动作影响；普通 Enter 不默认执行审批。退回必填原因并明确“记录与占用保留”。若只批准一个条件，成功反馈写“短装已批准，仍待临时确认”，不能写“车辆可离场”。

写请求发送前持久保存原命令（账号/仓库/来源/摘要/版本/键），存储失败不发送。刷新恢复同一命令；完全关闭浏览器后从服务端当前决定和命令回执恢复，不宣称现有 sessionStorage 已具备跨浏览器关闭保障。新 R06 必须落实服务端按命令 ID 查询回执/决定历史的恢复能力。

### W02 疑似重复核对

显示候选为什么出现：同仓车号、时间来源/差、产品重叠、计划/实际及作业状态。候选分“可核对关联”与“已有作业，仅可查看处理”。无匹配时说明查询范围，不能承诺绝对不存在重复单。

操作为“查看两单”“确认不是同一车次（必填依据）”“关联此正式单”。两单对比包含车柜号、产品/计划、快照/政策兼容、领取/PC活动/提交状态。关联确认显示“目标将承接原临时批次，原事实不变；旧目标审批失效，仍须核对出库”。

若目标被领取或版本变化，保留原临时记录及人工说明，显示“目标状态已变化，请重新核对”，不能静默选下一候选。关联成功显示双号、关联人/时间、当前待决条件；不直接变绿放行。关联命令未知则核对原命令，不能选择另一个目标重发。

### W03 退回后的处置

阶段依次展示：原批次终态→原机停止及完整恢复证据→逐包实物核验→主管批准→原机激活续作或受控结束→处置实际生效结果。RETAIN/RELEASE/QUARANTINE 每包明确选择，无默认“全部释放”。

保留原包补扫时回同一来源的新轮次；减包后保留原事实和处置引用；全部卸下走专项结束证明，无出库结果。原机失联、另一单已成功占同包或需返库再出时显示 R07 所需核对条件，保留阻断，不展示尚未实现的“强制修复”按钮。

## 5. 跨页面恢复规则

| 操作/故障 | 恢复结果 |
| --- | --- |
| 旋转、进程杀死、返回再进 | 从本机持久状态恢复草稿、原输入、冻结和回执；不从按钮的临时状态猜业务结果 |
| 设备重启且无网络 | 可查看原资料，暂停新增等待联网校时；自动任务不伪装已发送 |
| 登录/权限变化 | 页面重验访问范围，不让新账号接管旧人事实；原任务保留给有权恢复 |
| 列表刷新/云端映射晚到 | 事务更新别名/当前状态，旧响应不盖掉高版本，不改原正文或本机guard |
| 关联目标本机已有作业 | 保留两边，停止安装映射并对账；不能清掉任一事实以消除唯一键冲突 |
| 更新 APK | 检查/安装受 R05 安全点控制；临时草稿、事实、冻结、签名映射及恢复阻断须纳入迁移保护，未测不能声称可升级 |

本轮没有做可用性实测。后续现场需让操作者独立完成临时建单、混扫、短装及未知结果辨认，记录误触/找不到入口/把“已接收”当放行等问题，按 [验收方案](ACCEPTANCE.md) 留证。
