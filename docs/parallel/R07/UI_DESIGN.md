# Web审批与PDA交接交互设计

状态：页面设计提案及文字线框，未实现/未做浏览器或M71实测。沿用[总规范](../../design-system.md)、[Web模板](../../web-page-template.md)、[PDA模板](../../pda-page-template.md)、[状态语义](../../status-semantics.md)，不新增独立审批中心、装饰首页或全局批量审批。

## 1. 信息架构和视觉规则

Web从“装车订单 → 订单详情”进入“换机交接”或“出库更正”；从“库存查询 → 差异记录”进入对账详情。是否显示动作由当前渠道、对象状态及权限决定，服务端仍逐请求检查。订单COMPLETED保留原订单状态，附“已更正/已全部调整”而非改为未出库。

未正式化TEMP从R06“临时作业详情”进入同一交接详情，显示临时号、原创建机/人员及“尚未生成正式单”；不要求用户先建正式单或填写虚构订单号。恢复证据不足时显示缺项和补证据入口；完成来源登记不显示“已出库”。有正式目标后同时显示原临时来源与当前目标，映射变化提示“关联目标已变化，请重新核对交接方案”。

使用既有主题的background.surface/canvas、text.primary/secondary、action.primary、warning/danger/success/information语义；不另写相近颜色。Web正文14px、主要控件36px、桌面留白24px，窄屏按模板缩减；PDA正文16sp、标题20sp、主按钮56dp、其他触控≥48dp、按钮间距≥8dp。数字与单位清晰，条码前导零保留，重量精确显示有效小数。

默认列表20条，服务端真实分页。只有游标时显示前后翻页及当前范围，不显示虚假页数。返回保存账号/仓库/筛选/页位置/来源行焦点，切仓后旧响应不能覆盖新对象。

## 2. Web换机交接详情

首屏呈现车号/订单号、仓库、原设备/人员→接收设备/人员、案件阶段和阻断摘要。四项证据分别显示：原机停止、原提交结果、资料完整、实物核验；每项写明来源和最近核验时间，无在线证据只显示“最近联系”。

```text
装车订单 / 订单详情 / 换机交接                         [返回订单]
车号 合成车A     原机 PDA-A / 原人员甲 → PDA-B / 接收人乙
状态：等待原机停止    已申请停止不代表原机已经收到

停止证明：未收到       原提交：待核对
资料完整：尚未核验     实物核验：未完成
阻断：需原机上传停止记录及核对原提交结果

[处理进度] [逐包清单] [证据与历史]
当前阶段说明和已有证据
主操作：[核对原提交结果]         次操作：[查看停止申请]
```

阶段设计：

| 阶段/页面 | 主要信息与用户动作 | 成功后的明确去向 |
| --- | --- | --- |
| 申请 | 固定原机/原人/订单；选择本仓合格接收机及本人；原因必填；正常/原机故障明确选择 | 进入案件详情“等待停止/故障核验”，不跳成新机任务完成 |
| 等原机 | 最近收到记录时间、未决输入与原提交状态；未知数量显示尚未收到 | 原机实际上传后刷新证据阶段；超时仅提示联系现场 |
| 故障核验 | 设备回收/停止使用、隔离范围/位置、归档覆盖、未知区间和结果证据独立表单 | 完整且核验通过才进入审核；不完整显示“无法恢复原顺序，不能续扫” |
| 主管审核 | 原/新身份、原结果终态、逐来源覆盖、保留集合、已批准处置、起始序号完整性；冲突固定置顶 | 主动作“批准交接准备”；确认窗说明尚未激活、不释放包 |
| 已批准 | 固定清单版本、接收机资料阶段、指定接收人 | 等本人准备/激活；有权限可受控撤回，原因必填 |
| 已激活 | 新机/人员、新资格有效期、激活证据；服务器激活和新机本地确认分别显示 | “查看接收端任务”；只读历史可追溯，不能普通撤回 |

逐包清单按原orderScanSeq分页，列出序号、条码、产品、原重量、原设备/人员、保留/既有处置、凭据。来源摘要可展开，不能把C继承的A/B记录全部显示成C扫描。新减包要求进入实物处置，不在交接审批中增加无凭据“删除一行”。

审批简短确认窗使用480～560px基准，显示对象、双方、有效包数、原结果及影响。关键证据复杂编辑使用详情页，不叠套弹窗。普通Enter不触发危险审批，无默认勾选“全部核实”。

## 3. PDA原机页面

入口在本机任务对应行“停止装车核对”；进入后暂停普通扫码。保持车号/设备身份、主要阻断和一个当前动作可见。允许看原明细，不能切换另一单执行未决确认。

```text
‹ 停止装车核对 · 合成车A
本机 PDA-A · 原人员甲
已停止接收新扫码

尚需核对输入 2 条          [查看并逐项核对]
已保存记录 38 包           [查看原记录]
原提交结果：待核对         [核对原提交结果]

当前主动作：[核对未处理输入]
```

顺序为核对未决输入 → 确认核对结果并固定记录 → 上传停止记录 → 核验停止回执 → 等待主管。已保存和可能未记录的输入明确分开；存储异常不说“全部已保存”。回执已验签且Room保存成功才显示“本机停止已确认”。到期或账号失效显示相应限制，保留上传证据和受控代传说明，不提供清库/重绑。

## 4. PDA接收端页面

登录后的本机任务中显示“待接收交接”，与普通待领取分开。仅服务端返回当前人员/本机有权接收的案件；无对应交接时不给“强制接管”按钮。环境/仓库/设备身份沿用现有登记和设置页面。

```text
‹ 接收装车任务 · 合成车A
来源 PDA-A / 原人员甲 → 本机 PDA-B / 乙
状态：已批准，等待下载资料

原车保留 38 包    新增扫码从核验的下一号开始
资料：尚未下载   原提交：已终结，记录保留
实物核对：尚未确认

[下载交接资料]
```

| 接收阶段 | 显示和主动作 | 禁止事项 |
| --- | --- | --- |
| 待批准 | “主管尚未批准”；刷新案件 | 不出现继续扫码 |
| 下载中 | 已知字节才有百分比，未知仅显示阶段；失败可“继续下载” | 不把部分文件写成准备完成 |
| 核验失败 | 具体缺文件/资料不符/本机占用冲突及处理入口 | 不清本机旧订单，不重新计算摘要接受坏包 |
| 本机已准备 | 显示保留数量、原人原机/已知来源、实物位置；逐产品/包明细可查 | 不让未确认候选出现在可保存队列 |
| 可确认接收 | 本人核对实物和对象后“确认接收并启用”；确认说明将取得本单资格 | 不以检查框绕过后台缺口/旧结果未知 |
| 激活结果未知 | 固定“接收结果待核对”；主动作“查询原接收结果” | 不再次领取/换案件/选另一人 |
| 已激活且本地耐久 | “本机已接收，可继续装车”；进入原单扫码 | 不显示“后台已出库”；历史包不再播放PASS |
| 资格到期/恢复代次变化 | “扫码授权已到期”或“后台恢复后需核对原记录” | 不靠重登录或重新下载清单延长/解阻断 |
| 资料要求更新版本 | 可受控暂停时显示“保留当前资料，暂停交接并更新”，列出实际兼容/安装阻断 | 不要求完成无法识别的清单才能更新，不清数据；未知激活先查结果，更新后不自动启用 |

低高度及200%字体时：优先收起历史摘要/来源详情，保留对象、阻断、主动作；内容必要时纵向滚动，不压小关键字号、不让两个长按钮挤一行。软键盘打开按insets调整，返回先收键盘；交接页扫码广播不能计包。重启/旋转/进后台恢复同一暂存和原请求，不自动执行“确认接收”。

## 5. Web出库更正和库存对账

更正详情首屏同时显示三列结果，明确每列口径：

```text
订单 合成O1 · 原出库日 2026-09-18 · 后台已确认出库 / 已更正
原确认(v1)          累计调整             当前净结果(v3)
100包 / 30000kg     -1包 / -300kg         99包 / 29700kg
[原始明细] [调整凭据] [当前有效明细] [账务与库存]
```

申请页先选“真实退货/错误出库/重量更正/非实物更正”，每类只显示必要字段。退货与错误出库明确不同实物证明；重量更正显示原重量、当前有效重量和目标重量，差额由后台计算。显示预计结果、是否存在实际可反向账务、是否会增周期、恢复后仍有的隔离原因。不能笼统写“批准后恢复库存”。

审批页按固定文档/结果版本展示逐产品差额、逐包证据、实际账务贡献及最终状态预览。`ledgerEntriesCreated=0`显示“本次不产生账务流水”；只有核验该dispatch确无实际扣账时才补充“未由本系统扣账，无需反向”，不能仅凭流水数推断原扣账状态或显示“已补回库存1包”。批准主动作按类型命名，例如“批准退货更正”。被并发更正抢先后留原申请，突出新旧结果差异并引导重新核对，禁止自动套新版本。

库存对账页以同一条码四列比较“上游声明 / 当前实物与占用 / 出库事实 / 系统账务”，缺值与0区分。差异处理选项按真实情形提供：接受缺码但保留不可用、转退货更正、显式账务补记、核验隔离解除、保留待核对。主操作是提交明确方案/批准方案；不提供直接切换“在库”“已扣账”的编辑开关。

审计时间线展示申请人、核验人、批准人、发生/生效时间、版本及凭据号，默认最新在上、分页；原扫描明细仍按原序号。附件/技术详情按权限访问，UUID/epoch/摘要不占普通现场页面首屏。

## 6. 错误恢复交互

| 用户看到的情况 | 保留的事实 | 当前动作/去向 |
| --- | --- | --- |
| 请求尚未发送，存储失败 | 未发送编辑内容尽量保留，明确不能保证已保存 | 修复空间/本地存储后再发；不显示结果未知为成功 |
| 网络断开/请求超时 | 原请求ID、原正文、原代次及任务对象 | 查询原动作结果；明确未收到确认 |
| 登录过期 | 交接/更正原请求和本地证据 | 重新登录后先核对原对象权限/版本；不自动接管 |
| 403/目标不属于本机 | 原资料，限制敏感内容显示 | 返回有权限的列表；主管处理指定目标，不共享账号 |
| 签名/摘要不一致 | 原包及不匹配详情 | 停在不可操作阶段，重新下载相同文件或受控恢复 |
| 原结果已成功 | 原成功回执 | 查看已出库结果/更正入口，不续扫 |
| 高水位/审计缺失 | 已知范围和明确未知段 | 补原记录或故障恢复，主按钮无激活选项 |
| 服务端激活成功，本地失败 | 原激活请求、已下载暂存 | 恢复同一回执并重试本地事务；禁止签第二资格 |
| 库存/周期/版本变化 | 原审批正文、旧前后值 | 展示具体变更，重新核对，不能静默重试批准 |
| 后台恢复对账 | 原代次、guard、输入/回执/正文 | R09案件入口；新基线/重新登录不出现解锁按钮 |

阻断使用danger及明确文字，等待/未知用warning，成功只针对已确认阶段。离线但有效授权的正常作业仍按既有规则，不把“网络未连接”显示成账号损坏。页面不暗示存在未实现的即时联系主管、全局证据导出或自动恢复按钮。

## 7. 布局与现场验证安排

Web核对1366×768、1440×900、1920×1080、1024×768、390×844和桌面200%缩放；低高度改页面滚动，审批影响/主动作仍可达。窄屏复杂明细可局部横滚，但对象标识和阻断不丢失。

PDA核对M71 Android9，480×800/density240（约320×533dp）、实际系统栏/软键盘、480×600低高度、200%字体、长名称/原因、0/1/300+包、断网和存储不足。保留FLAG_SECURE和身份；模拟器/截图检查、真机可读性、强光、实体键/扫描广播及真实断电分别记录，不能互相代替。详细可判定场景见[验收方案](ACCEPTANCE_PLAN.md)。
