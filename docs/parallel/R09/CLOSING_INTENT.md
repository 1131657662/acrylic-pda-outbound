# 关闭意图与写者接纳

2026-09-26，接续 V39 关闭投影。本文定义下一子项，不是完成报告；不恢复旧调度或另建工作树。

当前问题：控制命令在获取写者独占锁失败时只返回 WRITERS_ACTIVE。当前记录没有改变，随后启动的写者仍可取得共享租约；持续新写入会阻止排空。

完成标准：

1. 控制推进在协调锁内先验证原命令、CAS 和合法阶段，再耐久追加关闭意图，之后尝试写者独占锁。已持租约的事务允许完成，新租约必须在打开 DB 前拒绝。无效命令不能制造停止意图。
2. 意图保存原 commandId、规范原正文摘要、原 revision/hash 和目标阶段，不重新签发命令或换 epoch。冲突 ID/正文不能替换；原键重试在最后写者退出后完成原历史/指针提交。
3. 意图及失败原件永久保留。以对应已提交记录证明意图完成，不删除意图或凭 mtime 清理。进程在意图落盘、历史追加、指针暂存/提交各点死亡后均保持关闭，按同一原件恢复。
4. Python 原件由 Java 独立消费；坏意图、少文件、错安装、跳号、已完成意图与原记录不符必须拒绝。已有旧控制原件不重写，旧消费者看到新格式/目录应失败关闭。
5. 当批验证真实持锁进程、Java 新租约拒绝、已接纳事务提交/回滚后原命令推进，以及独立非空 MySQL/真实 HTTP 必要兼容。所有能力仍按原边界关闭；该子项不能代替 API/Session/Worker/Flyway 全入口接线、NORMAL 初始化或受控释放。

采用按目标 revision 命名的不可变 intent 记录，放在独立受控目录中。完成状态由已有不可变控制历史推导，不增加可回退的“完成”布尔指针。锁序仍为 coordinator → writer lease → DB。

新建写者协议升级到version2，要求原意图目录及摘要头成对存在；version1原件继续只读，禁止自动升级后启写。摘要头只标识已耐久接纳的最新原意图，不决定完成；提交完成仍由原控制历史证明。先追加意图、再原子推进摘要头，任何半写状态均拒绝新租约；Python只允许对应原命令修复摘要头。删除单个已知原件必须被摘要头/连续链发现；攻击者同时回退全套控制原件与可信外锚点不属于本机hash链能独立证明的范围。
