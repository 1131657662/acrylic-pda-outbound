## 3. 无人值守执行规则

- 默认单助手、单写者，不创建新聊天或子代理。同一文件、数据库、构建输出或部署目标不可同时有多个写者；发现实际在途执行先保护现场，不能凭旧代理 ID 判断写权。
- 技术方案、实现拆分、测试夹具、故障定位和修复由执行者自主选择。优先沿现有模块、协议和已确认政策推进；不建立平行命令系统，不做无关重构或额外平台。
- 已确认业务规则直接执行，不重新询问。需人工确认的开发/未定业务选择已获用户授权采用最佳方案；先查既有依据，在现有规则内自主裁定、记录默认及理由后直接开发和隔离验证，不等待二次确认。第3.1节覆盖既有P01–P03、候选排除、取消、锚点和分批接线等选择；历史“提案获批后才能开发”的等待条款由本次授权替代。
- 每个子项按“范围/退出标准 → 最小实现 → 定向验证 → 自审修复 → 受影响回归 → 证据/文档 → 明确路径提交推送”交付。设计和读取、编译、单测、真实 HTTP、数据库、APK、模拟器、真机分别计证。
- 按已有授权提交并推送 `codex/development`；需要隔离开发时沿 Git 工作流使用短期分支。只提交本批明确路径，保存继承改动；禁止 `git add .` 混入他人改动、密钥、原资料或产物。
- 保持生产默认开关、七类决定的生产 handler/POST/放行/证据写入/关闭能力及 `localDeletionAllowed=false` 边界。隔离测试可沿已有授权显式启用测试入口，不能把测试通过转换成生产权限或改写真实设备事实。
- 不合 `main`、不打标签/Release、不部署、不接原库/现网、不使用正式签名、不清理既有证据；不重试或变换包装绕过历史自动审批阻断。新授权只能来自用户后续明确指令。
- 预算、会话结束、磁盘余量、工具限制或某项受阻均不等于完成。先保存断点；仍有可独立工作就继续，无可推进工作时按目标工具的既定规则如实登记阻断，不能用 `complete` 结束未完成目标。

### 3.2 重复失败、诊断上限与暂缓队列

1. 为每个失败记录D/O/U子项、阶段、首个根因/错误码/失败断言与关键栈、环境类别、输入SHA/命令/退出码、证据路径。去除端口/随机ID/耗时后形成可比较失败指纹；改文件名、换库号、重启会话不自动重置计数。
2. 第一次先定性产品/夹具/运行器/环境，保存现场；只允许有明确假设的检查或修复再复验。无新假设的原样重跑最多一次，不能为了达到3次机械跑满。
3. **同子项同根因连续3次且无新增可用证据，立即记为暂缓并执行下一独立项**；包括继承的适用失败，不能每次“继续”重新从1计数。不同根因才分开计数，成功的正向/预期拒绝测试不计失败。
4. 单个未收敛问题的主动诊断默认最多60分钟；到限且无明确即将验证的修复，就保存代码/日志/数据库和最小复现，暂缓该问题。预先约定的正常构建/测试时长不按诊断超时处理，不盲杀数据库；需认证停机并核对监听后才切重型任务。
5. 暂缓项登记最小重新入队条件、确实受阻的直接依赖和当前可做替代范围。只跳过受它阻断的部分，不跳整步；产品正向没通不能靠全拒绝满足标准，测试收集/运行器失败不能算功能通过。
6. 每个阶段收口重看暂缓列表，只在出现新源码修复、材料/环境变化或明确不同方案时重入队；没有新依据不再触发同指纹循环。全局运行环境故障优先作一次隔离修复，不能对每个业务项重复同样启动失败。
7. 所有独立项都已遍历后，若仍有暂缓/现场项，交付阶段成果与未完成清单，按目标工具规则报告真实状态；不将目标标为complete，不恢复用户未要求的旧任务/自动化。无人值守轮次结束不等于整个十步完成。

## 6. 特别容易漏掉的边界

- **续作扫码开发与生产放行分开**：要完成受控开发链的正向验证，又必须保留生产默认关闭和签名能力边界。若现有协议不能合法表达测试中的激活，先收敛契约/依据；不得为了通过而忽略 `CONTINUATION_BLOCKED`、借 FORMAL assignment 或伪造允许扫描的票据。
- **候选排除/取消释放**：按本次授权的P04/P05实施，不再等待方案裁定。普通有权正常确认可空理由；短装原因、冲突、候选排除、取消释放不能相互替代，真实库存/实物/资格事实不足不由自主决定补造。
- **主管审批与库存对账**：以源码和后续签名 HTTP 证据为准，不恢复早期“无主管角色/未编码”的结论；岗位映射已经有依据的直接复用。差异案件状态流转不等于业务核对、审批或账务补记完成。
- **故障订单撤回与设备停用**：停用撤销设备在线会话，订单撤回另行使旧领取/旧提交失效并允许重发；不能只改设备状态就视为订单已释放。坏机撤回不要求STOP/ACK，后台权限不扩大到已成功出库、更正、TEMP卸货/取消、库存解隔离或生产开放；旧机离线不能即时收到停用变化，旧上传必须被服务端拒绝。
- **断网取数与撤回重发分开**：O02只读导出不强迫停止/冻结、不依赖新资格或可信当前时间、不改确认/占用。O03是原设备事实经PC中转，保留原ID和身份，不把扫描进度交给新机；旧领取已撤回/重发时不得再记账。O04裸sku不能证明库存/授权/跨机唯一占用，身份采用本次授权P03默认，真实凭据和证明仍须取得。
- **原资料/旧 BCD/既有失败边界**：从历史索引定位原证据和实际文件，使用保全的隔离副本补验。找不到原物料则记缺失和取回条件，不用新 fixture 冒充原样本、原身份或原故障通过。
- **清理与恢复**：没有完整引用核对、可取回证明或合法删除资格，不能删除。D16 是必做开发项；仅保留 `localDeletionAllowed=false`、生成备份文件或列待办，均不能满足它的实现退出标准。

## 7. 验证与证据要求

每个新子项先写最小验收设计，覆盖实际业务成功路径与必要的权限/身份/仓库、原键/异文、并发、重启/丢响应、事务最后写入失败和存量兼容反例；不为凑数量写镜像测试。已有证据仅在对应代码、输入与依赖未受影响时复用，说明理由。

必需证据包括：

| 类型 | 必须证明什么 |
| --- | --- |
| 定向/单元/Room | 核心行为、耐久状态、真实事务及失败回滚；标明合成身份、生成签名和 fixture，不能称原设备证明 |
| 真实 MySQL/HTTP | 实际路由、会话/签名/权限、非空迁移、提交/记账、回执及数据库回滚。MockMvc、DTO或服务层测试不能替代真实 HTTP |
| 客户端与服务端组合 | 同一隔离输入下 Android 消费实际响应、持久原键、恢复、后续输入/提交/验签与服务端事实一致；分别列测试消费者与生产产品入口的覆盖 |
| Web/PDA 与文件 | 实际页面状态/返回/错误恢复可用；APK构建/lint、Web类型/构建及浏览器场景分别留证；导出逐值/顺序/字体/页布局回读与可见核对 |
| 离线及UI子项 | 对O01–O05/U01–U04建立逐行实现/证据映射；完全断网、快照并发、导出文件失败、解析冲突、防公式/精度、中转幂等/旧资格拒绝、回执消费与布局/队列恢复在可隔离输入上实测，真机通道另列，不以静态报告代替 |
| 备份/恢复 | 备份生成后实际恢复，核全量事实和文件引用；数据库 dump/哈希/binlog、认证停机与进程/监听核对，失败库和原日志保留 |
| 最终整合输入 | 服务端普通测试、专项 IT、Android/Room/迁移、Web/浏览器、R08渲染/文件、R09脚本与组合故障覆盖实际受影响范围；源码/依赖/输出哈希可追溯 |

服务端普通 `test` 排除 IT；`test` 通过不得写成集成测试通过。先建立 IT 类与退出标准的覆盖映射，逐类或独立批次准备一次性隔离环境；修夹具/运行器造成的不可解释级联后再取得有效结果。不要求把所有一次性 IT 强塞到一个共享数据库，也不允许用少数抽样代替必需业务覆盖。

每次运行使用新的证据目录与所需一次性数据库编号，核对所有工作树分配；一名数据库写者、一个重型 Gradle 构建。构建不得覆盖运行进程的 JAR/APK或其他批次报告。失败与跳过分别记录：skip 是未执行，不能计为通过；复制旧 XML 不计当次执行。

证据记录必须包含输入 SHA/分支/树、改动清单或哈希、执行命令及退出码、原日志/XML、报告计数、HTTP/文件/数据库证据、作者自审或独立消费者的身份、失败归因及最终结果。独立工具消费者不自动等于独立人员审查。

在最终候选输入上运行一次可解释的整合回归；运行后若再改影响行为的代码、配置、契约或迁移，对受影响范围复验。纯断点/链接修正不用机械重跑全部业务测试，但必须说明输入关系。

6. 看板和验收索引可追溯到最终交付；每项外部待验都有范围、原因、所需条件和验收方式，且仅属于第9节允许的现场/生产事项。
