# PDA 扫码确认交互方案比较

日期：2026-09-16。状态：**用户已明确选择 B，Demo 0.1.6 已实现，正在独立验收**。本次决策取代旧版逐包回车要求，已同步 V2.3 与 Q16；不代表自动保存已通过完整真机验收。

## 1. 现场反馈与现有证据

- 操作者通常使用设备正面的扫描按钮，小回车键不便逐包按下。
- 操作者希望比较“扫码后自动保存，手工输入仍人工确认”等方案；可在共用底层自动测试和修复完成后再决定。
- 现有日志/设备附录记录了标记为中央扫描键的 keyCode 293、scanCode 317；两侧为 293/310、293/311。中央键有事件证据，但尚未由操作者按其常用正面键专门完成位置复核、短按/长按及连续扫描验收。
- 0.1.5 及之前为每包实体 Enter 保存；0.1.6 执行 B。真实广播、手输、失败处理与软件测试不能混为同一种输入。
- 当前 0.1.5 四档软件测试数据一致；1 包/秒启动阶段延迟未达标。不能把已有结果转写为自动保存模式通过。

## 2. 三个可选方案

| 方案 | 正常扫码操作 | 手工输入 | 优点 | 代价与适用条件 |
| --- | --- | --- | --- | --- |
| A：换大确认键 | 正面/侧面键扫描，再按经实测顺手的 K1/K2 或大屏幕保存按钮 | 保留校验后人工确认 | 保留逐包核对机会，接近当前流程 | 每包仍需两个动作；K 键是否顺手待试，原校验/辅助入口需重新安排 |
| B：扫码校验通过自动保存（建议优先试用） | 按扫描键，应用收到完整条码并校验通过后自动保存 | 完整输入 → F1 校验 → 人工回车或等价大保存按钮 | 每包减少一次按键，更适合戴手套和连续装车 | 扫描一个合法但尚未装车的包也会计入；适用于“扫描即确认该包装入本车”的流程，错误必须明确暂停并处理 |
| C：按订单固定选择自动/人工模式 | 开工前选 B 或 A，该次作业固定使用 | 两种模式均保留手输人工确认 | 兼容快速装车与需逐包核对的作业 | 增加培训和测试组合；页面须明显显示模式，有未决输入时禁止切换，权限及默认模式另确认 |

方案 B 是当前现场反馈下的初步推荐。若经常先扫条码查询、之后才决定是否装车，方案 A 更合适。只有确实需要两种作业方式时再选 C。

## 3. 自动保存的建议实现边界

以下为已确认 B 的实现边界，0.1.6 Demo 按此实现；正式系统待完整 Demo 验收后开发。

1. **应用直接保存，不模拟点击回车。**厂家保持仅广播、关闭键盘注入及自动结束回车。扫描键只负责触发识别；收到完整厂家广播后，应用对该条输入执行受控保存，不依赖当前焦点。
2. **规则和事务仍完整执行。**格式、库存、产品、周期、重复、计划及授权等校验照常执行，最终事务再次核对。保存成功后才增加数量并播放 PASS；本地保存不等于云端确认出库，车辆放行规则不变。
3. **输入来源明确区分。**真实扫描采用自动确认策略，手输仍需 F1 校验及人工确认；审计保存原始字符串、来源、作业模式和确认方式。不得把自动确认标记为物理 Enter。
4. **每条广播有自己的持久身份。**按原接收序号入队、绑定订单和出库周期，保留扫码先后顺序。相同条码重复广播不得重复计数，不能以按时间粗略去重而丢弃不同包。
5. **错误处理明确。**重复、错产品、超计划、授权或存储错误不计包、不响 PASS。遇错暂停后续自动保存，后到输入保留可核对的处理状态；未持久接收的输入必须明确提示，不能静默丢弃。由操作者确认错误后再按明确规则恢复，后续成功音不能盖过待处理错误。
6. **误扫可纠正。**本地误计包须核实实物、填写原因并留下撤销凭据；已经云端确认的记录走正式更正流程。合法条码的误装车选择无法仅靠六层校验识别。
7. **恢复不能偷换确认方式。**自动模式对该条输入的保存意图须持久记录；重启按同一输入身份核对并最多完成一次。旧人工模式的未确认候选不能因切换模式而自动保存。

不建议使用“扫描头自动补一个 Enter”：广播与按键可能先后错位，且手输框、菜单或错误弹窗可能接到这个 Enter。也不优先推荐让同一个正面键根据状态在扫描/保存之间切换；这需要额外验证厂家触发行为，容易让操作者不清楚这次按下会执行哪种动作。

- 可以继续处理共用的数据库耐久、启动延迟、恢复、顺序和历史容量问题；这些问题不会因少按一次回车自然消失。
- 用户已于 2026-09-16 回复“选B”；不再等待方案选择。
- 用户选定后，同步修订 V2.3 的扫码交互/状态转换/审计说明、DEMO_PLAN、测试指南及业务规则清单，再实现并验收对应路径。
- 若选 B/C，新增“完整广播接收→耐久保存”的端到端指标；旧“回车→保存”指标仍保留给人工模式，不能挪用或省略实际保存耗时。
- 真实光学、正面扫描键、1～4 包/秒连续作业、长按重复、错误暂停/恢复、手输隔离、切页、断电与重启均须按最终模式复验。数据零差异、顺序准确、WAL/FULL、成功反馈后可恢复及内存门槛保持。
- 旧轮次保留为旧规则的证据，不删除失败记录，不将业务规则变更描述为原方案已经通过。
