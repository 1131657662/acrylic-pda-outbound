# 正式订单号与PDA识别

2026-09-20用户指出Web/PDA的OB加UUID长号不便现场识别，并要求PDA同步修复。本项独立于R06-C；R06-D仍按既定路线继续。

## 统一规则

- 0.23.1/V32起，新建正式订单使用`FH`＋北京时间日期`YYYYMMDD`＋全系统当日流水，例如`FH202609200001`。日期来自数据库UTC创建时间转换为Asia/Shanghai，与保存的created_at同一采样，不依赖PC/PDA时钟。
- 当日流水从1开始，至少4位；10000以后自然扩展为5位，不截断、不回绕。跨仓库共用同一日计数器，数据库行锁及原order_no唯一约束保护并发唯一性。超过INT最大值时明确拒绝，不能回绕。
- 编号分配、订单与原幂等回执在同一事务。相同请求重试返回原订单；修订、发布、领取和确认不会改号。失败事务回滚未交付的编号；不承诺绝对连续、无跳号。不得通过删除订单或清理计数器复用已交付编号。
- 内部UUID、URL、幂等键和所有关联继续使用原身份。现有OB长号保留，可按完整旧号搜索；不会修改已签名准备包、出库回执、历史作业或已确认订单。该编号只用于识别，不充当访问权限凭据。
- PDA_TEMP未来正式化必须在原提交事务复用OrderNumbers及全局日计数器，不得另起独立正式号计数器。本次没有实现R06-D，也不修改R06-C本机临时号或其UUID来源。

## PDA显示

待领取卡片示例：

```text
待领取 · 车号 苏A-测试车
订单号 FH202609200001
计划 2 包
```

第一行始终使用vehicleNo；订单号使用服务端orderNo。源码没有把这两个字段互换，原第二行缺标签易混淆。本机已准备订单卡片从已验签原计划读取同一订单号；领取确认框同时显示车号与完整订单号。旧长号仍完整换行显示，不伪造日期号或截短成另一个订单号。尚未取得可读编号的未决领取/已领取待准备记录显示“订单标识”及原UUID，不能把UUID标为车号或正式订单号。
