# PC 手工出库设计

日期：2026-09-17，实施更新：2026-09-18。状态：用户已授权按本方案实施，当前源码、接口、验证与使用边界见[交付记录](PC_MANUAL_OUTBOUND_GUIDE.md)；不等同现场或生产验收。不改变PDA已确认的B模式，不将普通Web账号伪装成PDA设备。

关联：[设计总规范](design-system.md)、[Web页面规范](web-page-template.md)、[状态语义](status-semantics.md)。已登记在[正式开发计划](系统设计方案与开发计划-V2.3.md)M14模块及15.1实施顺序，当前状态见[开发进度](DEVELOPMENT_PROGRESS.md)。本次设计范围包括进入、模糊查询、逐包核对计入、记录恢复、结单校验及结果查看，不只增加搜索框。

## 实施选择（2026-09-18）

实现采用独立pc_work/entry/submission/review/command_receipt和冻结行关联表，复用订单串行锁、全局bale_commitment、dispatch_record、结果与账务约束。写入窗口用随机ID、单调栅栏和版本；不设置过期自动释放。原写请求在浏览器发送前持久化，可跨刷新恢复。0.13.0基线主管恢复限原人员且保留全部原有效包，曾冻结的有效行不得普通撤销；0.14.0新增的换人、卸货释放和隔离走[独立异常处置证据流程](PC_EXCEPTION_DESIGN.md)，实际验证见[交付记录](PC_EXCEPTION_GUIDE.md)。具体权限、字段及重试规则见[当前契约](../contracts/IMPLEMENTED_API.md)。以下设计要求继续作为验收基准，文末样稿检查是历史记录。

## 1. 推荐流程与入口

入口放在装车订单详情右上方，名称为“PC 手工出库”，列表行的更多操作可提供同名快捷入口。主侧栏仍归属“装车订单”，不增加一个脱离订单的通用出库菜单。

流程：创建订单 -> 发布校验 -> 确认开始PC作业 -> 查找条码 -> 选择真实包 -> 确认计入本单 -> 结单核对 -> 后台校验/必要审批 -> 查看出库结果。

| 订单情况 | 入口与行为 |
| --- | --- |
| 草稿 | 可从“PC 手工出库”进入发布前核对，明确显示“发布并开始PC录入”；缺发布权限或规则/库存不符合时给出原因及有权限的处理入口 |
| 已发布、未领取 | 点击后核对仓库、订单、车号、计划与人员，确认后由后台原子取得PC作业资格 |
| 当前人员持有PC作业 | 入口改为“继续PC录入”，恢复同一作业与后台记录，不新建任务 |
| 其他人员或PDA已领取 | 显示作业归属与允许查看的详情，阻止并行录入；不能点击按钮强行接管 |
| 结单处理中/结果未知 | 入口为“核对PC提交结果”，不再允许新增包 |
| 待审核/已完成/已作废 | 查看对应明细和结果；不重复开放初始录入 |

“发布并开始PC录入”是显式业务动作，需要发布与PC作业两项权限。推荐后台在同一受控操作中处理发布校验和作业归属，或对分步处理的中间结果提供可靠恢复；不能发布后被PDA抢先领取却仍让PC界面显示已开始。具体接口与数据迁移在实现设计中与现有结构一起确定。

打开详情或预览候选不占用订单；确认开始才建立持久作业归属。拟新增作业路由 `/orders/:id/pc-outbound`，直接打开也重新检查权限和归属。返回详情保留原列表上下文，返回不表示释放订单。

## 2. 搜索语义

默认查询范围为当前仓库、当前订单有效计划中的全部发货代码，以及本次作业固定的库存/产品依据。不能搜索到订单外产品后悄悄加入计划。界面字段名“条码”，输入提示“完整条码或条码片段”；代码筛选器默认“本单全部代码”。

条码按现有11位规则处理，前三位为发货代码。输入保留前导零、去首尾空白、按已有规则处理字母大小写。不得进行数字转整数、自动补零、编辑距离猜测、删除字母后拼接匹配，或通过查询字段注入通配符。

- 完整11位：按完整条码精确查找，仍限制在本单产品范围；没找到时明确说明，不静默退成模糊匹配。
- 4-10位片段：在发货代码之后的条码部分作连续字符包含匹配；尾部完全匹配优先，其次其他连续包含。可包含合法字母，不跨越代码与包号边界拼出匹配。
- 少于4位：提示输入过短，不展开海量库存。四位为初始交互阈值，可依现场样本调整，不影响用户举例的六位输入。
- 连续输入停止约250ms后只执行只读查询；Enter或查询按钮立即查询。中文输入法组合期间不发查询，旧响应不能覆盖新条件。
- 搜索和浏览结果不预占具体包；选中行也不计包，只有确认后才发写请求。

以下为设计示例，不是实际库存：本单含003、571、719三个发货代码，输入 `010101`。

| 发货代码 | 完整候选条码 | 查询结果 |
| --- | --- | --- |
| 003 | 003B0010101 | 显示003组及该包 |
| 571 | 571B0010101 | 显示571组及该包 |
| 719 | 719C0010101 | 显示719组及该包 |

三种代码都有匹配就显示三组；只有两种有匹配就显示两组。没有匹配的产品不占候选列表，但右侧计划进度仍保留全部产品。一个代码有多条匹配时逐包列出，不合并成一条代码记录。此处“匹配”只表示找到了库存身份，是否可计入还需看状态。

候选按本单产品顺序分组，各组内尾部匹配优先，再按完整条码稳定排序。展示全局匹配代码数与包数，分组显示准确数量；组较多时先显示全部匹配组的摘要，各组默认最多5行，独立“查看更多”按需分页，避免首个代码占满前50条导致另两个代码被隐藏。总数须由真实查询提供，不能由前端当前页推算。

可增加“全部匹配 / 仅可录入”筛选，默认全部匹配，让用户知道为什么这包不能选。精确查到已出库/隔离/占用的本单产品时显示状态原因；其他订单的人员、车号等只在获授权时展示。

## 3. 页面布局

使用现有浅色工作台。作业期间侧栏可折叠至64px，仓库固定为本单所属仓库，顶栏保留返回和后台连接状态。不要另开浏览器标签页或要求弹窗全屏操作。

| 区域 | 内容 |
| --- | --- |
| 顶部页头 | “PC 手工出库”、车号、订单号、仓库、作业人员及PC作业状态 |
| 左侧主区 | 条码输入、代码筛选、查询；“候选条码 / 本单录入记录”标签与结果 |
| 右侧汇总区 | 本单有效包数/计划、净重；每个发货代码的计划、已录入、剩余 |
| 左区底部核对带 | 所选完整条码、代码/产品、净重、当前状态，以及“确认计入本单” |
| 右区底部 | “结单核对”；未满计划可进入短装核对，0包不能提交出库 |

桌面主区与汇总区采用约2.2:1比例，右侧约280-320px，左侧保持可阅读条码与产品的宽度；不使用左右两层卡片。搜索区约80-96px，结果行44-56px，核对带约72-88px，文字过长可增高。表体使用剩余高度滚动，搜索、所选包和确认动作保持可达。

在1366x768验证主要区域和确认动作同屏；宽度不足1100px时将产品摘要移到顶部紧凑区域，结果与核对区单列。更窄时字段和动作换行，不缩小条码字号。低高度/200%缩放时按Web规范切换页面滚动，不能多个固定区挤掉候选结果。会话内示意采用自适应高度展示，实际应用按视口实现。

候选每行展示选择控件、完整条码、发货代码/型号/品名、净重、状态。条码中的查询片段高亮，前三位代码始终保留。代码标签统一中性样式，不给每种产品分配大量不同颜色；可录入状态、已录入、不可用状态用文字加语义色。

当前选择显示浅色行底和明确选择控件；选择并不是成功色。底部核对带再次展示完整身份，减少只看相同尾号误选产品。搜索条件或代码筛选改变时取消旧选择，不能拿新结果界面确认上一次隐藏的包。

## 4. 从查询到计包

1. 操作员输入片段，结果跨本单全部发货代码展示；输入框Enter只查询，不直接计包。
2. 点击具体包的选择控件，底部核对带显示完整条码、产品和净重。多候选不默认选择第一行，即使只剩一条模糊候选也要明确选中。
3. 完整条码精确匹配唯一可录入包时可以预选以减少操作，但仍不自动保存。焦点不得自动跳到危险或结单动作。
4. 核对实物后点击“确认计入本单”。不为每包再弹一次确认框；核对带本身承担确认步骤。
5. 后台重新校验并原子保存成功后，右侧数量/重量和本单记录更新，反馈“已计入本单”。不能在发送请求时先加数量。
6. 成功后清除选择，默认保留查询片段和候选，将已计入行标为“本单已录入”且不能再次选择；光标回查询框。这样相同尾号的另外产品仍可选，不会被自动连带计入。

输入框Enter无论按多少次都不会执行确认。标准Tab可到选择控件和确认按钮，只有明确聚焦确认按钮时标准按钮激活才计包。鼠标双击行不直接保存，不提供“将所有模糊结果加入”或默认全选。

点击确认后冻结本次目标和请求身份，按钮加载防连点；结果未知时暂停下一笔写入并显示“本包录入结果待核对”。查询旧请求或按同键同正文恢复，不换一个新键重发。结果明确前不撤销另一行或结单；只读查询可以保留但不能混淆当前待核对对象。

原结果恢复成功只计一次；最后成功记录可保持在底部短状态区，不能遮住当前错误。此处成功只意味着后台保存了本单作业记录，订单仍未完成最终出库。

## 5. 录入记录、纠正与离开

“本单录入记录”展示后台已保存的条码、代码、净重、录入顺序、人员/时间、有效/撤销状态，默认最近在上便于核对；正式明细与导出仍按业务约定的原采集序号排序。记录可分页，并可按本单条码/代码查询，不能显示成每次查询重新累加的临时购物车。

未结单的误录可进入“撤销本次录入”，要求核对实物及原因，保留原记录和审计。撤销对占用的影响由后台按既有规则裁决并明确返回，不能浏览器删除一行就宣称包已全局释放。已结单、已审核或涉及历史实物处置的记录走受控处理，不直接编辑条码或重量。

返回订单、刷新、关闭浏览器不删除后台记录，也不自动解除订单占用。重新登录后可继续原PC作业。尚未发送的搜索文字无需弹确认；已选但未确认的包明确尚未计入；写请求结果未知必须保留可恢复记录与提示。

同账号多标签、多电脑只允许一个有效写入者。后台写入资格带版本/栅栏，旧标签发现失效后只读并显示新的处理入口；浏览器本地锁仅作辅助。心跳或短期写入租约失效不会自动释放业务订单和实物占用。主管接手需现有授权和明确交接，不通过清理浏览器数据绕过。

## 6. 结单与出库

“结单核对”打开专门核对页，显示车号、订单号、逐产品计划/有效包数/差额、净重、未处理异常和操作人员。完整包明细可展开查看；返回录入保持原状态。尚有录入结果未知时不能结单。

各产品都达计划时显示“确认结单并提交校验”；存在任一产品短装时要求原因并明确“提交后需主管审核”。不允许通过一个产品多录抵消另一个少录；超计划在逐包保存阶段就应阻断。0包不提交出库。

后台冻结本轮有序作业记录，固定提交身份与摘要，重新核对包身份、固定计划、当前周期、全局占用、权限、重量和数量。按既有政策创建出库事实、可选扣账、审计及最终结果；同一订单在PC/PDA渠道之间只有一个有效作业及当前提交归属。

结果区区分“正在校验”“待主管审核”“存在冲突，待处理”“出库结果待核对”“后台已确认出库”。点击提交不显示已出库；短装批准仍必须复核其他冲突。退回不自动释放包或恢复扫码。PC后续恢复作业需自己的受控证据流程，不能借用不存在的PDA停止证明。

## 7. 必要业务与技术支持

当前实现的正式提交绑定PDA身份、设备签名、授权和原输入证据。PC手工出库是新增采集渠道，需要后端支持，不能仅给现有页面加输入框。

- 使用Web登录会话、CSRF、当前仓库权限及单独的PC录入权限；拥有订单编辑权限不自动等于可计包或审批。具体权限标识实施时统一。
- 正式订单的FORMAL来源保留，新增“采集渠道=PC手工”与服务端作业身份；它与“订单由Web创建”是不同维度。拟新增字段/状态在接口和迁移中显式定义，不伪造deviceId、离线签名或PDA序号。
- 同一订单PC与PDA领取串行裁决，计划/库存/规则版本固定；PC在线作业不自行套用或续发PDA的48小时离线资格。
- 候选查询按仓库、当前计划产品及固定依据限定，查询结果附完整包身份、周期、净重、状态和可录入原因；选择结果不是可信写入凭据。
- 每次计包由后台复核身份/归属/版本、产品、格式、固定库存、当前周期、可用性、跨单防重和产品/整单上限；净重取可信库存，客户端不提交任意重量。
- 计包与本次在线占用、序号、有效汇总、审计、请求回执原子保存。两个PC并发选中同一包最多一个取得有效结果，不受自动扣库存开关影响。
- 搜索和确认之间可能被别的订单占用，确认时以最新后台裁决为准，失败时指出该包未计入且数量不变。PC看不到尚未上传的离线PDA事实，最终全局复核仍必要，不能宣称能实时阻止一切线下重复装车。
- 后台每笔记录可恢复，浏览器只缓存必要查询上下文和受保护的原请求恢复信息；断网时允许查看已确认记录但停止新的计包，不提供本轮离线Web录入。
- 数字片段查询需按本单范围限流、分组分页并验证性能；不得先把全部库存下载浏览器过滤。包含匹配不能假定普通前缀索引能高效支持，具体查询按实际数据量验证，不预先引入独立搜索服务。
- 共用订单最终出库、审批、占用和审计规则；分别验证PC服务端采集证据与PDA签名证据，不能为了复用接口删除现有安全校验。

## 8. 状态与边界样例

| 场景 | 页面行为 |
| --- | --- |
| 三代码同片段 | 三组全部可发现，逐条选具体包，不默认第一项 |
| 两代码同片段 | 只显示两组候选，计划汇总仍显示三产品 |
| 同代码多候选 | 所有包保留完整身份，分组内分页，不合并为一条 |
| 没有匹配 | 显示本单范围内无结果，保留输入，不扩搜其他订单产品 |
| 唯一模糊匹配 | 用户选择并确认，不自动计包 |
| 已录入/已出库/隔离/占用 | 显示原因，不能选择；不得泄露无权限的他单信息 |
| 计划已满 | 产品进度清楚，确认阶段拒绝超量，不先加数再标红 |
| 连点/超时/关闭后重开 | 同一次原请求只生效一次，恢复原结果 |
| PDA同时领取 | 后台只允许一方成功，另一方显示真实归属 |
| 写入资格被接管 | 旧窗口停止写入；不丢既有记录，不释放业务占用 |
| 结单短装/冲突 | 按原因进入主管审核或受控处理，不统一显示成功 |

## 9. 交付与验证

先评审订单入口与PC作业代表页，再落实采集渠道、作业归属、候选查询、原子计包、恢复和结单契约，最后接前端及回归现有PDA链路。与UI优化配套实施，但作为明确的新业务范围记录。
