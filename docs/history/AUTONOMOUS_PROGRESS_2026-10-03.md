## 自主决策记录

36. 优先修复真实批准链的前置阻断。先让生成测试身份的原设备通过真实 HTTP 完成停工，再调用既有原批次 abort 入口；不通过 SQL 伪造 ABORTED。927 实测停工成功后 abort 返回 409 WRITE_CONFLICT，订单版本 6、停工消息版本 7，19 表全部回滚，确认共享版本分配缺陷。
37. 修复局限于 HandoverStore：下一号取订单 row_version 和同恢复代次消息最大版本的较大值再加一；插入消息时同时推进订单版本。MANDATORY 强制已有事务，条件更新防止版本倒退。停工和激活复用同一修复；不改写历史消息，不新增迁移或放开生产 gate。
38. 用两类证据证明行为：真实 HTTP 停工→原设备 abort→立即/重启恢复；隔离事务内人为构造订单领先、消息领先的数值夹具并回滚，后者只证明分配算法。另注入 HANDOVER_STOPPED 消息 INSERT 失败，十九表快照证明订单版本、召回撤权、交接证据与幂等索引全部回滚。
39. 修改已验业务后重新跑完整服务端回归，并单独回归既有来源拒绝/锁竞争/激活链。后者仍使用合成停止证明，只作共享版本修复回归；不将它升级成可信批准或设备验收。自审整文件重写时发现并移除一次误加的测试断言，最终差异仅新增激活版本核对。
40. 检索发现 CorrectionStore 仍有仅按 MAX(entity_version)+1 分配且不推进订单版本的相似模式。仅记为待验证风险，下一项先验证更正后真实后续状态写入是否冲突，再继续可信批准链；本次提交不把未验证的更正风险标成已修。仅明确五个源码/测试路径进入产品提交，11 项遗留保护。
