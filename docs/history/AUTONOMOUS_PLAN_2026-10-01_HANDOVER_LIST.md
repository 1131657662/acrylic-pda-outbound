# R07 订单内交接查询方案（2026-10-01）

## 依据与范围

输入为 `009b9d05af463339f623a6b7ecbf62a7ca07edf7`。`docs/parallel/R07/UI_DESIGN.md` §1 指定“Web从装车订单→订单详情进入换机交接”，并要求“默认列表20条，服务端真实分页”“切仓后旧响应不能覆盖新对象”；§2 要求“原机停止、原提交结果、资料完整、实物核验”分开显示。现有 GET 只能凭已知案件 ID 查询，订单详情没有交接入口。

据此将初稿的全局列表收窄为订单内查询。新增 `/api/v1/handovers/cases`，必传仓库与订单；复用实时 `order:handover` 或 `order:resume` 权限、仓库校验及默认关闭的既有交接开关。按申请时间和案件 ID 降序，游标绑定仓库与订单，最多取请求数加一条判断后续，不返回虚假总页数。列表摘要不是已核验原件；详情继续调用既有验签的上下文 GET。

Web 从订单详情“查看换机交接”进入订单内列表并进入详情；保留订单查询参数及交接游标。详情分开显示四维状态与原申请原因；原标识放折叠凭据区。本批不新增命令按钮、全局审批中心、签名/回执重写、PDA接收能力或正式契约发布。

## 环境与失败纪律

仅新建隔离数据库与合成身份，不接原库/现网。D盘须大于20GiB；设备只枚举前后快照，不启动AVD。八项预存保护文件不动。脚本整文件编写并parse检查，单Gradle写者。真实产品缺陷或既有回归失败停依赖项并记录，不自动重跑刷绿。新attempt认证停机、dump及ZIP逐文件验证后才清理本批datadir，旧证据不动。

## 未验边界

列表是实时读取，跨页期间状态可能变化，不承诺跨HTTP请求固定快照；刷新首页可看到后到记录。字段与状态显示不证明现场身份、PDA停止/准备/激活、本机耐久或续扫资格。811首次同键、outbox缺status、R06原命令恢复、分页806及其他既有停报项仍保留。全开关默认false、localDeletionAllowed=false，不合main、不部署、不打标签，不进R08/R09/R10。
