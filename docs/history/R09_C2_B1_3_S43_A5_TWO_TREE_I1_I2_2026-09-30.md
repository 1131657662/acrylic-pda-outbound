## 1. I1：判定共享树唯一实质差异——**不并入**

**对照对象**：`server/src/main/java/com/acrylic/outbound/temporary/command/CommandReceiptIntegrity.java`
（主树 HEAD `7866686` 版本 vs 共享树 `r06-e2a-migration` detached `ea4d166` 工作区版本）

**逐行对照结果（归一化行尾后）**：

```text
sharedLines=109 mainLines=104
SHARED L21:         catch(RuntimeException damaged) {
MAIN   L21:         catch(RuntimeException damaged) { throw CommandErrors.corrupt(); }
```

共享树版本比主树/HEAD **多 5 行**，内容是一段自述的诊断块：

- `// TEMPORARY DIAGNOSTIC (attempt 117): name the failing invariant instead of swallowing it.`
- `System.err.println("RECEIPT-INTEGRITY-CAUSE: " + damaged);`
- `damaged.printStackTrace(System.err);`

**判定：仅为 attempt 117 的临时诊断，`catch` 内多了两行 stderr 输出；主树/HEAD 的版本才是干净版本。** 依据：①该块自述为 `TEMPORARY DIAGNOSTIC`；②同类诊断在 S31 已用 `git checkout --` 撤销（[S31 记录](R09_C2_B1_3_S31_SIGNING_BINDING_2026-09-29.md)先例）；③主树该文件**不含**任何 `DIAGNOSTIC`／`attempt 117`／`printStackTrace`／`System.err`（grep 为空）。**⇒ I1 结论：不并入；主树无需据此改动。** 共享树原件保留未动。

**支撑事实（S34 已实测，本批复用）**：共享树 95 项脏内容（28 改＋67 未跟踪）中 **94 项与主树工作区逐字节相同**（LF 归一化），唯一差异即上述文件（`.local/shared-tree-reconcile-20260930/normalized-diffs.txt`）。
