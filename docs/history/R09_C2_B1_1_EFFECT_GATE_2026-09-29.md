## 2. 实现与规则裁定

**对抗性复核更正**：原规则在 getObject、视图 SELECT、语句元数据取得处有漏口；真实反例及修正见[复核记录](R09_C2_B1_1_ADVERSARIAL_2026-09-29.md)。下列规则行已同步修正；前轮测试数和运行记录仍按历史保留，不冒充本轮最终验收。

实现位置：[连接代理](../../server/src/main/java/com/acrylic/outbound/recovery/RecoveryConnectionHandler.java)、[子对象代理](../../server/src/main/java/com/acrylic/outbound/recovery/RecoveryJdbcObjectHandler.java)、[门](../../server/src/main/java/com/acrylic/outbound/recovery/RecoveryEffectGate.java)、[SQL 分类](../../server/src/main/java/com/acrylic/outbound/recovery/RecoveryEffectSql.java)、[SQL/批记忆](../../server/src/main/java/com/acrylic/outbound/recovery/RecoveryEffectStatement.java)、[JDBC 方法表](../../server/src/main/java/com/acrylic/outbound/recovery/RecoveryEffectCalls.java)。

1. `commit()` 无条件经过门；`setAutoCommit(true)` 除**明确成功的显式 commit/全量 rollback 之后、且没有任何后继执行或行变更**的清理复位外，均经过门。新的执行尝试在委托前清除该证明，包含部分批处理失败；不使用驱动 `getAutoCommit()` 作为提交证明。
2. 按本次提示词“凡不能证明只读 ⇒ 过门”，**已知写入也不依赖手动事务免门**。原始 COMMIT、SET AUTOCOMMIT=1、START TRANSACTION/BEGIN、白名单 DDL 总是过门；DDL 已提交结果不能由 close/rollback 撤销。全量 rollback/保存点操作仍走既有通路。
3. 有限 SQL 允许集：只有无 FROM 的常量 SELECT、SHOW TABLES/DATABASES 保留只读免门；有限 SELECT FROM（列/COUNT(*)、单关系、简单 WHERE）、DESC/DESCRIBE、有限 EXPLAIN 均按 SOURCE_READ 过门，因为关系可为带写函数的视图。其他复杂 SELECT/WITH/函数/未知 SQL/注释/多语句等继续委托前拒绝。原 G09 的宽只读声明被本轮 A2 更正，不以语法外观证明无副作用。
4. prepare 期绑定 SQL；无参执行/入批缺失绑定即拒绝，显式 null SQL 不能回退到绑定。入批与执行分别检查；clearBatch 成功才清除记忆；批操作失败后状态不确定，必须确认清空后才能再次执行。已确认空批可执行，不复用旧写入判定。子对象反向引用复用已绑定代理。
5. ResultSet 的 insertRow/updateRow/deleteRow/updateXxx/moveToInsertRow 经过门；refreshRow 等未知方法拒绝。ResultSet/CallableStatement 的 getObject（无类型、类型提示、Map、索引、名称）及 getBlob/getClob/getNClob/getSQLXML/getArray/getRef 全部取得处拒绝。PreparedStatement/CallableStatement.getMetaData 可由驱动隐式执行 SQL，亦取得处拒绝；ResultSet.getMetaData 仅描述已取得行。统一拒绝码 CONTROL_EFFECT_UNCLASSIFIED，不因 Authority 放行而委托。
6. 现有连接监视器继续串行化子对象与关闭。UNKNOWN 触发本机门拒绝，不改写既有 writer lease/文件锁协议。关闭/回滚清理不被新的效果判定拦截。
