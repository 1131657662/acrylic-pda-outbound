## 2. 方法：真实产品获取路径（不是裸 FileChannel）

- 新增 IT `G0K1WriterLeaseIdentityRealIT`；扩展子 JVM 探针 `G0K1FileLockProbeMain` 增加**产品路径模式**：
  `product-lease-acquire`（`RecoveryControlLock.locked(root, () -> RecoveryWriterLease.acquire(root))`，真实持有并保持）、
  `product-lease-acquire-fail`（同一路径，记录真实异常**类型/码/栈帧**）、`classpath-check`（确认子 JVM 能加载产品类与 JNA/jackson，**防止静默降级为裸 FileLock**）。
- 控制根由 `RecoveryWriterLeaseTest.protocol()` 构造（`writers.json` 写入 `RecoveryWriterProtocol.fileIdentity(...)`），使 `RecoveryControlLock.requireOwner` / `RecoveryControlIntents.requireAdmission` 可通过。
- 身份观测**只用产品原生函数** `RecoveryWriterProtocol.fileIdentity`（Windows＝JNA `GetFileInformationByHandle`）；**禁用** `Files.readAttributes().fileKey()`（Windows 为空，2026-09-26 已记录）。
- 每个场景 **3 次重复**，每条记录含子进程 PID、JVM 版本、退出码、起止时间戳与**调用路径标签**；所有结论均**有断言**。

## 4. 为什么上一轮 §4 的定性证据不足（必须写清）

| # | 证据缺陷 | 后果 |

| 1 | 用 `Files.readAttributes().fileKey()` 观测“文件身份” | Windows 上该值为空（2026-09-26 已记录并改用原生身份）⇒ “新文件身份”**未被真实度量**，等于没有身份证据 |

## 6. B1 承重需求清单（本轮不实施）

1. **`fenced.lock`（未实现）**：只创建、不删除、不替换；**每次获取前**用原生身份校验（`GetFileInformationByHandle` 语义），不一致 ⇒ **失败关闭**（等价于 `CONTROL_WRITER_LOCK_REPLACED` 的拒绝码，具体码由 B1 定）；加**审计事件**；**禁止**用 `fileKey()` 观测。
2. **`writers.lock`（已实现、已覆盖）**：保持现有身份绑定与“不自动修复”语义；B1 不得弱化，亦不得引入“锁文件缺失即重建”的自动修复。
3. **DDL 隐式提交 ⇒ close 期 rollback 假设**（源自 [G0-K1-1 真实驱动验证](R09_C2_G0_K1_REAL_JDBC_REVERIFY_2026-09-29.md)）：不得假设“未显式 commit ⇒ close 期 rollback 可撤销”；DDL 类调用必须按提交类过门。
4. **可用性/运维**：外部删除锁文件会使后续写者失败关闭 ⇒ 需要运维流程与审计可见性（属 B1 运营面，不改变本轮安全结论）。
