# 无人值守开发计划（2026-10-05）

## 目的与适用范围

本计划用于在 `D:/acrylic-pda-outbound` 按既有 R01–R09 路线继续收口。它不是新的产品需求，也不扩大路线范围；当前版本、分支、SHA、迁移和契约事实只读取 [协作断点看板](../ORCHESTRATION_STATUS.md) 的生成事实块。

执行方式为无人值守：技术方案、实现顺序、测试工具和修复方式由当前助手自主选择；出现多个可行方案时选风险最低、改动最小、最符合现有实现和已确认政策的方案，并把决定记录到当日自主进度。每个子项都必须有当次证据，不能用历史通过替代本次验证。

本计划不授权以下动作：合入 `main`、打标签或 Release、部署、接原库/现网、修改生产开关默认值、使用正式签名、删除 `.local` 证据或清理真实数据。遇到这些边界时保持停止并记录，不用技术选择替代审批。

## 当前进度判断

依据看板、进度索引、当日自主进度和源码核对：

- R06/R07/R09 已有大量隔离环境、真实回环 HTTP、迁移和回归证据，但这些是子项证据，不等于 R06、R07、R09 整体完成。
- 接收机确认后的跨设备续作服务端链、最终提交和账务链已经完成相应服务端验收；Android 消费、PDA 页面/重试交互、APK、两个物理设备、原身份和现场网络仍未验。
- R06 的 TEMP、mapping3+、候选排除授权及跨来源业务闭环仍有明确缺口；R07 的更正/库存对账仍需按已确认政策逐项编码和验证；R08 需消费已验证的原结果/调整/净值契约；R09 仍有恢复运维和外部/长时边界。
- 工作树存在既有未提交和未跟踪路径。编制核对期间另有一个项目内无人值守开发会话正在活动并拥有实际写权；该会话已在本计划提交前完成并推送检查点。后续仍须在任何写入前重新核对实际写者，不触碰他人正在修改的文件、数据库、证据目录或提交。
- 当前没有证据支持“完整跨设备现场闭环”“生产就绪”或“R01–R09 全部完成”的结论；这些称谓继续禁止使用。

## 无人值守决策规则

1. 已确认的 R06/R07 业务政策直接执行，不重复询问；技术细节优先选择 fail-closed、追加写、原键幂等、事务原子、最小权限和可回放方案。
2. 纯技术选择由当前助手直接决定，并记录“选择、被舍弃方案、理由、影响和验证”。不因等待用户回复而停住。
3. 尚未定义且会改变业务权限、库存结论、生产放行或数据删除的政策，不臆造业务事实；采用“拒绝并保留证据”的安全默认，记录为待决边界，继续其它可独立子项。
4. 发现现有测试、契约或实现与计划冲突时，以源码和当次可复现实验证据为准；先保留失败证据，再修复最小范围并重跑受影响回归。
5. 共享树、数据库、设备和提交同一时刻只允许一个写者。长任务启动前记录进程、监听、磁盘和树快照；磁盘低于既定安全阈值或出现未知写者时暂停该批次。

## 统一子项闸门

每个子项严格执行以下顺序：

1. 写明范围、非目标、依赖和可验证退出标准。
2. 只读核对现有实现、契约、迁移和历史失败证据，确认没有重复实现。
3. 实现最小改动；迁移、权限、错误和恢复路径一起处理。
4. 运行定向测试；失败时保留 XML、日志、数据库 dump、源码哈希和失败说明。
5. 自审代码、测试、权限、事务、幂等、并发、原键和日志；修复后从定向测试重新开始。
6. 运行受影响的模块回归、隔离真实 HTTP 或 Android/APK 检查；明确记录 tests/failures/errors/skipped。
7. 仅在退出标准全部满足后，按明确路径暂存，复核暂存差异、敏感文件排除和 `version_facts.ps1 -Check`。
8. 使用既定中文提交格式提交并推送到 `codex/development`；记录提交回执、远端核对、证据目录和未完成边界。
9. 更新当日自主进度和看板当前区；看板当前区只保留摘要，细节放历史记录。失败或跳过不得改写成通过。

任何一项未通过，停止进入下一项；只修复导致失败的范围，不借机扩展功能。

## 执行批次

### B0：写权交接与基线冻结

**范围**：等待当前活动写者完成或明确交接；核对实际分支、HEAD、远端、全部脏路径、工作树、进程、监听、磁盘和数据库占用；为本批次创建新的 `.local` 快照目录。

**退出标准**：写权唯一且可追溯；受保护脏路径清单已保存；没有复用旧 attempt 的日志、XML、dump 或数据库；版本事实检查通过。

**验证与交付**：只读脚本、Git 差异核对、进程/监听快照、`version_facts.ps1 -Check`。这是后续批次的前置条件，不修改产品代码。

### B1：收口当前 R07 接收机跨设备续作

**范围**：在当前活动写者交接后，核对最终提交、原提交替代指针、续作占用、账务、回执重放、错误身份/序列和恢复屏障；只修复当次复验发现的缺陷。

**退出标准**：服务端真实回环 HTTP 在新隔离数据库上通过；普通集成和服务端单测无新增失败；失败轮全部保留；不宣称 Android 或物理设备闭环完成。

**验证与交付**：先定向续作/最终提交测试，再受影响集成和服务端全量；源码前后哈希一致后才暂存、提交、推送。若仅复验无代码变化，提交只包含必要进度/证据索引变更。

### B2：接收机 Android 消费与 PDA 重试

**范围**：沿既有 Room、下载确认、原正文耐久保存和续作设计，接入接收机续作命令的本地持久队列、签名回执验收、网络重试、身份/权限/恢复屏障变化处理和页面状态。保持原导入资料不可改写、冻结态不可提前解冻、同键幂等。

**非目标**：不新增通用同步平台、不放宽生产 gate、不把 JVM/MockWebServer 结果写成真机验收。

**退出标准**：Android 单元/Room 定向测试通过；成功、服务端拒绝、响应丢失、socket 断开、重启重放、身份切换和错误回执均有反例；APK 构建、lint/typecheck 通过；同实例服务端 + Android 组合测试通过。

**证据与交付**：保存测试 XML、日志、APK 校验、数据库摘要和源码哈希；通过后提交推送，再更新进度。真实 PDA、APK 安装、两个物理设备和原身份仍单列未验。

### B3：R06 来源、停止保全与候选消费

**范围**：完成停止与扫码写者协调、原件/请求/回执耐久队列、坏资料拒绝、身份/仓库/设备切换暂停、重启和丢回执恢复；补齐来源事实校验和实际消费者对非零候选的确认。mapping3+、候选排除和跨来源权限只沿已有政策或安全默认处理。

**退出标准**：非空迁移保留原键、正文和回执；错误来源、缺失事实、伪造或跨仓输入拒绝且不误占；非零候选由真实消费者验证；上传、停止、恢复和占用/审计状态在事务失败时守恒。

**验证与交付**：Android 定向、服务层、隔离 MySQL + 真实 HTTP、受影响全套回归；每次失败保留证据。未得到业务授权的候选排除不实现新权限码，改为拒绝并列边界。

### B4：R06 处置、续作与成功回执剩余链

**范围**：按已确认规则补拒绝、实物处置、跨来源续作、关联确认和成功回执链，复用已验证的确认记账、独立短装和成功归档；不改写原事实，不提前生成放行或删除资格。

**退出标准**：每条命令具备权限、原请求恢复、不可变回执、占用/账务一致性；同键重放返回原回执，异文/跨身份拒绝；事务、触发器和并发反例通过。

**验证与交付**：定向 HTTP、真实 MySQL、服务端回归；若需要新迁移，先在非空库升级/回退验证，再提交迁移和代码。TEMP 高轮次、mapping3+ 等无法由现有证据推出的项目单独停报，不包装成完成。

### B5：R07 换机、更正与库存对账

**范围**：先只读核对现有实现，再按已确认政策编码主管审批、跨日补录、附件限制、误批撤销、逐笔调整、原来源保留和最新净结果；接入 R09 已有事实恢复接口时保持最小边界。

**退出标准**：原出库事实、原 ID、原回执不可变；审批身份分离；附件大小/数量限制和失败回滚可复现；重复调整、并发激活、错误审批和账务贡献均有反例；每笔调整可追溯且只记账一次。

**验证与交付**：真实 Web HTTP、非空迁移、精确 SQL 故障、重启恢复、服务端回归；必要时补 PDA 消费测试。通过后分批提交，不把 GET 查询或合成服务层结果当作完整业务验收。

### B6：R08 原结果、调整和净值导出

**范围**：只消费已经稳定的 R06/R07 结果版本；实现严格按原采集顺序的 Excel/PDF/汇总/任务/授权下载/失败恢复，区分原结果、调整和当前净值，禁止报表自行补造账务。

**退出标准**：任务数据版本固定；授权下载、重试、取消、重复执行和权限变化有反例；导出顺序、数值、调整链和审计可复核；失败不产生半个可交付文件。

**验证与交付**：服务端单测、真实 HTTP、任务重启/失败恢复、文件字节和解析检查；原生 Office 打印显示与现场留存仍列为 C 档未验。仅在实现和验证同时通过后提交推送。

### B7：R09 恢复与运维可隔离部分

**范围**：收口共享恢复控制/fence、恢复代次、历史 keyring、事实重建、备份恢复、设备对账、监控和资源限制中可在隔离环境证明的部分；锚点保管/轮换等未定政策先形成提案并采用安全默认。

**退出标准**：实际恢复后原 ID、原回执、取消、调整和账务不重复；错误数据库、截点外文件、旧 keyring、并发写者和升级回退有反例；恢复前后设备/订单对账一致。

**验证与交付**：非空隔离数据库、真实跨进程/HTTP、恢复批次和服务端全量；RPO/RTO、异地防覆盖、长时和真实断电只记未验，不能由本机演练代替。

### B8：整合回归与 R01–R09 遗漏核对

**范围**：在各子项提交推送后，以实际整合输入检查契约、迁移、权限和 UI/Android 依赖；只整合已有授权范围，逐批解决冲突。

**退出标准**：每个已实现子项有对应当次证据；每个后延事项有缺条件和下一动作；受影响服务端、Android、Web、迁移和脚本回归通过；未跟踪敏感文件和 `.local` 不进入提交。

**验证与交付**：运行整合后的受影响全套，核对远端分支和提交清单，更新看板和进度索引。`main`、Release、部署和正式签名继续不执行。

## 明确后延的现场条件

第二台/异地 PDA、真实 Keystore、真机全量页面、现场原身份和网络、连续离线长时、真实断电/OS 死亡、实际数据规模与性能、原生 Excel 打印、App 内 HTTPS 升级、完整备份取回证明、Linux 实际运维启停和 R10 现场验收，必须取得相应环境与授权后单独验收。无人值守规则不会伪造这些证据，也不会把隔离测试改写为生产结论。

## 失败处理与停止条件

- 定向测试失败：保留失败证据，定位根因，最小修复，重新跑同一批；不删除失败轮。
- 回归新增失败：停止当前批次，比较源码和迁移差异，修复或回退本批未提交改动，再从定向测试开始。
- 发现未知写者、数据库非隔离、监听冲突、磁盘低于安全阈值或敏感文件进入暂存：立即停批，保存快照并记录。
- 只要退出标准未全部满足，就不提交、不推送、不更新为“完成”。
