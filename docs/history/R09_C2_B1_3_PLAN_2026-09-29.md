## 4. S1 实现规格（已核实到可照做；**尚未实现**）

> 本节是**勘察结果**，不是交付。S1 仍未实现、未验证。

核实结论（主树 `codex/development`）：

- 唯一权威加载入口：`RecoveryControlHistory.load(RecoveryControlLocation, Path trusted)`（[RecoveryControlHistory.java:13](../../server/src/main/java/com/acrylic/outbound/recovery/RecoveryControlHistory.java)）；入口第一步已调 `RecoveryControlRecords.identity(...)`。
- 现存 kind 取值：`identity.json` 的 `authorityKind = INITIAL_NORMAL_INSTALL`（另见 `RecoveryLeaseRoots.java:87`）；`InitialNormalEvidence.kind = INITIAL_NORMAL`；`InitialNormalCompletion.kind = INITIAL_NORMAL_COMMITTED`。
- **封闭权威目前只有路径**（`identity.json.closedAuthority`，且初始安装要求它**不存在**），其身份文件尚未实现（属 B9）⇒ 今天只有一个 kind 可通过校验。
- `load` 的**直接**调用点共 4 处：`RecoveryControlReader.java:18`、`RecoveryLeasedTransaction.java:48`、`RecoveryAdmittedDataSource.java:89`、测试侧 `RecoveryWriterProcess.java:45`。
- **与设计 §9 第 2 行的差异**：该行列出的 5 个类（`RecoveryClosedProjection`、`RecoveryLeasedTransaction`、`RecoveryControlReader`、`RecoveryNormalRegistration`、`RecoveryAdmissionVerifier.of`）**当前不直接调用 `load`**。S1 只强制**直接调用点**；对它们的"purpose 穿参"在真正引入加载调用时处理 ⇒ **不得声称设计表第 2 行已完成**。

S1 的确切做法：

1. 新增 `RecoveryControlPurpose` 枚举：`NORMAL_ADMISSION`、`CLOSED_PROJECTION`。今天只有 `NORMAL_ADMISSION` 可通过；`CLOSED_PROJECTION` 遇到 `INITIAL_NORMAL_INSTALL` 抛新码 `CONTROL_AUTHORITY_PURPOSE_FORBIDDEN`。
2. `load(location, trusted, purpose)` 成为**唯一入口**，去掉无名重载 —— 让"省略 purpose"在编译期不可能。
3. 4 处直接调用点显式传 `NORMAL_ADMISSION`；测试侧同类。
4. 验收测试（纯离线，`RecoveryAuthorityPurposeTest`）：①`NORMAL_ADMISSION` 加载既有 fixture 正常；②`authorityKind` 非法 ⇒ 既有码不变；③`CLOSED_PROJECTION`＋`INITIAL_NORMAL_INSTALL` ⇒ `CONTROL_AUTHORITY_PURPOSE_FORBIDDEN`；④**静态测试**：扫描 `src/main`、`src/test`，断言不存在省略 purpose 的 `RecoveryControlHistory.load(` 调用。
5. Python 侧 `control_history.load(...,purpose)`：**本切片不实施**（避免无调用点的空接口），需要时单列。
