# R07 正式来源停止证据接入

这是既有召回与交接流程的受控连接，按自主授权实施。完成标准是原人员/原设备通过认证入口把已耐久的原恢复包绑定到交接案件，同一事务保存原停止结果、交接凭据、审计和通知；同键同文恢复原字节，错误来源/摘要/高水位/状态拒绝且不留半笔效果。生产交接开关继续默认关闭。实施结果与 SHA 见本日自主进度。

## 选择与边界

- 复用既有 `RecallRepository` 的本地停扫/恢复包以及 `RecoveryPackages`、`RecallStops` 的服务器原资格撤销语义。新入口不生成设备 RECALL_STOPPED 事件，也不接受主管代原机声明停止。
- 新增受控 PDA `POST /pda/handovers/{caseId}/stop-ack`。请求引用召回及恢复包，携带原键、原案件版本、摘要、输入/审计高水位。原恢复包须已经通过既有上传入口耐久保存。
- 原人员和原设备都匹配后，按身份→来源→案件→订单/槽/批次取得锁，核对原申请、实时来源及恢复包原事实。允许已过期的离线凭据提交停止证据，仍须有效在线身份；不发放扫码权。
- 复用原召回停止回执，先验原签名、用途与绑定，再用独立签名域签发交接停止回执。回执固定原请求、原来源、原身份、恢复包摘要与高水位，全部能力为 false。停止、证据两行、案件变更、审计/outbox 和幂等索引在同一事务内生效。
- STOP_PROOF 行摘要绑定完整签名回执字节；RECOVERY_PACKAGE 行摘要绑定原恢复包，两行保存相同的签名描述回执，避免复制大包正文。两行各自标识、来源设备、高水位及记录时间也在重放时核验。
- 同一人员/路由的同键已提交命令先恢复原回执；跨案件复用同键、同键异文、不同原键重复停止均不得创建第二结果。首写缺文件或包事实不完整即拒绝。重放核验原签名、证据对和幂等索引，不依赖后续案件状态或重新签发。
- 本项只连接 FORMAL 现有召回链。原批次未终结时只记录停止证据，批准仍受原结果门控制；TEMP 的来源级停止与专用接收资格另行实现。PDA 页面接入、两端实物交接和新机最终提交仍须独立验收。

## 验证口径

1. 离线协议/签名测试：严格字段、规范原键、大小限制、签名域、篡改、能力位、原字节恢复及 Spring 代理配置。
2. 非空隔离 MySQL：发布/领取/召回/上传使用既有处理器和生成的 EC 测试身份，新停工入口使用实际 HTTP。非原人员反例的会话为明确合成夹具；均不替代现场原设备/Keystore 证据。
3. 比对错误身份、版本、摘要、高水位、恢复包、缺文件、写入失败前后业务表，证明失败不留部分撤权、证据或通知。真实锁等待覆盖首次同键并发；正常与既有召回停止均验证重启重放、保留包占用和拒绝未终结原批次批准。
4. 编译、相关及完整服务端回归，并将实际 HTTP 请求/回执对照契约；MockMvc、真实 HTTP、合成身份和真实设备/现场分别记录。
