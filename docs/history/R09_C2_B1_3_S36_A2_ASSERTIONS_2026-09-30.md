## 2. 落成的断言（实测原始输出）

`.local/e2a-cross-20260925-736/operations.txt` 原文：

```text
verification level=service layer (SecurityContextHolder + HandoverCommandService/HandoverActivation); HTTP layer not verified
M5 清单状态无效 -> HANDOVER_CHECKLIST_REQUIRED

M9b 案件不存在 -> HANDOVER_CASE_NOT_FOUND
```

| 矩阵行 | 断言 | 实测码 | 同用例内的"不落半条"断言 |
| --- | --- | --- | --- |
| M5 | 清单状态不在固定词表内 | `HANDOVER_CHECKLIST_REQUIRED` | `handover_checklist` 行数与失败前**相等**（清单是先插入后判定四维证据 ⇒ 必须无残留） |
| M8 | 原结果未终结 | `HANDOVER_ORIGINAL_RESULT_OPEN` | 案件状态/版本/回执数/审计行数均不变 |
| M9a | 案件版本过期（乐观锁） | `HANDOVER_CONTEXT_CHANGED` | 同上 |
| M9b | 案件不存在（404） | `HANDOVER_CASE_NOT_FOUND` | **该 404 没有留下回执、也没有留下案件行**（"404 不当成未发生"） |
| M13-② | 被拒命令不得留半条 | — | `handover_checklist`／`handover_evidence`／`handover_command_receipt` 计数与基线相等；`handover_case` 状态与 `row_version` 不变；`order_assignment` 仍只有 1 条 ACTIVE |

**前置构造的诚实说明**（写进用例注释）：M5 必须穿过"停止证明/证据完整/实物一致/原结果明确/高水位"这些守卫才能到达清单判定，因此用例**直接在库里记录**守卫要求的状态（追加一条 `STOP_PROOF` 与把 `stop_state` 置为 `DEVICE_ACKED`）。这正是既有反例①已经证明"缺它必拒"的那道缝，**再断言一次不构成新证据**；本用例证明的是**它之后**的清单与原子性。

## 3. M6（摘要／回执完整性）**不是缺测试，是没接线**——本轮定性

对 `server/src/main/java/com/acrylic/outbound/handover` 全目录 grep `corrupt|HANDOVER_RECEIPT_INTEGRITY_FAILURE|receiptIntegrity|verifyReceipt`：

```text
唯一命中：handover/HandoverCommand.java:35
    static BusinessException corrupt() { return new BusinessException(409,"HANDOVER_RECEIPT_INTEGRITY_FAILURE",…); }
```

⇒ **`HandoverCommand.corrupt()` 零调用点**：R07-1 命令链**没有**"原命令回执可核验"的读取/校验路径（对比 R06 链有 `CommandReceiptIntegrity` 全量回读校验）。目前对"回执被篡改"的抵抗力只有 `HandoverCommandService.replay` 的**逐字节比较**（`:63`），命中时给 `IDEMPOTENCY_CONTENT_MISMATCH`，**不会**给 `HANDOVER_RECEIPT_INTEGRITY_FAILURE`。

**处置**：M6 定性为"**实现缺口（回执完整性校验未接线）**"，**不写成"缺测试"**，也**不**为它造一个不存在的行为断言。补它需要产品改动（把 `HandoverReceiptCodec` 的读取/校验接进命令回读路径），**需单独授权**。已登记为 R07 缺口。
