# R09 C2 B1-2 补充规格：P5 认证锚点（2026-09-29）

来源：[B1-2 对抗性复核](R09_C2_B1_2_ADVERSARIAL_2026-09-29.md)。本页只定义**决定与实现规格**，不含代码；未获决定前不实施。

## 1. 要解决的问题（已实测，非推测）

| 变体 | 实测 | 是否可由锚点闭合 |
| --- | --- | --- |
| **H3** 孤儿租约的 owner 引用被改写成**活属主**（摘要自洽） | 放行 `delegateDelta=1 observerDelta=1`，3/3 | ✅ 可（记录带 HMAC 标签即不可伪） |
| **H3′** 直接**删除**孤儿租约记录 | 同族：无记录即无可扫之物 | ✅ 可，但**必须**配合"锚定的操作索引"（否则删除后扫描看不见任何东西） |
| **H3″** 把租约改名成审计标记 | 已修（仅当同前缀租约仍在且内容为审计形态才跳过） | 已闭合，但 H3′ 仍会使它退化为"删掉即可" |

共同根因：**租约与进程记录之间的配对、以及"应存在哪些记录"这件事，全部由同一目录内、双方摘要均由写入方给出的文件表达**。在这类文件上做"自洽校验"无法防伪。

## 2. 必须先定的问题（用户决定）

**P5 租约/进程记录目录是否属于"可被对手改写"的范围？**

- **若属于（推荐按此继续）** ⇒ 走**方案 A**；F5/孤儿扫描在锚点落地前**不得**被当作防伪依据，`DEBT-R09-C2-LEASE-ANCHOR` 与窗口 W 并列单列。
- **若不属于** ⇒ 走**方案 B**：以用户书面决定记录"P5 目录改写不在威胁模型内"，同步修订设计中对 F5 的表述（明确其前提是被信任的本地目录与 ACL），并把 `forgedLeaseRepointingIsAdmittedAndTrackedAsAnOpenGap` 从"declared-gap 待修"改为"模型外·有前提"，**不得**仍标注为待修缺口。

> 建议：按 **A** 继续。理由：本项目其余部分（`writers.lock`、协调锁、原生身份）都按"耐久状态可能被外部改写"设计，只对 P5 例外会形成不自洽的安全声明。

## 3. 方案 A 实现规格（锚点 + 锚定索引）

### 3.1 秘密的供给（关键）

- 新增显式供给项：`outbound.recovery.fence.anchor`（32 字节随机值的 hex），与既有 `identitySha256`/`markerSha256` 同属**显式可信输入**。
- **秘密只来自配置/环境，绝不写入 P5/P3 可写目录**；若写在同目录，锚点无意义。
- `provision` 在自哈希的 `lease-root.json` 中记录 `anchorId = sha256(secret)`；`verify` 要求运行期秘密的 `anchorId` 与 marker 一致，否则 `CONTROL_ANCHOR_MISMATCH`（失败关闭）。
- 跨进程开关开启而锚点缺失 ⇒ **启动失败**（与"缺权威即启动失败"同一条纪律）。

### 3.2 记录标签与索引

1. `RecoveryControlFormat` 增 `hmac(secret, canonical(node))`（HMAC-SHA256，输出 hex）。
2. `RecoveryLeaseProcess.open`：进程记录加 `anchorTag`；`validate` 校验之。
3. `RecoveryLeaseScan.publish`：租约加 `anchorTag`；`checkRecord` 先验标签，再判存活。
4. **锚定索引**：`leases/index.json`（或追加链），每发布一条操作即追加 `{operationId, anchorTag, prevHash}`，并整体用 `hmac` 保护；扫描时：
   - 索引里存在而**记录缺失** ⇒ `RECOVERY_LEASE_OUTSTANDING`（闭合 H3′ 删除变体）；
   - 记录存在而**不在索引**中 ⇒ 同样拒绝（防插入伪造）。

### 3.3 改动面（文件级）

`RecoveryControlFormat`（hmac）、`RecoveryLeaseRoots`（anchor 字段 + anchorId 绑定与校验）、`RecoveryLeaseProcess`（标签）、`RecoveryLeaseScan`（标签 + 索引 + 删除检测）、`RecoveryEffectConfiguration`（新配置项与 fail-closed）、测试供给侧 `FenceTestSupply`（随机秘密）、`RecoveryFenceIntegrityIT`/`RecoveryFenceAdversarialDurableIT`（用例翻转）、设计 §5.4/§5.5 与欠债 `R09-C2-ANCHOR`。

### 3.4 验收

- `forgedLeaseRepointingIsAdmittedAndTrackedAsAnOpenGap` **翻转为必须拒绝**（H3 闭合），并保留原攻击构造（`newLockAvailable=true`、身份确实不同）。
- 新增：删除租约记录后必须拒绝（H3′）；插入未入索引的伪租约必须拒绝；`anchorId` 不匹配必须失败关闭；跨进程开启而锚点缺失必须启动失败。
- 回归：定向单测 **2038**、并集全量 IT **662**（`RecoveryEffect*IT|RecoveryFence*IT`）不得回退；失败轮与 XML 保留。
- 口径不变：**同一会话实施＋自审**，非独立第三方验收；默认关闭、未接线、未部署；K1 仍未通过。

### 3.5 残余风险（方案 A 也不覆盖）

- 秘密的**保管与轮换**属运维政策（谁能读、如何轮换、轮换时在途租约怎么办）——需与七类生产决定同级的授权，本轮不臆断。
- 攻击者若能同时改写 P3 `identity.json` 与配置，锚点仍可被绕过：锚点的强度**等于配置来源的强度**。
- 窗口 W 与本页无关，仍按原证明保留。

## 4. 停止点

本页**只登记规格**。在用户就 §2 作出决定前：不实施方案 A、不修订 F5 表述、不把 `R09-C2-ANCHOR` 标为已解决；`DEBT-R09-C2-LEASE-ANCHOR` 与窗口 W 继续并列单列。
