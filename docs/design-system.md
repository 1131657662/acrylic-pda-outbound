## 2. 产品目标与取舍

让使用者在当前页面能回答：我在哪个仓库/哪张订单；数据来自哪里；现在是什么状态；能做什么；做完或出错后去哪里。

| 使用者 | 主要任务 | 优先优化 |
| --- | --- | --- |
| 仓库管理人员 | 查单、建单、找货、维护库存 | 定位快、表格可比较、返回保留位置 |
| 主管 | 核对差异、审批、停止与恢复作业 | 决策依据集中、影响清楚、结果可追溯 |
| PDA 操作员 | 领单、准备、连续扫码、上传 | 当前包清楚、少按键、出错能恢复 |
| 设备维护人员 | 登记、核对身份、处理故障 | 不搬运长密钥、可定位问题、保留数据 |

推荐在现有 Vue/Element Plus 与 Kotlin/XML 上建立项目规范并逐页替换。仅改配色不能解决导航和业务理解；换框架或全盘重写会扩大验证范围。本次不引入新的通用后台平台、组件编辑器、可拖动仪表盘或自定义布局引擎。

产品原则：

1. 页面围绕一个主要任务组织，首屏优先呈现任务对象、当前状态和下一步。
2. Web 优先扫描比较，PDA 优先现场操作；共享术语和状态含义，分别布局。
3. 同类页面有一致结构，列表、详情、表单各有模板。新增业务不继续纵向追加大区块。
4. 保留用户上下文与输入；返回、重试、刷新不会偷偷换单、换仓或新建请求。
5. 展示有证据的状态。已领取不等于正在扫码，最近联网不等于在线，收到数据不等于允许放行。
6. 关键错误必须有可执行的恢复路径。可恢复问题不要求用户清除数据、重装或重置设备。
7. 正常操作简洁；只有影响数据、占用、审批或现场动作的决定才要求确认。

## 3. 视觉方向与色彩

采用明亮、清晰、紧凑的工作工具风格。主体为中性浅灰与白色，青绿色只强调主要动作，蓝色表示信息与焦点，绿/琥珀/红分别表达成功、待处理和阻断。侧栏使用浅色，不以整片深色侧栏、渐变或大面积品牌色占据工作空间。

以下为实现基准，集中映射至 Web 主题变量与 Android 资源，禁止各页另写近似颜色。

| 语义变量 | 色值 | 用法 |
| --- | --- | --- |
| background.canvas | #F4F6F8 | 应用外层背景、页间分隔 |
| background.surface | #FFFFFF | 侧栏、顶栏、主要工作区、表格 |
| background.subtle | #F8FAFB | 表头、只读摘要、轻量分区 |
| text.primary | #1F2329 | 正文、标题、关键数量 |
| text.secondary | #4E5969 | 次级字段与标签 |
| text.muted | #606A78 | 时间、辅助字段；不用于隐藏必要信息 |
| border.separator | #D6DCE2 | 非交互区块分隔线 |
| border.control | #7C8794 | 输入框等需要辨认的控件边界 |
| action.primary | #0F766E | 主按钮、选中导航文字 |
| action.primary-hover / pressed | #0B625C / #084F4A | 悬停、按下；保持白字 |
| selection.background | #E6F4F1 | 当前导航项、轻量选中态 |
| disabled.foreground / background | #606A78 / #EEF1F4 | 不可操作控件；必要原因保持正文可读性 |
| information.foreground / background | #1D4ED8 / #EFF6FF | 正在处理、提示、键盘焦点 |
| success.foreground / background | #166534 / #EDF7EE | 已完成的明确事实 |
| warning.foreground / background | #92400E / #FFF4E5 | 待审批、结果待核对、临近到期 |
| danger.foreground / background | #B42318 / #FEF0EE | 阻断、拒绝、危险操作 |

本次已按 sRGB 对比度公式核对基准组合：主按钮白字5.47:1，正文白底15.78:1，辅助文字页背景5.06:1，选中导航4.84:1，各语义文字/背景组合均超过4.5:1，控件边界对白底3.65:1。此结果仅为色值计算，不替代实际组件、透明度、禁用态及强光真机检查。

颜色始终配合文字或图标。达到计划、保存成功、后台确认出库分别写明含义；不能用同一个绿色勾替代。禁用态降低强调但原因保持可读。正常主题即满足高对比度要求，暂不增加暗色/高对比度主题切换。

## 4. 排版、尺寸与视觉细节

| 项目 | Web 基准 | PDA 基准 |
| --- | --- | --- |
| 字体 | 系统中文无衬线，不下载装饰字体 | Android 系统中文字体 |
| 正文 | 14px，行高20-22px | 16sp，行高约1.35-1.5 |
| 辅助字段 | 12-13px，必要信息不低于14px | 14sp，仅低优先级信息使用 |
| 页标题 | 22px / 600；紧凑页20px | 20sp / bold，允许长车号换行 |
| 区块标题 | 16px / 600 | 16-18sp / bold |
| 关键数量 | 24px，等宽数字 | 24-28sp，受固定区域约束 |
| 间距档位 | 4、8、12、16、24、32px | 4、8、12、16、24dp |
| 控件 | 默认36px高，图标按钮36px方形 | 点击区域至少48dp，主要按钮56dp |
| 圆角 | 控件4px，浮层6-8px | 控件4dp，浮层最多8dp |

字距统一0，不用视口宽度缩放字号。长标题优先换行，必要时调整布局，不挤压主要操作。条码和发货代码作为字符串显示，保留前导零；条码可用等宽字体。数字右对齐，单位在列标题或数值旁明确标出，重量按整数克精确换算，不统一截成两位小数。

页面区块用标题、留白和细线划分，主要工作区平铺，不做多层卡片嵌套。阴影只用于菜单、抽屉和对话框区分遮挡关系。反复出现的独立订单摘要可以使用单层卡片，圆角不超过8。

图标沿用 Element Plus 对应图标体系和 Android 标准资源，保持同一套描边与尺寸；主导航图标18-20px，工具图标16-18px，PDA图标24dp。返回、刷新、展开、设置等采用熟悉图标，Web 提供悬停/聚焦名称，PDA 提供可访问名称。业务命令使用明确文本或图标加文本，不让用户猜测图标含义。

不加入装饰性插画、背景照片、渐变光斑、口号或英语眉题。已有真实品牌标识可小尺寸使用；设备示意仅在确有操作价值的设置/诊断页面使用实际设备资料。

## 5. 组件规则与交互底线

| 类型 | 统一规则 |
| --- | --- |
| 页面头 | 标题、对象标识、状态、主要动作；详情有固定位置的返回入口 |
| 表格与列表 | 搜索/筛选、稳定排序、分页、加载/空/错误态完整，行点击不是唯一入口 |
| 表单 | 持续可见标签、必填说明、单位、就地校验、首次错误定位、原输入保留 |
| 单选/模式/开关 | 选项用选择器或分段控件，二元配置用开关/复选框；有风险的生效动作另确认 |
| 操作按钮 | 一个主要动作；次要动作平级但弱化；危险动作独立；请求中防重复提交 |
| 状态标签 | 固定语义映射、文字可读；未知状态回退为“状态待核对”，禁用不确定的写操作 |
| 弹窗/抽屉 | 简短确认用弹窗，轻量详情用抽屉，复杂编辑用页面；避免弹窗套弹窗 |
| 提示 | 字段问题在字段旁，业务阻断在操作区，成功轻提示；关键结果保留在页面 |
| 恢复入口 | 绑定原对象/请求，状态变化时更新实际可执行动作，不统一用“重试” |

先沉淀页头、列表工具栏、分页、状态标签、空/错误态和确认流程；不先做一个容纳所有业务的万能表格或表单引擎。组件展示与业务许可分开，UI 不能替代服务端权限/状态校验。

所有组件需要覆盖默认、悬停、聚焦、按下、选中、禁用、加载、错误和只读状态中适用的组合。按钮文案或加载指示切换不改变尺寸。表格加载保持区域稳定；首次骨架屏与后续刷新分开，失败不显示成“暂无数据”。

## 6. 易用性、可访问性与性能

- 按钮、输入、菜单和标签页可通过键盘访问，焦点可见；弹窗管理焦点并在关闭后回到来源。普通 Enter 不触发危险审批，Esc 不丢弃未保存内容或未确认请求。
- 不把关键内容只放在悬浮提示中。触屏、键盘及放大字体同样可以查看完整文字和禁用原因。
- 动画限于必要状态过渡，约120-180ms；尊重减少动态效果设置。扫描结果不做飞入、闪烁、全屏庆祝或连续声音叠加。
- 高频扫码以真实提交结果更新界面，合并绘制可以节流，业务事件不能防抖丢弃。错误提示优先，读屏不逐包播报长日志。
- 查询刷新只影响对应内容区；后台轮询限制在相关页面/待处理对象，离开页面或后台后按策略停止，不通过高频全量刷新伪装实时。
- Web 列表请求量有界；PDA 使用可复用列表及按需读取，不能为了显示首页拉完所有订单、创建全部行视图。
- PDA沿用现有峰值内存250MB以内的约束，重视Android 9/2GB设备上的连续滚动、扫码和页面重建，不靠降低业务耐久性换取流畅。
- 缓存按账号、仓库、对象和查询条件隔离。退出清除可见的敏感缓存，但不丢弃依法需要恢复的本机作业记录；下个账号不能读取上个账号的数据。
- 原有 FLAG_SECURE、设备密钥保护、审核证据与订单占用继续有效。展示测试不得通过关闭安全限制获取正式设备截图。

## 7. 实施顺序与边界

以下是同一完整方案的施工顺序，不缩减完整系统交付范围，也不调整其他业务任务的既定授权。

2026-09-18用户已确认[后续十步开发路线](DEVELOPMENT_ROADMAP.md)。现阶段先补PC异常处置并进行独立测试后台/真机联调，再完成PDA高频页面及其余页面统一；下表继续描述UI内部依赖，不能用于重做已经完成的Web基础或覆盖最新业务顺序。后续新增功能均直接沿用本规范。

| 顺序 | 交付物 | 完成条件 |
| --- | --- | --- |
| A 基准 | 页面清单、状态/术语表、主题变量、代表页样稿 | Web订单列表/详情与PDA扫码/异常/手输状态能被核对 |
| B 基础 | 工作台框架、导航返回、页高滚动、列表分页、通用反馈 | 查询-详情-返回上下文闭环；窄屏导航和键盘可用 |
| C 主要流程 | 订单查询/编辑/审批、PDA订单/扫码/结单 | B模式和异常恢复不变；主要动作不被挤出视口 |
| C-PC 新增业务配套 | 随M14接入订单入口、PC查询/候选/记录、逐包核对、结单与恢复 | 先完成对应后台契约和业务能力，再开放入口；通过真实接口验证，不以样稿代替 |
| D 全面覆盖 | 库存导入/查询、映射、规则、设备、召回续作、登录 | 所有现有页面和异常状态迁移；短码登记开发时复用 |
| E 验收 | 浏览器证据、设备适配、业务回归、文档更新 | 逐项记录通过、失败及未测范围，不凭截图声明业务通过 |

样稿可以先用于设计评审，但不用虚构数据状态替代正式接口。需要确认的视觉方向由代表页集中评审，不让用户逐个批准常规像素调整。逐个完整流程迁移，已迁移页面内部保持一致，避免一次提交同时重写所有业务。

单独列为后续能力：全局搜索、批量审批/作废、完整筛选结果导出、用户自定义列配置、复杂快捷键、主题切换、通用证据导出、独立待办中心。这些不作为本次基础优化的先决条件；原总体需求已包含的报表等功能仍按既定业务计划开发。

涉及接口的必要配套：真实分页/总数/排序、列表摘要、产品与扫描明细按需查询。必须同步契约和查询性能验证。界面不会编造总页数、实时装车量或后台进度。具体查询方案见 Web 文档。

## 8. 验收清单

| 检查 | 可判定标准 |
| --- | --- |
| 找到入口 | 每个有权限的现有业务均有导航入口；窄屏可展开导航，无空白侧栏 |
| 定位与返回 | 在同一筛选结果的第3页进入详情再返回，条件、页、滚动和焦点恢复；刷新/直达有合理回退 |
| 列表容量 | 验证0、1、20、21及大量记录，边界按钮、总数、下一页正确；不全量下载后假分页 |
| 任务完整性 | 新建草稿、发布、查询审批、导入核对、设备登记/停用都有明确结束与返回路径 |
| 文字 | 长车号、品名、账号、错误与备注不遮挡；必要信息可完整查看；不用未解释的技术词 |
| 高度与缩放 | 1366x768、1440x900、1920x1080、1024x768、390x844及桌面200%缩放可操作，无页面横向溢出 |
| PDA | 480x800/density240、实际系统栏、软键盘和放大字体下，当前错误、候选与主操作可达 |
| 状态真实性 | 离线、后台不可达、登录失效、授权过期分别显示；已领取不伪装实时作业 |
| 数据与恢复 | 超时/丢响应/刷新/重开/重复点击后恢复原对象，不重复保存、不误报成功、不解锁原占用 |
| 高风险操作 | 审批/召回/卸货/停用确认展示对象、影响及原因；冲突或旧版本不能越过校验 |
| 扫码 | 自动扫码、手输人工确认、错误暂停、队列及恢复语义保持；静音时仍可理解结果 |
| 权限与仓库 | 切仓清除不适用条件与选择；越权链接不泄露对象；旧响应不覆盖新仓数据 |
| 可访问性 | 焦点顺序合理、无仅颜色传意、对比度达标、对话框无焦点逃逸、触控区域达标 |
| 性能 | 比较同设备同数据的优化前后加载/滚动/扫码响应；不回退已确认耐久与性能约束 |

代表页实施后安排简短的真实使用核对：管理人员完成“查指定车号-看差额-回原列表”和“建草稿-修订-发布前核对”；现场人员完成“选本机任务-扫一包-识别重复错误-手输确认-查询提交结果”。先让使用者自行操作，记录找不到入口、误解状态、误触及需要开发者解释的位置，并据此调整。能正确区分“本机保存”和“后台确认出库”是必要条件，不以主观好看代替可用性。

本次实际验证仅为源码/设计交叉核对、文档链接与一致性检查、候选色值对比度计算。后续实施按影响范围增加导航、分页、恢复、权限及布局回归；仅样式细调不新增重复实现的单元测试。真机操作、强光、声音和键盘结果单独记录，不重新打开已结束的历史 Demo 验收。

## 9. 维护与后续启动
