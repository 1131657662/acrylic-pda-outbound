# PC异常处置与交接实施记录

日期：2026-09-18。分支：`codex/development`，基线`a81aa33`。R01源码和本机隔离环境验证已完成；本轮未提交、推送、合入main、发布或部署服务器，不表示现场或整个系统验收完成。

## 实际操作

订单详情的“异常处理”或PC作业页的“异常处置与交接”进入本单核验页，保留仓库、筛选和页码上下文。

1. 主管选择“停止并核验实物”，填写原因并明确确认。后台固定停止时全部原录入、人员、轮次及摘要；所有旧窗口失去写入资格，待审原提交终止，包占用保持。
2. 主管填写接续登录账号和交接后安排，逐包选择“本车保留”“卸货并释放”或“卸货并隔离”。卸货或隔离必须填写实物位置、结果和核验凭据，不能漏包、重复或替换周期。编辑清单来自停止时的固定全集，20条一页；翻页保留选择，只有全部核对才可提交。未提交资料可明确放弃并清空。
3. 主管核对固定方案并批准或退回。批准时再次检查权限、全包占用及保留包库存；批准本身不释放包。尚未交接的批准可以撤回，原方案和全部审核决定保留。
4. 指定接续人员登录，核对全部实物后“本人确认实物交接”。后台在同一事务保存处置证据、释放或隔离占用、切换人员并开启新轮次。选择继续时，返回PC页显式“在本窗口继续”后录入；选择全部卸下结束时，不生成出库或扣账。隔离包仍被全局锁定。

每个写请求发送前保存原标识、正文和恢复代次；断网或丢响应时使用“恢复原PC请求”，刷新后也先查回执，找不到才以同键原正文重试。浏览器存储失败则不发请求，弹窗直接显示原因。读取失败保留上次资料并暂停变更。普通关闭、返回或超时不释放包。

## 权限与保留事实

- 查看要求`order:read`；停止要求`order:recall`；提案和审核要求`order:resume`；批准减少包另需`order:dispose`，结束另需`order:recall`。指定接续人员须在本仓库具备`pc:operate`和`order:read`。实际交接时再检查审批人和接续人的当前授权。
- 原录入条码、重量、人员、时间、序号及原状态不改写；已冻结正文和摘要保持。新处置独立保存，原行只增加关联，读取派生“已卸货释放/已实物隔离”；有效数量和重量排除处置行。曾冻结或交接保留的包不能普通撤销。
- 释放包可按正常规则在同单或其他订单重新录入，形成新事实；隔离包不能由PC、PDA或库存导入重新使用。新冻结正文含累计处置证据，旧无处置正文保留兼容核验分支。
- 不实现已出库后的账务更正、解除隔离、PDA换机或灾后重建；它们不通过此流程绕过。
