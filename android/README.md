# 正式PDA：资料准备、扫码与首轮提交

2026-09-17，版本`0.3.0-submission`。本工程独立于已验收的`demo/`，App名称“腈纶出库 PDA”，debug包名`com.acrylic.outbound.pda.debug`。当前完成设备密钥、人员登录、独占领取、固定资料下载校验、Room原子激活、下载确认、本地扫码、结单冻结、上传、短装审批恢复和签名回执校验。

**这不是完整出库App。** 已接正式订单首轮云端出库及按政策扣账；召回换机、续作、临时单、更正、授权续期、增量同步及文件生成仍待实现。当前“资料已就绪”及“已保存到本机”仅表示本地资料/作业事实完成，不表示可放行。

## 构建与验证

要求Java 17或21、Gradle 8.11.1、Android SDK 36及Build Tools 36.1.0；支持Android 9/API28以上，target35。从仓库根目录执行：

```powershell
python tools/start_development_db.py
powershell -NoProfile -ExecutionPolicy Bypass -File tools/development_server.ps1 -Task Verify
powershell -NoProfile -ExecutionPolicy Bypass -File tools/build_pda.ps1
```

后端Verify使用隔离测试库生成`server/build/pda-contract-fixture.json`与`pda-submission-fixture.json`。Android主机测试直接消费真实后端签名及gzip文件，不自行伪造一套协议；测试时间锚定该样本的签发时间，不因样本保存超过48小时失效。修改后端下载协议后先重新Verify。构建脚本不运行Demo任务，也不安装到任何设备。

产物：[`../outputs/pda/Acrylic-PDA-0.3.0-debug.apk`](../outputs/pda/Acrylic-PDA-0.3.0-debug.apk)，同目录附SHA256及APK信息。它是开发验证包，未配置正式发布签名。测试fixture只位于被忽略的build目录，不打包测试账号、服务端私钥或登录凭据。

## 首次使用

1. 管理员按[后端运行说明](../server/README.md)启动服务，发布库存与订单。当前设备登记提供API，Web设备管理页面尚未接入。
2. 在App点“复制本机登记公钥”。私钥由Android Keystore生成并留在设备；复制内容只有P-256公钥。
3. 管理员通过Web会话/CSRF及对应仓库权限调用`POST /api/v1/devices?warehouseId=...`，提交设备代码、名称、公钥，保存返回的`deviceId`。详见[协议](../contracts/PDA_API.md)。
4. App填写服务器`https://<服务地址>/api/v1/`与管理员返回的设备UUID，保存绑定，再使用获授权人员账号登录。服务器、设备及公钥一经绑定不能在界面任意替换。
5. 联网刷新后领取READY订单，核对货堆备注；领取后点“下载并校验资料”。完成全部校验与本地事务后显示“资料已就绪 · 已确认下载”，再点“本地扫码 / 恢复作业”进入作业页。

正式连接要求HTTPS。仅debug支持`localhost`、`127.0.0.1`、`10.0.2.2`的HTTP回环联调；模拟器可用`http://10.0.2.2:8083/api/v1/`访问本机开发后端。不要把生产地址绑定到测试身份，也不要通过清除数据处理结果未知。

## 重试与本机恢复

- 领取前持久保存原请求键、原正文与人员/设备身份。响应丢失后使用“重试原领取”，或登录后从本机活动授权恢复。换人不能复用原离线凭据。
- 下载中断或校验失败不激活半份数据；临时文件清理后可下载同一固定包。服务端继续保留原占用。
- 激活在一个Room事务内写入完整资料，WAL及synchronous=FULL；失败全回滚。已完整激活的版本不会被失败重试覆盖。
- 确认响应丢失时保存“下载确认待重试”；重开App仍可重试同一个包，服务端返回首次确认时间。确认不是扫码或出库提交。
- 离线凭据固定48小时。验证使用服务器时间锚点及设备单调时钟，重启/改时后要求联网；登录刷新不延长授权。授权、登录过期和设备停用均不自动放锁。
- 扫码页只在前台注册厂家广播`com.android.decodewedge.decode_action`及字符串Key`com.android.decode.intentwedge.barcode_string`；输入入口容量64，按接收顺序由单一消费者处理，不使用防抖丢弃重复广播。广播扫码按B模式自动保存，手输固定MANUAL策略，先按F1/K1校验再用回车或大按钮确认。
- 每个输入保存原始字符串、规范化条码、扫码序号、设备序号、订单/授权/库存/周期和时钟上下文。校验失败、重复、不可用、周期变化和超量均保留为失败事实并暂停后续保存；处理当前错误后才能恢复队列。F2/K2只允许放弃尚未确认的手输项。
- 保存事务同时写有效明细、条码防重、产品/整单汇总、审计及输入终态；失败或重启后按capture恢复，不重复插入。末包可填写实物核对原因撤销，原明细和序号保留，之后重扫使用新序号。
- 退出即清除本机登录凭据，保留订单与待恢复请求。断网退出不能即时撤销服务端会话；不得以删除App、清除数据或换设备规避占用。

本地资料不备份/迁移到另一台设备；会话加密保存于noBackupFilesDir，私钥不可导出。页面启用FLAG_SECURE，系统截图可能为空，这是预期行为。

## 验证证据与边界

42项Android主机测试覆盖真实签名包、篡改/坏gzip、重复条码、重量/周期校验、事务中断全回滚、重复激活、数据库重开、授权到期/换人、V1→V3及带扫码事实的V2→V3迁移、输入队列、自动/手动确认、撤销重扫、错误恢复、入口满载、切单期间原输入保留和设备键/广播生命周期、冻结重试/SQL回滚、到期上传、原失败/撤销证据及真实Java签名回执篡改拒绝。另有2项模拟器测试；其中完整业务联调连接真实后端及MySQL测试库，执行公钥登记、Keystore签名登录、领取、下载、激活、确认、实际页面显示、自动/手输扫码、冻结、响应丢失、查询恢复、短装批准、验签和数据库重开。

联调使用单独read-only模拟器`emulator-5580`、独立测试后端端口18083；测试账号来自`PdaAndroidFixtureIT`生成的ignored fixture，经run-as注入测试App后立即删除。无秘密证据保存在`.local/submission-e2e-evidence.json`、`.local/submission-main-ui.xml`、`.local/submission-work-ui.xml`与`.local/submission-receipt-ui.xml`。480×800/density240下核对了冻结作业及回执页面；最终2包、601.5kg，重开仍保留固定正文与SYNCED状态。勿将测试fixture复制到src/assets或APK。

另外，约3.4MB中文/表情正文在原生SQLite中保存、重开和更新状态后保持逐字节一致；通过每次128KiB读取解决游标窗口大小限制。该测试不代表32MiB上限性能验收。

上述证据不等于M71现场验收。真实M71和已验收Demo未被本轮安装或操作；扫码广播顺序、声音、闪存耐久、4条/秒长时负载、真实断电、生产部署和备份恢复仍须在本机现场及完整业务链路完成后验证。M71已验收的Demo按键配置只作为适配参考，正式App未宣称已通过同等现场验收。

## 结单上传

从作业页进入“结单 / 上传 / 查询回执”，核对实物、车号和各产品实装数，短装填写原因后确认冻结。冻结后只读，不能继续扫码或撤销；0包或未决输入会阻断。授权到期允许冻结上传此前已保存记录，不允许新增保存。

点上传会先查询原批次，再传原正文；超过1MiB自动分块。当前完整正文上限32MiB。点击上传后仅WiFi自动重试，前台手动上传可使用当前可用网络。待审时主管在Web订单详情核对并审批，PDA查询并验签后才显示云端已确认。退出、联网失败、到期或审批退回不清除本地记录。

Room升级至3，只新增提交表并保留旧数据。APK是debug开发包；最终信息和签名见outputs/pda/APK_INFO.txt。当前lint为0错误、42项非阻断提示（主要硬编码文案/界面建议），没有宣称零告警。
