## 构建与验证

要求Java 17或21、Gradle 8.11.1、Android SDK 36及Build Tools 36.1.0；支持Android 9/API28以上，target35。从仓库根目录执行：

```powershell
python tools/start_development_db.py
powershell -NoProfile -ExecutionPolicy Bypass -File tools/development_server.ps1 -Task Verify
powershell -NoProfile -ExecutionPolicy Bypass -File tools/build_pda.ps1 -ServerUrl 'http://127.0.0.1:18083/api/v1/' -EnvironmentName '本机联调环境（USB转发）'
```

后端Verify使用隔离测试库生成`server/build/pda-contract-fixture.json`、`pda-submission-fixture.json`、`pda-recall-fixture.json`与`pda-continuation-fixture.json`。Android主机测试直接消费真实后端签名及gzip文件，不自行伪造一套协议；测试时间锚定该样本的签发时间，不因样本保存超过48小时失效。修改后端下载协议后先重新Verify。构建脚本不运行Demo任务，也不安装到任何设备。

历史0.7.0 debug产物仍见[`../outputs/pda/Acrylic-PDA-0.7.0-debug.apk`](../outputs/pda/Acrylic-PDA-0.7.0-debug.apk)；本轮0.8.0-r04-test staging APK仅保存在`android/app/build/outputs/apk/staging/app-staging.apk`，已覆盖安装USB M71，未发布、未上传服务器。最终Debug APK未构建，旧产物不能代表本轮源码。开发验证包未配置正式发布签名，测试fixture只位于被忽略的build目录，不打包测试账号、服务端私钥或登录凭据。

原生测试默认使用debug；需要对已绑定staging设备做辅助页面只读检查时，构建增加`-PpdaTestBuildType=staging`，执行仅指定`com.acrylic.outbound.pda.AuxiliaryReadOnlyDeviceTest`。该类核对已有身份、切换声音后恢复、打开退出确认并返回，不真正退出或重新登录。既有M71不得运行整套会清理测试数据的端到端测试；含清理步骤的用例仅在专用模拟器或隔离设备运行。

构建不指定`ServerUrl`时地址为空，短码页明确提示未配置并禁用开始登记。正式环境须传入已部署的HTTPS地址及准确环境名称；当前没有已验证的正式地址。上面的回环地址仅供独立测试后端18083及`adb -s <测试设备序列号> reverse tcp:18083 tcp:18083`联调，不代表异地可达，也不会自动启动后台服务。

## 首次使用

1. 管理员按[后端运行说明](../server/README.md)启动服务，发布库存与订单。Web侧栏“PDA 设备管理”提供设备登记和启停，需要`device:manage`及对应仓库权限。
2. 在未绑定PDA首页进入短码登记，核对环境和服务地址后点“开始登记”。App自动复用或生成Keystore私钥，证明持有私钥后显示8位登记码，有效期10分钟。
3. 管理员在同一后台选择正确仓库，在“短码配对登记”输入登记码，核对型号和时间，填写设备编号及名称，确认登记意图并发送给原PDA。此时尚未启用设备。详见[设备管理操作说明](../docs/WEB_DEVICE_GUIDE.md)。
4. 原PDA前台每4秒核对状态，显示仓库、设备名称和编号。操作员核对无误后点“信息无误，确认绑定”；本机完整保存身份后点“进入人员登录”，使用获授权人员账号登录。公钥、服务地址和设备UUID自动传递；配对不代替人员登录，也不增加人员权限。
5. 联网刷新后领取READY订单，核对货堆备注；领取后点“下载并校验资料”。完成全部校验与本地事务后显示“资料已就绪 · 已确认下载”，再点“本地扫码 / 恢复作业”进入作业页。

正式连接要求HTTPS。仅debug支持`localhost`、`127.0.0.1`、`10.0.2.2`的HTTP回环联调；模拟器可用`http://10.0.2.2:8083/api/v1/`访问本机开发后端。不要把生产地址绑定到测试身份，也不要通过清除数据处理结果未知。

配对断网、丢响应或本地保存失败时使用“刷新／恢复原请求”，沿原申请和原确认恢复。取消或过期须先联网核对终态，再用原密钥重新申请；后台已完成的结果不因短码到期丢失。已有设备直接沿原身份登录，覆盖升级不会要求重新配对。高级维护保留手工公钥/UUID入口，普通登记不使用它。完整验证和恢复边界见[配对说明](../docs/PDA_PAIRING_REGISTRATION_GUIDE.md)。

## 重试与本机恢复

- 领取前持久保存原请求键、原正文与人员/设备身份。响应丢失后使用“重试原领取”，或登录后从本机活动授权恢复。换人不能复用原离线凭据。
- 下载中断或校验失败不激活半份数据；临时文件清理后可下载同一固定包。服务端继续保留原占用。
- 激活在一个Room事务内写入完整资料，WAL及synchronous=FULL；失败全回滚。已完整激活的版本不会被失败重试覆盖。
- 确认响应丢失时保存“下载确认待重试”；重开App仍可重试同一个包，服务端返回首次确认时间。确认不是扫码或出库提交。
- 离线凭据固定48小时。验证使用服务器时间锚点及设备单调时钟，重启/改时后要求联网；登录刷新不延长授权。授权、登录过期和设备停用均不自动放锁。
- 扫码页只在前台注册厂家广播`com.android.decodewedge.decode_action`及字符串Key`com.android.decode.intentwedge.barcode_string`；输入入口容量64，按接收顺序由单一消费者处理，不使用防抖丢弃重复广播。广播扫码按B模式自动保存，手输固定MANUAL策略，先按F1/K1校验再用回车或大按钮确认。
- 每个输入保存原始字符串、规范化条码、扫码序号、设备序号、订单/授权/库存/周期和时钟上下文。校验失败、重复、不可用、周期变化和超量均保留为失败事实并暂停后续保存；处理当前错误后才能恢复队列。F2/K2只允许放弃尚未确认的手输项。
- 保存事务同时写有效明细、条码防重、产品/整单汇总、审计及输入终态；失败或重启后按capture恢复，不重复插入。末包可填写实物核对原因撤销，原明细和序号保留，之后重扫使用新序号。
- 退出即清除本机登录凭据，保留订单与待恢复请求。断网退出不能即时撤销服务端会话；不得以删除App、清除数据或换设备规避占用。

本地资料不备份/迁移到另一台设备；会话加密保存于noBackupFilesDir，私钥不可导出。页面启用FLAG_SECURE，系统截图可能为空，这是预期行为。

## 结单上传

从作业页进入“结单 / 上传 / 查询回执”，核对实物、车号和各产品实装数，短装填写原因后确认冻结。冻结后只读，不能继续扫码或撤销；0包或未决输入会阻断。授权到期允许冻结上传此前已保存记录，不允许新增保存。

点上传会先查询原批次，再传原正文；超过1MiB自动分块。当前完整正文上限32MiB。点击上传后仅WiFi自动重试，前台手动上传可使用当前可用网络。待审时主管在Web订单详情核对并审批，PDA查询并验签后才显示云端已确认。退出、联网失败、到期或审批退回不清除本地记录。
